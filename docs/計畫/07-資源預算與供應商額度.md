# 資源預算與供應商額度 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` (recommended) or `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 【推論】對所有執行者後端提供同一套先保留後花費的硬帳，誠實處理供應商 push-observed 額度的 per-bucket 證據，並以版本化 soft allocation policy 加 live hard eligibility gate 決定可派工後端。

**Architecture:** 【推論】資源權威擁有 BudgetReservation、RateCardVersion、AllocationPolicyVersion、QuotaBucketEvidence 與 eligibility decisions。自有貨幣帳是權威硬上限；供應商額度只是可能失鮮的外部 evidence。`QuotaTopology` 先組合 bucket/channel，再與本地 reserve、update/capability/isolation 狀態合成 dispatch eligibility；比例只進 deterministic deficit round-robin，不可繞過任何 hard gate。

**Tech Stack:** 【推論】CPython 3.14.7、Decimal integer minor units、MachineSpec、SQLite single-owner ledger、event stream、fake clock/property tests、ClaimSpec runner。

**Spec:** 【查證】本檔「子系統規格」，以及[第三輪資源與分配裁決](../sol-新局-第三輪.md#42-後端比例硬資格與額度觀測)、[第四輪不可觀測 fallback](../sol-新局-第四輪.md#4-q4若沒有任何可靠的供應商剩餘額度)、[第五輪 per-bucket 五態](../sol-新局-第五輪.md#1-額度接受五種情況但狀態的主詞必須改對)。

## Global Constraints

- 【推論】貨幣一律 integer minor units；浮點數不得進 budget/rate calculations。
- 【推論】每一 paid action 先以最壞成本 reserve；settle 不得大於 reservation，未使用餘額 release。
- 【推論】每筆 reservation 釘當下 active RateCard digest；Work 釘 AllocationPolicy digest，兩者生命週期不同。
- 【推論】QuotaBucket 的五態固定為 `NOT_APPLICABLE`、`OBSERVED_FRESH`、`OBSERVED_STALE_SAME_WINDOW`、`WINDOW_ROLLED_UNOBSERVED`、`NEVER_OBSERVED`；rolled 不等於滿額。
- 【推論】freshness 300 秒、reset skew guard 60 秒、observation probe 最短間隔 15 分鐘；都由 immutable ResourcePolicy 擁有。
- 【推論】provider observation 不是 atomic reservation；claim 只覆蓋 gate 如何使用已知 evidence，不保證外部 client 不競態。
- 【推論】無 observation capability 的 backend 才走 blind single-flight/circuit fallback；Claude/Codex 主路徑不得誤走 blind mode。
- 【推論】delegation 核銷來源順序固定：provider `DELEGATION_TREE_TOTAL` monetary evidence；否則 tree-inclusive per-model usage乘 pinned RateCard；`ROOT_ONLY` 僅在 delegation 被機械禁止時可用；其餘一律 `USAGE_SCOPE_INCOMPLETE`。
- 【推論】啟用 delegation 前必須由 `DelegationPolicy` 封住最大子代理數、深度、模型集合與每支上限；無法算 worst-case reserve 就不得派工。

## 子系統規格

【推論】BudgetReservation machine 為 `REQUESTED -> RESERVED -> SETTLED|RELEASED|DENIED|EXPIRED`；只允許一次 terminal。reserve 與 Work available budget 扣減在同一 state-owner transaction。

【推論】fresh fractional policy 固定：used `<0.80` 普通派工、`0.80≤used<0.95` single-flight、`≥0.95` 每 15 分鐘最多一 probe；`ALLOWED_WARNING` 至少 single-flight，`REJECTED` 在原窗口封鎖。只有 compatible `ABSOLUTE_REMAINING` 可聲稱 worst-case sufficient。

【推論】`QuotaTopology` 以 channel 表達：一個 channel 的 buckets 是 `ALL_OF`；不同 channels 是 policy-allowed alternatives。v1 `allowed_channels=[included]`，不默認 overage/credits 支出。
