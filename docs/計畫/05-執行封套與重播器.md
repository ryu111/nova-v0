# 執行封套與重播器 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` (recommended) or `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 【推論】建立一次執行的外部權威邊界：後端只能產生事件與候選產物，不能延長 wall time／回合／輸出／核准花費，也不能指定自己的權威終態；純函式重播器以零付費跑完整契約。

**Architecture:** 【推論】`ExecutionEnvelope` 是第一個垂直生命週期。領域決策只讀 `ExecutionFacts`，程序監督、時鐘與資源保留由 port 提供；每個後端實作相同的 typed event protocol。封套把後端事件歸約成權威狀態，超限時由父程序終止整個 process group，最終只發布一個 typed terminal event。

**Tech Stack:** 【推論】CPython 3.14.7、asyncio、`subprocess` process groups、Linux/macOS platform adapter、JSON Schema、SQLite owner port（由 plan 03 提供）、ClaimSpec runner（plan 01）。

**Spec:** 【查證】本檔「子系統規格」，以及[第一輪性質 1](../sol-新局-第一輪.md)、[第二輪三層裁決](../sol-新局-第二輪.md)、[第三輪狀態機定案](../sol-新局-第三輪.md)、[第五輪 Guard 與工具鏈定案](../sol-新局-第五輪.md)。

## Global Constraints

- 【推論】後端事件中的 `done`、`success`、文字「完成」都只是觀測，不是權威終態。
- 【推論】wall time、回合、輸出 bytes、工具呼叫與核准花費的計數器由封套持有；後端拿不到可寫 reference。
- 【推論】每次執行恰有一個終態：`SUCCEEDED`、`FAILED`、`TIMED_OUT`、`ROUND_LIMITED`、`OUTPUT_LIMITED`、`SPEND_LIMITED`、`CANCELLED`、`BACKEND_LOST`、`UNSUPPORTED_CAPABILITY`、`INTERNAL_FAULT`。
- 【推論】程序型後端必須以 argv 啟動，禁止 shell string；終止需覆蓋孫程序且有 kill escalation。
- 【推論】重播器與付費後端接受相同 `ExecutionRequest`、產生相同 `BackendEvent` union，不另開測試捷徑。
- 【推論】`ExecutionRequest` 引用 plan 01B 的 `ToolAuthorizationPolicyRef`、`StructuredOutputContractRef`、`DelegationPolicyRef`；manifest 以 `PRE_TOOL_DECISION|NATIVE_STRUCTURED_OUTPUT|DELEGATION` 宣告能力，缺 required capability 只回 typed `UNSUPPORTED_CAPABILITY`。
- 【推論】工具操作分成 `READ_ONLY|EFFECT_INTENT_REQUIRED|LOCAL_WORKSPACE_MUTATION|DELEGATION`；`EFFECT_INTENT_REQUIRED` handler 只能呼叫 EffectIntent port，不得直接碰外部 endpoint。
- 【推論】usage observation 必帶 `ROOT_ONLY|DELEGATION_TREE_TOTAL|UNKNOWN` scope；封套不得把 root usage 升格成 tree total。

## 子系統規格

【推論】`ExecutionRequest` 固定包含 `execution_id`、`pursuit_id`、`backend_ref`、`workspace_snapshot_ref`、`input_payload_ref`、`limits`、`isolation_offer_ref`、`budget_reservation_ref`、`idempotency_key`；不包含判準內容。

【推論】`ExecutionLimits` 的每一欄都是正整數且同時有全域 policy ceiling：`wall_ms`、`max_rounds`、`max_output_bytes`、`max_tool_calls`、`max_approved_minor_units`。呼叫端只能要求更小值。

【推論】終態由 `(權威狀態, 外部觀測, 限額計數器, cancellation)` 的封閉決策表決定；後端退出碼與自報狀態只是輸入 facts。
