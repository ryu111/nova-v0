# 本地模型後端 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` (recommended) or `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 【推論】支援不依賴供應商額度的本地模型執行者：模型權重/runtime/tokenizer/prompt template/sampler全進fingerprint，provider quota明示NOT_APPLICABLE，金額核銷為有證據的零而非繞過帳，外部wall/round/output限制與其他後端完全相同。

**Architecture:** 【推論】domain-neutral `LocalInferenceEngine` port隔離具體runtime；v1提供in-process fake/reference與supervised-process production bridge，兩者都輸出同一BackendEvent。manifest綁ModelArtifactRef、runtime executable/library digest、tokenizer digest、context capacity、chat template digest、sampler capabilities。Execution assembler使用同一tokenizer的exact/conservative meter；engine只收已組好的InvocationEnvelope。

**Tech Stack:** 【推論】CPython 3.14.7、async token stream、memory-mapped/hash-verified model artifacts、optional supervised local process、plan 05 backend contract、plan 07 zero RateCard/NOT_APPLICABLE quota、plan 12 context contract。

**Spec:** 【查證】本檔「子系統規格」，以及[第二輪 workload envelope包含本地模型](../決策/sol-新局-第二輪.md#3-q3-workload-envelope是先訂出來再量測修正)、[第三輪adapter目錄與NOT_APPLICABLE語義](../決策/sol-新局-第三輪.md#22-完整目錄樹)、[第五輪quota證據態](../決策/sol-新局-第五輪.md#12-正式模型每個-bucket-五種證據態)、[MLX-LM generation/cache API](https://github.com/ml-explore/mlx-lm/blob/main/mlx_lm/generate.py)與[prompt-cache example](https://github.com/ml-explore/mlx-lm/blob/main/mlx_lm/examples/chat.py)。

## Global Constraints

- 【推論】provider quota固定NOT_APPLICABLE，UI顯示「不適用」而不是∞/100%；本地budget/time/process capacity仍受Resource/Execution gates。
- 【推論】monetary RateCard明示zero minor units且每Execution仍reserve/settle事件；「免費」不等於跳過資源帳。
- 【推論】fingerprint對模型bytes、runtime、tokenizer、chat template、model id、context capacity、sampler semantics敏感。
- 【推論】模型輸出、自報success/usage不寫terminal/verdict；token count由trusted tokenizer observer，wall/output由外部封套。
- 【推論】無法取消的in-process engine不admit production；必須可cooperative cancel或改用可kill supervised process。
- 【推論】本地不等於無網路/安全；沒有OS mediation capability時manifest不宣告NETWORK_DENY/hostile isolation。
- 【推論】model/runtime更新不在v1 updater endpoint；換權重/engine產生新backend fingerprint與新Pursuit lineage，不原地改在途Execution。
- 【推論】本plan的production backend admission與「在實作nova時拿現成9B當外部worker」是兩條不同生命週期。後者不取得backend supported宣告、不繞過task ClaimSpec，資格證據放在總覽Execution Handoff；不得為了提早使用worker而刪除本plan的04–13前置。
- 【實測】day-one既有oMLX endpoint是`127.0.0.1:8000`且三量化manifest宣告`max_model_len=262144`；這是待probe的deployment input，不是程式預設值。production manifest必綁resolved loopback endpoint evidence，連線失敗只回`LOCAL_RUNTIME_UNAVAILABLE`，禁止轉用任何雲端provider。
- 【實測】本地usage不能套雲端RateCard；launchd user agent只在登入session載入，因此「未登入／agent未載入」屬runtime availability，不是模型或quota錯誤。

## 子系統規格

【推論】`LocalModelManifest`必填 `model_artifact_ref/runtime_ref/tokenizer_ref/chat_template_ref/context_capacity/model_family/sampler_capabilities/cancellation_mode/process_mode`；production admission要求所有content refs可verify。

【推論】`sampler_capabilities` **封閉一成員 `{SEED}`**（sol 2026-08-28 裁定）。

**成員資格判準**（這條之後用來擋所有重入，不只管這個集合）：

> 成員必須是**可協商的語意能力**；已有明定 consumer 依它改變**准入或選路**，
> 並有獨立負控、防恆真格與 exact-set 保護。

| 成員 | consumer（誰讀、做什麼決定） | v1 機制 | 負控 |
|---|---|---|---|
| `SEED` | execution assembler：對宣告 `SEEDED_REQUEST`（01B）的綁定把 seed 放進 canonical request。要求 seeded 而引擎無 `SEED` → typed `UNSUPPORTED_CAPABILITY` | bridge 的 generate 請求含 seed 欄；宣告依 probe：送兩個不同 seed，transport spy 斷言 request 逐欄忠實交付 | 宣告 `SEED` 而 bridge 丟棄／覆寫／固定 seed → 紅在 `seeded_request_delivers_seed`；防恆真＝未宣告者不被要求接受 seed |

**刻意不進能力集的**（各有理由，不是漏列）：

- `GREEDY`——`GREEDY ∨ SEED` 的准入條件會**讓沒有 seed 的 probe 鑄出
  `SEEDED_OUTPUT_REPEATABILITY_OBSERVED`**，撞上 01B 既有的 `SEEDED_` 語意。
  greedy 設定留在 probe evidence 與 sampler fingerprint。
- `TEMPERATURE`／`TOP_P`／`TOP_K`／`MIN_P`／`REPETITION_PENALTY`——這些是
  **sampler semantics（指紋層）**，只進 fingerprint，不供協商。

**能力集（可協商）與語意值（純指紋）分兩層，不互混。**
日後重入必須**先出現真正的 consumer**，再補 admission schema、checker、固定負控
——**不得為了湊成員反向創造 consumer**。

【推論】`LocalInferenceEngine.generate(request,cancellation)`只輸出typed chunks/turn/tool/usage/error。工具能力不是模型文字宣稱；只有engine bridge提供typed tool-call schema才advertise。

【推論】exact context meter以同tokenizer+chat template渲染實際outbound input後計數；若只能算text不能算template framing，使用證成的framing upper bound，否則context accounting unsupported。
