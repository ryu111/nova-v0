# 宣告式狀態機 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` (recommended) or `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 【推論】讓 MachineSpec／FlowSpec 成為 runtime 與圖的單一 source，編譯期證明 guard 互斥完備與結構可達性，執行期只准走 declared transition。

**Architecture:** 【推論】JSON source 先經封閉 schema、canonical digest、reference resolution與 lint，再編成 immutable MachinePlan／GraphIR。Guard v1 只接受 BOOL、ENUM、BOUNDED_INT scalar facts與封閉 AST；複雜判斷必須先成 typed authority event。

**Tech Stack:** 【推論】CPython 3.14.7、JSON Schema 2020-12、frozen dataclasses、Hypothesis、Graphviz DOT／SVG、ClaimSpec runner（Plan 01）。

**Spec:** 【查證】本檔「子系統規格」、[第三輪狀態機](../sol-新局-第三輪.md#2-q1狀態機是資料不是帶著狀態名稱的程式碼)、[第五輪 Guard v1](../sol-新局-第五輪.md#3-guard-v1能表達什麼絕對不能塞什麼)。

## Global Constraints

- 【推論】先完成 [01](./01-可執行保證語言.md)；所有 structural／behavioral lints 都有 ClaimSpec 與固定反例。
- 【推論】MachineSpec、FlowSpec 是 source；GraphIR、DOT、SVG 是 deterministic artifacts，沒有手改入口。
- 【推論】Guard 禁止 callback、module path、shell、eval、clock、I/O、random、fact-to-fact compare與 arithmetic。
- 【推論】Guard limits：depth 8、nodes 64、ALL／ANY children 2–16、set 1–32、facts 32、proof cells 4,096。
- 【推論】CustomDecisionProducer 不在 Guard AST；上限為每 machine 1、全域 3、依賴 edges `max(1,floor(N/5))`。

## 子系統規格

【推論】MachineSpec 擁有單一 aggregate 的 state／trigger／guard／edge／terminal／**output（`output_id`＋`payload_digest`，由 transition 的 `emits` 引用）**；FlowSpec 只綁既有 output→trigger與 parent cardinality；GraphIR 只供 view。每個 entity 永久釘 machine digest，升版只能走顯式 MachineMigration。

【推論】compiler 對每個 `(state, trigger)` 建 finite proof cells：BOOL 兩格、ENUM 每 symbol、BOUNDED_INT 依 literal 切 interval／point；每 cell 恰一 edge，0 是 `GUARD_NOT_EXHAUSTIVE`，2+ 是 `GUARD_OVERLAP`，並回最小 witness。
