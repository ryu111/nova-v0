# 開發期工坊 Implementation Plan

**Goal:** 【推論】把「派工給不可靠執行者」這件事的**固定損耗**（工單轉錄、
grant 握手、驗收報告）從人手挪到機械，讓計畫的實作階段跑得動。
**這是開發期基礎設施，不是產品功能**——產品化版本在計畫 05／08／12／14–17，
本計畫帶明文退役條件，屆時整包刪除、流程平移產品介面。

**Architecture:** 【推論】`工坊/` 是**具名的暫居頂層**：`出工單.py` 從計畫 task
區段機械生成工單並綁來源 digest；三個角色薄殼只做「讀 prompt ＋ 收工單 ＋
驗 grant ＋ 呼叫後端 ＋ 原樣收輸出」；`驗工.py` 是**非 LLM 的獨立驗工入口**。
**dispatch 邏輯（retry／cascade／收斂）明文禁止入殼**——那是產品 Work／Pursuit
的地盤，在殼裡長就是第二個 harness。

**Tech Stack:** 【推論】CPython 3.14.7、pytest、tomllib；後端為外部 CLI
（claude／codex／agy），以 PATH resolve 後的絕對路徑執行。

## Global Constraints

- 【推論】三個角色的輸出一律是 **observation／advice**，**不得取得 acceptance
  authority**——接受權只在 ClaimSpec 閘。
- 【推論】工單為動態產物，預設輸出 stdout 或 repo 外路徑；**不入 Create 清單**
  （寫進 `工坊/` 會逐份撞 `UNPLANNED_FILE`）。
- 【推論】`files_scope` 的重疊拒絕**只約束同一 dispatch batch**；跨 batch／
  跨程序**明講不防**——active registry ＋ owner ＋ 生命期就是 lease 機制，
  那是產品 Work 的地盤。`從簡:` 天花板與升級路徑見 Task 2。

### Task 2: 出工單與獨立驗工入口

**Files:**
- Create: `工坊/出工單.py`
- Create: `工坊/驗工.py`
- Create: `工坊/test_出工單.py`
- Create: `工坊/test_驗工.py`
- Create: `規格/工程/保證/工單封閉且拒絕過期.claim.json`

**Interfaces:**
- Produces: 工單封閉 schema——`schema_revision`、plan 相對路徑＋task id、
  **task 區段原始 byte digest**、`base_commit_sha`、prompt revision ＋ digest、
  驗收命令、`files_scope`、grant、backend／model identity。
- Produces: **消費三驗**——重讀來源並重算 digest、驗工作樹基準 SHA、
  驗 `schema_revision`。【查證】只把 SHA 印進工單而不驗它，**舊工單照樣能打新樹**。
- Produces: `files_scope` 重疊拒絕**只在同一 batch 內**（`從簡:` 跨 batch 不防，
  升級路徑＝產品 Work 的 lease 承接）。
- Produces: 【查證】**不得寫死 `zsh`**：第一版寫死它，本機（macOS）八道全綠而**CI 的 Linux runner 沒有 zsh**，`FileNotFoundError: 'zsh'` 讓整道 tests 閘掛。本機綠不等於閘綠——這是「換個情境跑綠不能判定假紅」的反面。

- Produces: `驗工.py` 為**非 LLM 入口**：零個或多義的最終 PASS 命令 **fail-closed
  不自行猜**；以**探測到的**嚴格旗標執行（`sh -euo pipefail`，在沒有 `pipefail` 的 POSIX `sh` 上退成 `sh -eu` 並明講該上限）；逐條記 argv 與 exit；失敗與**未執行**
  都明列；**全部 exit 0 才輸出 green**。
- Forbids: 角色殼取得 acceptance authority。

**ClaimSpec:** 【推論】`workshop.work-order.closed-and-stale-rejecting` 從紅轉綠。

**ClaimSpec落點:** `workshop.work-order.closed-and-stale-rejecting` → `規格/工程/保證/工單封閉且拒絕過期.claim.json`（本 task Create）

**固定負控:** 【推論】工單手改一字紅在 `work_order_digest_mismatch`；
舊工單打新樹紅在 `stale_base_commit`；缺欄或未知 `schema_revision` typed 拒；
同 batch 兩張 `files_scope` 重疊第二張必拒，紅在 `files_scope_overlap_in_batch`；
零個或多義 PASS 命令紅在 `ambiguous_acceptance_command`；
**假後端零產出而回 `"status":"SUCCESS"` 時驗工入口不得 green**
（agy 實案機械化，見 `docs/陷阱.md`）。
防恆真：合法工單＋正確 digest＋基準相符＋單一 PASS 命令照常 green。
