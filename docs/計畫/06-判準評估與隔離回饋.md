# 判準評估與隔離回饋 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` (recommended) or `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 【推論】讓判準定義與候選執行彼此隔離、讓裁定輸出有受控梯度，並確保任何一次揭露都不可逆地燒掉該 sealed case；宿主能力不足時 typed fail，絕不靜默降級。

**Architecture:** 【推論】判準面拆成 immutable definition authority、evaluation authority 與 feedback reducer。候選只取得 guidance pool 的公開條款；sealed pool 的檔案與 expected values 不進候選 workspace。評估器在 execution 結束後取得候選 CAS snapshot，以 `IsolationCapability` 協商可執行等級；reducer 只輸出 clause-level code、位置類別與 remediation class，不逐字轉送 assertion repr。

**Tech Stack:** 【推論】CPython 3.14.7、ClaimSpec/TestPlan、MachineSpec、temporary filesystem projection、subprocess evaluator、CAS evidence、SQLite state owner。

**Spec:** 【查證】本檔「子系統規格」，以及[第一輪性質 4 解法](../sol-新局-第一輪.md)、[第二輪威脅模型與 ClaimSpec](../sol-新局-第二輪.md)、[第三輪 isolation 裁決](../sol-新局-第三輪.md)、[第四輪約束與隔離更正](../sol-新局-第四輪.md)。

## Global Constraints

- 【推論】v1 明講只防「無意看到」；同 UID、無 sandbox 時不宣稱抵抗主動 syscall／`/proc`／socket 竊取。
- 【推論】每個 ClaimSpec 必填 `isolation.required_capabilities`；offer 不覆蓋 requirement 時結果只能是 `UNSUPPORTED_ISOLATION`。
- 【推論】guidance 與 sealed case 使用不同 content roots、不同 projection manifest、不同 process invocation；候選 invocation 不帶 sealed path、digest 或 expected value。
- 【推論】回饋粒度固定為 `clause_id + outcome_class + location_bucket + retryability`；原始 stdout/stderr 只進 evidence，不能直接回給執行者。
- 【推論】sealed case 一旦 raw detail 被授權揭露，當次 evaluation 可完成，但 case 立即 `BURNED`，不得再用於後續 admission。

## 子系統規格

【推論】`CriterionDefinition` 指向 guidance cases 與 sealed cases 的 immutable refs；`EvaluationRun` 狀態為 `REQUESTED -> ISOLATION_CHECKED -> RUNNING -> REDUCED -> VERDICT_RECORDED`，另有 typed terminals `UNSUPPORTED_ISOLATION`、`HARNESS_FAULT`、`CANCELLED`。

【推論】`Verdict` 是 evaluation authority 的產物，包含每條 claim 的 typed result與 evidence refs；它不包含 ClaimSpec source bytes。`FeedbackPacket` 是衍生物，不是 verdict 本體。

【推論】v1 capability vocabulary 固定為 `SEPARATE_PROCESS`、`OMIT_SEALED_PATHS`、`ENV_ALLOWLIST`、`NO_INHERITED_FDS`、`NETWORK_POLICY_DECLARED`；其中前四項可以在目前部署提供，`NETWORK_DENY_ENFORCED`、`PROC_HIDE`、`UID_SEPARATION`、`MICROVM` 只可被宣告為 unsupported。
