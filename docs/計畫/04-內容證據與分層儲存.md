# 內容證據與分層儲存 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` (recommended) or `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 【推論】建立 domain-neutral CAS、不可覆寫 EvidenceRecord、hot／warm／cold retention、recovery checkpoint與可驗 backup，使 hot SQLite 可 prune 而 event truth、active Work replay與稽核證據不變弱。

**Architecture:** 【推論】大 bytes blob-first 寫 CAS、metadata second 寫 state-owner transaction；event archive 先寫且驗 segment，再 commit SegmentManifest，checkpoint＋suffix 等價 full replay後才可在 24h overlap後 prune。CAS 可物理去重，但 recovery／operational／audit／raw／artifact pin ledgers分開。

**Tech Stack:** 【推論】CPython 3.14.7、filesystem CAS（atomic rename＋SHA-256）、SQLite state owner port、immutable segments、Hypothesis state machines、subprocess SIGKILL。

**Spec:** 【查證】本檔「子系統規格」、[第五輪 tiered storage](../sol-新局-第五輪.md#2-envelope-與儲存你的乘法成立第三輪必須翻案)、[第二輪 backup SLO](../sol-新局-第二輪.md#32-建議的-v1-design-envelope)。

## Global Constraints

- 【推論】Plan 01、03 必須綠；CAS 不可直接改 authority status，SegmentManifest／pins 只能由 state owner寫。
- 【推論】logical event log = hot committed range + committed manifests所引用且 hash 正確的 segments。
- 【推論】segment 每 1h或64MiB uncompressed先到者；checkpoint每 active aggregate 256 transitions或1h先到者；hot overlap 24h。
- 【推論】retention：operational 90d、audit 365d、raw 30d、accepted artifact 365d；到 hard point停 ordinary admission，不早刪。
- 【推論】容量 points：hot 4/8/10GiB、operational16/20GiB、audit12/16GiB、raw64/80GiB、artifact24/32GiB。

## 子系統規格

【推論】`ContentRef(algorithm,digest,size,media_type)` 對 bytes 唯一；put 同 bytes 冪等、get 必驗 digest。EvidenceRecord 只能 append；更正新增 record並指向被更正 id。

【推論】checkpoint 包含 aggregate id／seq、machine digest、fold-code digest、state digest、covered cursor。corrupt／wrong-code checkpoint 必須棄用 full replay，不能讓 cache取得 truth。

def put(self, content: bytes, media_type: str) -> ContentRef:
