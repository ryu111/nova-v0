# 06B 技術效益評測

前置計畫：01 02 03 04 05 06

**Goal:** 【推論】回答「某項技術值不值得用」——對 baseline 與 treatment 做成對實驗，
產出**帶不確定度的比較證據**：token 用量的**上界**降低，且品質的**下界**不低於門檻，
兩者同時成立才接受。要的是**範圍值不是精準值**，而且區間必須窄到能做決定。

**Architecture:** 【推論】本計畫擁有一個獨立生命週期：
`DRAFT → DESIGN_FROZEN → RUNNING → EVIDENCE_SEALED → ANALYZED → ACCEPTED|REJECTED|INCONCLUSIVE|INVALIDATED`。
它不是 06 的一次 EvaluationRun（06 擁有「單一候選合不合既定 criterion」），
不是 07 的一種帳（07 擁有「能不能花、花了多少、還剩多少」），
也不是 09 的選拔（09 擁有「已有合法分數後怎麼選 winner」）。
它消費 plan 05 已正規化的 `UsageEvidence`；若 05 尚不能提供 tree-inclusive token evidence，
該 run 是 `USAGE_SCOPE_INCOMPLETE`，**不得偷偷改用 07 的金額帳替代**。

## 子系統規格

【推論】**兩個端點，intersection-union 決策，兩條都過才接受。不得揉成一個效益分數**——
揉成一個分數就是讓省 token 去補償品質下滑。

- **token 端點**：上界檢定。`token_treatment / token_baseline < max_token_ratio`（單側上界）。
- **品質端點**：非劣性檢定。`quality_treatment − quality_baseline > −noninferiority_margin`（單側下界）。

【推論】**兩個門檻不是同一回事，混用會讓結論失去意義**：
`max_token_ratio` 是**決策門檻**（至少要省多少），`max_interval_width` 是**精度門檻**
（區間寬到分不出結論就不是答案——「省 0–90%」不是答案）。

【推論】**只有相對非劣性不夠，必須同時有絕對下限 `minimum_absolute_quality`。**
理由：baseline 品質 0.20、treatment 品質 0.20，統計上非劣，但根本沒有使用價值。

【推論】**決定性只在三段成立，中間那段不成立，這是外部事實不是實作缺陷**：
`ExperimentSpec → RunPlan` 必須決定性；`live invocation → model response` **不要求**；
`已完成 run → EvidenceBundle` 必須 immutable；`同 EvidenceBundle → 統計結果` 必須決定性。
`rerun_model` 建立新的 `MeasurementRun`，**不是 replay**，不覆寫舊 run。

【推論】**nova 不自己寫統計核心。** 它擁有 frozen protocol、evidence manifest、
決定性的分析呼叫與 pass/fail 政策；bootstrap 與信賴區間用**釘版的成熟實作**，
package／version／locked artifact hash 進 analysis fingerprint。自己寫就從可驗收工程滑成自製統計套件。

**Interfaces:**
- Produces: `分析(bundle, spec) -> TechniqueExperimentResult`。回報的是**區間**不是點值。
- Consumes: 釘版的 `scipy`（`scipy.stats.bootstrap`，`method="BCa"`）與 `numpy`
  （seeded `Generator`）。**兩者都列為 direct dependency**——`numpy` 被直接 import，
  不得只依賴 `scipy` 的傳遞依賴。
- Produces: `analysis_fingerprint` 綁六樣：package name、package version、
  **實際安裝的 artifact 與完整 `uv.lock` 的 digest**（不是從 lock 裡任選一個未必安裝的 wheel hash）、
  analysis 函式的 revision、parameters、analysis seed。
- Forbids: 自寫 bootstrap、信賴區間或非劣性統計；resampling unit 不是 case；
  把同一 case 的 replicates 當獨立樣本（配對分析必須明寫 `paired=True`）。

**ClaimSpec:** 【推論】`evaluation.technique.token-upper-quality-lower.predeclared` 由紅轉綠。

**ClaimSpec落點:** `evaluation.technique.token-upper-quality-lower.predeclared` → `規格/評測/保證/技術效益雙端點事前凍結.claim.json`（Task 1 Create）

【推論】**fixture 契約**（審查條件，2026-08-28）：兩個門檻的負控 fixture
**必須提供原始成對 observations，由釘版分析器實算區間與決策，不得直接塞入人工 interval**
——塞人工區間測的是 fixture 不是分析器。
「區間過寬」那格要滿足：輸入只有事前凍結的 spec、原始 paired observations 與 analysis seed；
reference analyzer 實算出**兩個端點皆過**、同時 interval width > `max_interval_width`、
結果必為 `INCONCLUSIVE`；**faulty analyzer 的唯一變異是略過 width gate**，因而錯判 `ACCEPTED`。
可以把 `max_interval_width` 設得比該資料自然產生的區間更窄，**無須偽造區間**。
絕對品質那格同理：由原始品質 observations 實算出相對非劣、但 lower bound 低於 absolute floor。

**固定負控:** 【推論】四格。`ineffective-technique`：treatment 與 baseline 的 token 來自同一分布、
品質可相同，必須紅在 `token_ratio_upper_bound_exceeds_max`。
`saves-but-degrades`：token 端點過但品質差超過 margin，必須**只**紅在 `quality_lower_bound_below_margin`
——兩格分別殺一條，證明兩端點都有牙且**不能互相補償**。
`package-swap-same-fingerprint`：同一 EvidenceBundle 換統計套件版本卻宣稱同一 fingerprint。
`fingerprint-missing-package`：fingerprint 少了 locked artifact hash 仍通過准入。
後兩格必須紅在 `analysis_fingerprint_covers_package`。
`wide-interval-not-inconclusive`：區間寬於 `max_interval_width` 仍判 `ACCEPTED` 的
分析器變體，必須紅在 `interval_width_within_max`——精度門檻是 spec 明文的第二個
門檻，「省 0–90%」不是答案，它要有自己的殺手。
`low-absolute-quality-accepted`：兩端點統計上都過、但絕對品質低於
`minimum_absolute_quality` 仍 `ACCEPTED` 的變體，必須紅在
`absolute_quality_floor_enforced`——baseline 0.20 對 treatment 0.20 非劣但沒有使用
價值，spec 自己說的，殺手原本缺席。
（R13 覆蓋審：06B 是三方自己新開、從未被審過的計畫——兩條 claim 對兩個端點的牙
是真的，但 spec 宣告的**四個門檻裡有兩個零殺手**。）
防恆真格：事前造好的「真省且品質非劣」配對樣本 `ACCEPTED` 且回報區間；
同 bundle＋同 fingerprint＋同 seed 兩次分析的 result digest 相同。

**【實測，2026-08-27】** CPython 3.14.7 上解析到 scipy 1.18.1＋numpy 2.5.2，
`scipy.stats.bootstrap(method="BCa")` 跑得動，同 seed 兩次區間逐位相同、換 seed 不同。
**這只證明目前釘版的這一組堆疊可重播，不得升格成所有 scipy 版本的保證**——
所以 fingerprint 必須綁實際安裝的 artifact。
