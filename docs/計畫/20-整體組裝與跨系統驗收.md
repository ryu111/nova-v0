# 整體組裝與跨系統驗收 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` (recommended) or `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 【推論】把前 19 個已各自驗收的子系統組成單機 production topology，證明三層生命週期、四權威、五種 executor backend、CAS／分層事件、effects、constraints、UI 與自我維護在真實邊界及全程序崩潰下仍共同成立；本計畫不新增任何單一 owner 的領域規則。

**Architecture:** 【推論】`nova/啟動/` 是唯一 production composition root：它從 immutable `規格/目錄.json` 載入 exact digests，向各程序只注入 consumer-owned ports，再以 state owner、scheduler、evaluator、event publisher、effect relay、backup、application server 的獨立 process specs 啟動。跨系統驗收使用真 SQLite／filesystem CAS／OS processes／HTTP-SSE；只有外部付費或破壞性 endpoint 以符合相同 contract 的 deterministic fixture 取代 I/O，fixture 不得偽造 owner verdict。

**Tech Stack:** 【推論】CPython 3.14.7、uv、pytest 9.1.1、Hypothesis、xdist、SQLite rollback＋WAL tail、filesystem CAS、JSON Schema、Graphviz、ASGI／SSE、TypeScript／Vite／Vitest、POSIX process signals。

**Spec:** 【查證】本檔「子系統規格」、[總覽依賴圖](./00-總覽.md#4-依賴圖)、[第三輪定案 source/runtime tree](../sol-新局-第三輪.md#32-source-tree規格到最小職責檔案)、[第五輪修正 envelope](../sol-新局-第五輪.md#2-workload-envelope重算並補上缺的穩態欄位)與[雙方簽字](../控制端審查.md#六簽字2026-08-26)。

## Global Constraints

- 【推論】本計畫只建立跨 subsystem ClaimSpecs；單一 authority 的 predicate 只能引用既有 immutable ClaimRef，不能複製後改成較弱版本。
- 【推論】production composition 不得注入 `Fake*`、`InMemory*`、test clock、test primitive 或 bypass evaluator；測試 fixture 可替代外部 I/O，但必須經 production port／gate／state owner。
- 【推論】整體 PASS 需要 actual＋positive 全綠、每個事前命名 negative direct red、harness failures 為 typed non-pass；不得用 xfail、retry-until-green、mutation raw kill rate 或 live paid backend availability 代替。
- 【推論】跨崩潰測試必須啟動真 OS processes、對整組 PID 發 SIGKILL、丟棄全部記憶體 object，再只用 runtime data root 重啟；呼叫 shutdown hook 或保存 Python object 不算。
- 【推論】同 UID／無 sandbox 的 v1 只宣稱 `COOPERATIVE_PROCESS`；整合 suite 必須拒絕更強 isolation claim，不測不存在的 hostile confidentiality。
- 【推論】外部供應商測試分成 offline contract gate 與 opt-in live diagnostic；release PASS 只依 deterministic contract gate，live diagnostic 不能把 rate limit／網路故障歸咎 production code，也不能反過來掩蓋 adapter contract red。
- 【推論】release evidence 分成 `CORE_DEPLOYABLE` 與 `BACKEND_READY[exact_fingerprint]`；前者全 deterministic，後者需要未過期 live conformance evidence。部署若啟用 Claude，兩者必須同時為真。
- 【推論】50 tx/s 是 60 分鐘 engine-selection soak，不是 production steady；0.5 tx/s transaction／2 events/s 是 24 小時 rolling steady sizing。兩者各自產生 evidence，不能混成一個平均數。
- 【推論】工具薄殼只依 exit code 聚合，不能修改 pytest／ClaimSpec／Vitest 結果或在失敗時回 0。

## 子系統規格

【推論】production processes 固定為 `state-owner`、`work-scheduler`、`evaluator`、`event-publisher`、`effect-relay`、`backup-worker`、`application-server`；前端是 application server 的 immutable build artifact。所有 process 都有 component id、capability manifest digest、spec catalog digest、readiness event與 typed unhealthy event，沒有共用 mutable Python singleton。

【推論】`規格/目錄.json` 是 production bootstrap closure：每項固定 semantic id、revision、relative NFC path、canonical SHA-256、kind 與 dependencies；catalog 本身不列自己。啟動時 bytes 或 dependency closure 任一不符就 fail before opening a writable DB。

【推論】整體 backend matrix 固定五列：pure replayer、Claude Agent SDK、Codex CLI、generic CLI、local model。每列跑相同 InvocationEnvelope／ContextManifest／budget reserve-settle／terminal／cancel／quota evidence contract；不適用能力要回 manifest-declared `UNSUPPORTED_*|NOT_APPLICABLE`，不能跳過該格。

【推論】release gate 有兩個 profile：`--quick` 跑所有 deterministic functionality／named negatives但不授予 storage selection claim；`--release` 額外跑 60 分鐘 soak、burst、真備份還原與全程序 kill matrix。只有 `--release` 的 evidence bundle可標記 deployable。
