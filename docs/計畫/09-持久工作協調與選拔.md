# 持久工作協調與選拔 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` (recommended) or `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 【推論】建立跨程序、跨崩潰的 Work portfolio：持久排程最多八個 Pursuit、在明確 cutoff 前收集合格候選、以釘版 ranking schema 確定性選最好，並在 7 天／8,192 operational events／總預算等界線內必然終止。

**Architecture:** 【推論】Work 是第三個垂直生命週期與父聚合，擁有目標、child set、portfolio budget、pinned criterion/knowledge/allocation/ranking refs、cutoff 與 SelectionRecord。它只建立／取消 Pursuit，不直接建立 Execution。排程拓撲固定是持久佇列加顯式父子；禁止 child-to-child prerequisite、跨 Work join 與 arbitrary DAG edge。選拔以 `cutoff_global_seq` 封住晚到 verdict，再以 schema-defined ordered dimensions 與 digest tie-break 確定結果。

**Tech Stack:** 【推論】CPython 3.14.7、MachineSpec/FlowSpec、SQLite single owner/leases、event log/CAS、fake clock、ClaimSpec runner、deterministic Decimal comparator。

**Spec:** 【查證】本檔「子系統規格」，以及[第二輪 Work/Pursuit 分權與 envelope](../sol-新局-第二輪.md#2-q2目標追求是層而且現在就拆)、[第三輪父子與 BEST_BEFORE_DEADLINE](../sol-新局-第三輪.md#41-平行搜尋的選拔與停止)、[第五輪 7 天與 8,192 events](../sol-新局-第五輪.md#2-儲存三個數字確實互相矛盾)。

## Global Constraints

- 【推論】Work nonterminals：`READY`、`RUNNING`、`SELECTING`、`WAITING`；terminals：`SATISFIED`、`EXHAUSTED`、`DEADLINE_EXHAUSTED`、`EVENT_LIMIT`、`FAILED_FINAL`、`QUARANTINED`、`CANCELLED`。
- 【推論】Work 建立後 absolute deadline 最晚 `created_at + 7 days`，pause/wait 不停鐘，呼叫端與執行者都不能延長。
- 【推論】每 Work 最多 8 個 Pursuit、同時 active 最多 4；全系統 active Pursuit 32、running Execution 8，額外項目在持久 queue 等待。
- 【推論】每 Work 最多 8,192 個 operational domain events；第 8,192 槽只可寫 typed terminal，第 8,193 筆由 DB constraint 拒絕。CAS raw chunks 不計入，領域 transition／intent／ledger events 都計入。
- 【推論】selection policy 固定 `BEST_BEFORE_DEADLINE`；第一個 ACCEPT 不立即封 Work，固定 N 未完成也不強迫等到最慢。
- 【推論】cutoff 是 deadline、全部 Pursuit terminal、或資源永久不足且無 running/reserved action三者先到；temporary quota stale/unknown 不構成永久不足。
- 【推論】cutoff 時先持久化 `cutoff_global_seq`，之後拒絕新 reserve；只有 `VerdictRecorded.global_seq <= cutoff_global_seq` 可參選。

## 子系統規格

【推論】`RankingSchema` 是 ordered nonempty dimensions：每維必填 `score_id`、`value_type=INTEGER|DECIMAL`、`direction=ASC|DESC`、`missing=REJECT_CANDIDATE`；維度全相同時以 candidate digest ASCII ascending tie-break。自由文字不能參與 comparator。

【推論】SelectionRecord 固定保存 eligible candidate refs、每維 normalized values、excluded reason、ranking schema digest、cutoff seq 與 winner ref；Work 只能在 record append 成功後進 terminal。

【推論】自我維護不直接修 production。Health Claim red 只可產生帶 evidence refs 的 maintenance Work proposal；它仍受 Work admission、budget、criterion與 effect gates。1,000 nonterminal Work 配額中固定保留一槽給 maintenance。
