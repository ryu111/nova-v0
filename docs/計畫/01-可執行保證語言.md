# 可執行保證語言 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` (recommended) or `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 【推論】建立最小信任根：一份 ClaimSpec 可確定性編成外部 TestPlan，對 actual／正控接受，對事前固定錯誤 subject 產生指定 direct red，且 harness fault 永不冒充候選失敗。

**Architecture:** 【推論】ClaimSpec source 與 mutable verdict 分離；compiler 只接受封閉 primitive catalog 與 typed predicate AST。外部 pytest adapter 把 actual、positive sensitivity、negative sensitivity 各註冊成獨立 test id，EvidenceRecord 保存 direct result；production subject 只由 BindingManifest 綁定。

**Tech Stack:** 【推論】CPython 3.14.7、uv、JSON Schema 2020-12、pytest 9.1.1、Hypothesis、xdist、mutmut 3.7.0、Ruff 0.16.4、mypy 2.3.1、dataclasses／enum、SHA-256 canonical JSON。

**Spec:** 【查證】本檔「子系統規格」，以及[第二輪 ClaimSpec](../決策/sol-新局-第二輪.md#5-q5第一份具體檔案與-claimspec-v0)、[第五輪工具鏈實測](../決策/sol-新局-第五輪.md#4-cpython-314不是看起來支援是真的跑過)、[控制端複驗](../決策/控制端審查.md#工具鏈我的一手複驗不是採信它的宣稱)、[Ruff設定與check模式](https://docs.astral.sh/ruff/configuration/)、[mypy strict構成](https://mypy.readthedocs.io/en/stable/existing_code.html)、[Python identifier normalization](https://docs.python.org/3/reference/lexical_analysis.html#identifiers)與[Bash name定義](https://www.gnu.org/software/bash/manual/html_node/Definitions.html)。

## Global Constraints

- 【推論】Python 固定 3.14.7；所有 schema object `additionalProperties=false`；semantic ids 用 ASCII。
- 【實測】pytest 同時 discover `測_*.py/test_*.py`、`測試_*/test_*`、`測_*/Test*`，`pythonpath=["."]`。
- 【實測】mutmut 設 `source_paths`、list 型別 `tests_dir`、list 型別 `also_copy`；不得以 mutation kill rate 驗收。
- 【推論】actual／positive 必須 `ACCEPT`；negative 必須 direct `CLAIM_REJECTED` 且 failed predicate ids 恰等於 `must_fail_exactly`。
- 【推論】`UNBOUND_SUBJECT`、`UNSUPPORTED_ISOLATION`、`HARNESS_ERROR`、`HARNESS_LIMIT` 是獨立結果，不得被 negative control 當成功。
- 【推論】day-one Python gate固定 `ruff format --check`、`ruff check`、`mypy --strict` 與 repository AST checker；沒有 baseline ignore檔、沒有「先累積再清」。Ruff官方把format/lint設定集中於`pyproject.toml`，且`--check`會以non-zero表示需重排；mypy官方的strict包含禁止untyped defs/calls、Any generics、implicit re-export與return Any等檢查。
- 【推論】Python production code的硬上限：module最多400行logical code、class最多250行、function/method最多60行且McCabe complexity最多10、branch最多12、parameters最多6。超過不是加ignore，而是拆責任；generated/vendor bytes不進`nova/`。
- 【推論】所有production module與public class/function/method必須有docstring；內容語言不限，機械gate要求non-empty summary line且不能等於「名稱＋標點」的直接重述。tests/fixtures只免docstring，不免format、lint與型別可解析。更細的「說得好不好」不可可靠機判，只是code review診斷，不能被宣稱為系統保證。
- 【推論】import固定absolute-only、stdlib/third-party/first-party分組、module top-level、禁止wildcard與跨層捷徑；Ruff執行格式/順序，`架構/目錄規則.toml`與AST checker執行nova九層依賴。
- 【推論】Python識別字可全中文或全ASCII，必須NFC，禁止同一identifier混用Han與Latin以免同形／規約漂移；dunder與前導underscore不計script。跨程序semantic id、event/schema field、DB table/column、CLI executable、failure code與shell variable/function name一律ASCII。Python允許Unicode identifiers並在解析時做NFKC normalization；Bash name只接受字母、數字、underscore且不能以數字開頭，因此shell不適用中文命名。
- 【推論】未列在任何active plan `Create:` 的新檔案不得進repo。需要新增落點時先修plan、通過`docs/計畫複驗.py`與placement gate，再建立檔案；「實作時順手多一個helper」不是例外。

## 子系統規格

【推論】輸入是 immutable ClaimSpec bytes、PrimitiveCatalog digest、BindingManifest digest、IsolationOffer digest；輸出是 immutable TestPlan 與 typed CaseResult。statement 只供人讀，沒有判定權。

【推論】ClaimSpec 0.2.0 top-level 固定包含 `$schema`、`claimspec_version`、`claim_id`、`revision`、`supersedes`、`statement`、`sources`、`primitive_catalog`、`subject`、`parameters`、`setup`、`stimulus`、`observations`、`judge`、`controls`、`run_limits`、`isolation`、`effect_delivery`、`evidence`、`feedback`、`cleanup`；`effect_delivery` 依是否使用外部效果原語而必須是閉合契約或 `null`，檔案內沒有 ACTIVE／PASS／admitted_by。

【推論】designated mutation 是 `NegativeControl` 或 `MutationControlRef` 在 admission 前固定的 faulty subject／semantic anchor；mutmut 全掃只產生 diagnostic EvidenceRecord，不產生 acceptance percentage。

def run_with_wall_limit(argv: tuple[str, ...], wall_ms: int, grace_ms: int) -> ExecutionResult:
    process = subprocess.Popen(argv, start_new_session=True, close_fds=True)
    try:
        process.wait(timeout=wall_ms / 1000)
        return ExecutionResult.from_returncode(process.returncode)
    except subprocess.TimeoutExpired:

        process.wait(timeout=grace_ms / 1000)
        return ExecutionResult.terminal("TIMED_OUT")
