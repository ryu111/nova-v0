# 應用服務與外部介面 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` (recommended) or `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 【推論】提供 CLI、Python caller、HTTP、MCP 與前端共用的唯一 use-case boundary：相同 typed command得到相同 decision/error/events；外部介面不能取得 repository/SQL/權威寫口，view只可訂閱事件與按digest取GraphBundle。

**Architecture:** 【推論】`nova.應用.邊界` 只暴露 `execute(command_envelope)`、`get_operation(operation_ref)`、`subscribe(after_cursor, subject_filter?)`、`get_graph_bundle(digest)`。CommandBus把命令送入各 use-case handler，handler以 UnitOfWork port協調三層與四權威但不自行宣告終態。`OperationReceipt` 只由 event projection fold，不能查 domain repository。CLI/Python/HTTP/MCP都是純協定轉換，唯一可import應用boundary；composition root才可注入SQLite、event tail、CAS與backends。

**Tech Stack:** 【推論】CPython 3.14.7、dataclasses/tagged JSON、OpenAPI 3.1、ASGI/SSE、JSON Schema、SQLite tail port、ClaimSpec、import-linter/AST checks。

**Spec:** 【查證】本檔「子系統規格」，以及[第三輪完整目錄樹的應用/介面邊界](../sol-新局-第三輪.md#22-完整目錄樹)、[前端控制需求](../需求-前端控制.md)、[第四輪 constraint commands](../sol-新局-第四輪.md#52-新增取代或保留的-claimspec-semantic-ids)。

## Global Constraints

- 【推論】所有 mutating commands 必有 ASCII `command_id`、caller identity/capabilities、idempotency key、expected schema version；重送同 bytes同結果，key同但bytes不同typed conflict。
- 【推論】client不能傳 terminal state、verdict、ledger balance、ACTIVE constraint/knowledge status或delivery receipt；這些只由owner commands產生。
- 【推論】application handler不能import concrete SQLite、filesystem、network或backend；只import領域公開契約與權威ports。
- 【推論】CLI、Python、HTTP、MCP對同command canonical bytes回同 `ApplicationResult` kind/reason/event refs。
- 【推論】MCP 是第四個 transport adapter，不取得新權威；舊 operation 若無 exact typed mapping 必須回 `DEPRECATED_OPERATION|UNSUPPORTED_OPERATION`，不得靜默消失或猜舊語義。
- 【推論】訂閱先catch-up後live，cursor是global seq+event digest；duplicate可忽略，gap/out-of-order typed error，不能偷偷查domain補畫面。
- 【推論】`subject_filter` 只接受 exact typed subject refs；它只過濾 emitted envelopes，不重編 global cursor、不把被濾事件偽裝成不存在，也不能變成任意 predicate/domain query。
- 【推論】long-running command 的進度真相是 domain event prefix；`OperationReceipt` 是同一 prefix 的純 projection，不是 ticket table或第二份狀態。
- 【推論】core contract 不依賴 experimental MCP Tasks schema/version。MCP adapter 可在自己邊界做 capability negotiation；未協商時仍用 `ACCEPTED + OperationRef + get_operation/subscribe`。
- 【推論】GraphBundle只按immutable digest取；不存在/摘要錯是typed error，不提供「目前最新」mutable pointer給view。

## 子系統規格

【推論】public command envelope v1固定 `command_id`、`command_schema_ref`、`payload`、caller／capabilities、idempotency key；payload只能引用啟動時已准入的exact-digest command schema。plan 13 的bootstrap catalog固定 `CreateWork`、`PausePursuit`、`ResumePursuit`、`CancelPursuit`、`CancelWork`、`AdjustBackendAllocation`、`RequestBackendUpdate`、`ProposeKnowledge`、`ReviewKnowledge`、`RevokeKnowledge`、`ProposeConstraint`、`ApproveConstraint`、`RetireConstraint`。新增command必須同一變更集加入封閉payload schema、typed model、唯一handler、ACL與fixed negative；不改envelope、不接受free-form action string。

【推論】`ApplicationResult` union固定 `ACCEPTED(command_id,event_refs,operation_ref?,result_ref?)|REJECTED(reason_code,evidence_refs)|CONFLICT(existing_digest,received_digest)|UNAUTHORIZED(missing_capabilities)|UNSUPPORTED(reason_code)`；long-running command 的 ACCEPTED 必帶 `OperationRef`。HTTP status/CLI exit code只是這個union的映射。

【推論】`OperationRef` 固定 `operation_id/command_id/subject_ref/accepted_event_cursor`；`OperationReceipt` 固定 `operation_ref/status=ACCEPTED|RUNNING|TERMINAL/terminal_result_ref?/last_event_cursor/updated_at`，每一欄都由 event prefix pure fold 得出。

【推論】public read只有event envelopes、GraphBundle與public schemas；系統狀況、流程token、後端額度、約束狀態都由consumer fold events，不開第二份domain query API。

## Plan Exit Gate

- 【推論】public command/result unions封閉；client不能代寫任何owner truth。
- 【推論】same key/same bytes重送同result，same key/different bytes conflict，所有commands先ACL再handler。
- 【推論】long-running ACCEPTED 必帶 `OperationRef`；`get_operation`／filtered subscribe只fold event prefix，沒有ticket truth table或domain query。
- 【推論】CLI/Python/HTTP/MCP對同command canonical result/event refs一致，舊MCP operation都有typed mapping或typed disposition。
- 【推論】public reads只有event tail與digest-only specs；沒有Work/Resource/Constraint domain query route。
- 【推論】SSE reconnect/gap/backpressure不碰state owner transaction，transport heartbeat不冒充domain heartbeat。
- 【推論】import graph使interfaces只依ApplicationBoundary，concrete infrastructure只在composition roots。
