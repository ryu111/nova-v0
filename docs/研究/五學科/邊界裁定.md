# 五學科邊界裁定（workflow 產出，2026-08-26）

# 五層堆疊的邊界裁定

> 全篇的裁定都由三條判準生成，不逐條重新論證：
>
> **判準一（生命週期歸屬）**：一個子系統屬於「它所保護的不變式所跨越的**最小生命週期物件**」那一層。終態的作用域是一次執行、收斂的作用域是一串執行、effect-once 的作用域是跨程序跨崩潰的工作集。
> **判準二（單一寫入者）**：同一份持久狀態只能有一層擁有寫入權，其餘層只能讀或提出請求。兩份日誌之間沒有全序，崩潰後必然分裂。
> **判準三（花費點就近）**：攔截必須發生在花費點上，額度必須發生在看得到全部並發者的地方；兩者只能靠「預留憑證」串起來，不能靠同一個模組。
>
> 另有一條否定判準：**沒有自己生命週期物件的東西不是層**。它是橫切設施，或是某層的內圈。

---

## 一、重疊：逐條裁定

### 裁-1　持久日誌（H／L／G／A／M 五層都認領）

**裁定：兩份日誌、一個全序錨點。** 高頻的執行內事件（每次模型呼叫、每次工具呼叫、每次壓縮）留在 H 的 run-local journal；低頻的狀態轉移與外部副作用留在 G 的 journal。但 **H 不得自行宣告終態的持久性**——H 的終態那一筆必須以「錨點（最後 seq＋最後 hash）」的形式寫進 G 的 journal 才算落地。L 的代際帳與 M 的軌跡帳一律降級為**衍生索引**，不得是第三、第四份真相來源。

**理由**：合併成一份，G 的日誌會被 token 級事件淹沒，重播與掃描成本失控；完全分開，則會出現「H 說已收束、G 說仍 running」的分裂，而崩潰恢復的不變式只能在單一權威上證明。錨點是唯一能同時滿足兩者的形狀：兩份各自 append-only，但**跨份的因果只有一個方向**（H → G），沒有環。

**反轉條件**：若部署形態是「每個 run 一台一次性機器、run 之間不共享任何狀態」，G 的 journal 退化成 H 的日誌的聚合視圖，錨點寫入變成純網路往返成本，這時應合併成一份並由 H 擁有。

---

### 裁-2　終態列舉（H／L／G／M）

**裁定：三個不同型別的終態，禁止共用列舉、禁止互相繼承。** H 的終態回答「這一次執行怎麼結束」；L 的終態回答「這個目標收斂了嗎」；G 的終態回答「這個節點是否已離開可推進集合」。M 的終止控制器**不是第四種**——它與 L 的終態裁決是同一件事，併入 L。

**理由**：`H.success` 只表示「執行者跑完且沒撞上限」，它對「目標達成」沒有意見。把兩者放進同一個列舉，等於把驗收權從執行者手上收回來之後，又原封不動交給了「執行者的殼」。這是同一個錯誤往上挪一層。

**反轉條件**：若某個部署裡「一次執行」與「一個目標」嚴格一對一（單發任務、無重試迴圈、無 keep-best），兩個列舉塌成一個，這時維持兩份是純開銷。**注意這個條件很容易誤判為真**：只要有任何一種「上限到了就再開一輪」的路徑，它就不成立。

---

### 裁-3　預算、配額、計量（五層全認領）

**裁定：額度分配權在上、攔截權在下，且「預留」與「記帳」分屬不同層。**

| 層 | 擁有什麼 | 為什麼只能是它 |
|---|---|---|
| G | 租戶／全域預算、跨 run 預留 | 只有它看得到所有並發者，雙花只能在這裡防 |
| L | 單一目標的三軸上限、開下一輪前的預留 | 只有它知道「還要不要再開一輪」 |
| H | 八維度的**呼叫前**攔截、權威帳 | 只有它站在花費點上 |
| A（H 的內圈） | per-request 分項計量 | 只有它知道 token 怎麼分區 |
| M | **不擁有任何新配額**，只擁有歸因 | 歸因是帳本加一個欄位，不是新機制 |

串起這四層的是**唯一一個跨層型別：配額憑證**（見第三節）。

**理由**：判準三。把 enforcement 放在觀測面救不了，把額度放在花費點則看不到並發。

**反轉條件**：若後端不回報權威用量（成本只有估算），L 的「金額軸」必須降級為 token 軸或直接標為失效——這時把金額上限掛在 L 是假保證，應下沉到 H 並明講「上限是估算上限」。另：若系統完全無並發，G 的預留退化為 no-op，全部歸 H。

---

### 裁-4　冪等 / effect-once（五層全認領）

**裁定：冪等鍵的「產生」屬於發出副作用的那一層；去重表只有一份且屬於 G。**

產生方各自為政是對的（A 對工具呼叫、G 對節點步驟、M 對人工決策各有自己的鍵構成），但**去重表若分層各存一份，跨層重播時每一份都會認為自己是第一次**。唯一性只能由單一交易保證，這是不可分割的。

**反轉條件**：若 G 不存在（見第七節的三層堆疊），去重表下沉到 H，代價是保證縮小為「run 內冪等」——跨 run 重播不保證，必須明講。若所有副作用都在沙箱內（沒有任何外部埠），整格可刪。

---

### 裁-5　租約（H／L／G／M）

**裁定：拆成兩種不同型別的東西。**

- **執行權租約**（誰有權推進這個工作、持有者死了怎麼辦）：**只有一份，屬 G**。L 的迴圈註冊與 H 的恢復協調器裡的租約是同一機制的別名，應消滅。
- **資源寫入租約**（同一可變資源在任一時刻只有一個寫入者）：**屬 M/共享工作區**，不是同一件事——它是 run 內、細粒度、可重入的互斥，與跨程序的存活問題無關。

**理由**：執行權租約的全部價值在於回答「持有者死了怎麼辦」，這個問題只在跨程序層有意義。寫入租約的價值在於防交錯，程序死不死無關。

**反轉條件**：若寫入者跨機器（多台機器上的執行者寫同一份共享工作區），寫入租約也需要跨程序存活偵測，兩者合併成 G 的通用資源鎖。

---

### 裁-6　信任標記與資料/控制分界（L／G／A／M）

**裁定：標籤的產生與傳播規則是橫切設施（L0），不屬任何一層；但「用標籤做裁決」的閘各層各有一個，暫不合併。**

標籤本身是一個型別加一條格：`propagate(inputs) = min(labels)`，純函式、抽走任何層仍成立 → L0。閘則各層裁決點不同：A 在每次工具呼叫、G 在每個節點的能力授予、M 在每則跨主體訊息、L 在輪邊界（判準輸出不得進裁定分支）。

**但這裡留一個待驗命題**：若能證明所有裁決點最終都歸約成「一次工具呼叫」（G 的節點、M 的訊息最後都落地成某個工具被呼叫），四個閘可以塌成一個。我傾向這是真的，但它需要一條會 fail 的測試來背書（造一條「節點層放行、工具層拒絕」的路徑，斷言結果與「節點層拒絕」等價），在那條測試綠之前不得合併。

**反轉條件**：上述命題被證偽——存在一種有後果的動作不經過工具呼叫（例如節點本身就是一次資料庫寫入），那時 G 的閘不可省。

---

### 裁-7　副作用閘 vs 動作閘（H／A／G）

**裁定：歸 H。A 只保留輸入面（能力互斥檢查、工具視圖），不保留輸出面。**

**理由**：閘必須在執行者碰不到的地方。A 的定義位置是「組 prompt、算 token 的那一側」——若閘也在 A，「攝入不可信內容後收窄動作集」與「決定送什麼進去」同屬一個模組，一次錯誤同時破壞兩者。H 的閘在沙箱邊界上，是唯一對「執行者自己 shell 出去做的事」也生效的位置。A 的閘只能攔它自己知道的工具呼叫，攔不到執行者繞過去的那條路。

**反轉條件**：若執行者是黑箱託管 runtime（工具在對方那邊執行），H 拿不到工具呼叫點，閘只能退回 A 的宣告面。此時保證強度從「強制」降級為「宣告」，**必須在能力宣告裡明講**，不得靜默降級。

---

### 裁-8　版本與相容閘（H／L／G／A）

**裁定：一個指紋函式（L0）、三個消費者。A 的續跑相容閘應消滅。**

指紋（模型 id、prompt hash、工具 schema hash、程式碼版本、記錄 schema 版本）是純函式 → L0。「拒絕續跑」的決定權屬於**恢復的發起者**：G 對圖版本、L 對目標契約 hash、H 對 run record schema 與工具 schema。A 的續跑閘所斷言的東西是 H 的子集，重複一份只會出現兩層各自的容忍清單不一致。

**反轉條件**：若 A 的 session 可以獨立於 H 的 run 存在（後端持有 session、H 只是短命客戶端），A 就有了自己要保護的續跑邊界，這時它需要自己的閘。這與第四節的裁定反轉條件是同一個。

---

### 裁-9　隔離工作區（H／L）

**裁定：兩個都留，不同不變式，L 是 H 的呼叫端。**

H 的供備器保證**資源與可見性邊界**（記憶體上限、掛載過濾、網路）；L 的配發器保證**基線一致性**（逐位元等於基線、可算出四類變更集）。把後者塞進前者會讓 H 依賴版本控制概念，破壞「H 對執行者做什麼沒有意見」這條分層原則。

**反轉條件**：若目標領域沒有版本控制式工作區（例如目標是「呼叫一組 API 直到某指標達標」），L 的配發器退化成「狀態快照與回滾」，那時它與 G 的 checkpoint 很可能是同一件事，應合併到 G。

---

### 裁-10　失敗分類與重試（H／L／G／A）

**裁定：分類法一份（L0）；處置權分層，且禁止跨層重試相乘。**

- A：只准對**尚未送達**的模型呼叫重試（429/5xx，退避＋抖動，上限 4–5）。
- H：處置一次執行的失敗（重跑 vs 交回），受冪等性旗標約束。
- G：處置一個 task 的失敗（attempt 上限＋隔離區）。
- **L 不重試**——L 的「再開一輪」是新的一代不是重試，兩者的帳語意不同（重試不記新代、新代記帳、新代進 keep-best 比較）。
- M 不擁有重試。

**理由**：若各層各自實作上限，同一個失敗會被重試 4×3×5＝60 次。這是重試風暴的標準成因，而且每一層單獨看都「有上限」。

**反轉條件**：若重試也從同一個配額憑證扣減（重試是花費，不是免費），多層重試可以並存——裁定改成「多層可重試，但共用一個重試預算 token bucket」。這其實是更好的設計，但它要求配額憑證能表達「重試軸」，成本較高。

---

### 裁-11　停滯偵測（L／M）

**裁定：進度停滯歸 L；等待環死結歸 M（或下沉為 G 的通用等待圖）。這是兩個偵測對象，不是同一格。**

L 的指紋比對抓的是「工作區不再變化」；死結抓的是「每個參與者各自都在推進，但集體零進展」。後者的工作區指紋**會持續變化**，L 的偵測器結構上抓不到。

**反轉條件**：若多寫者被裁-4/裁-5 收斂成單寫者（見裁-14），死結消失，M 這一格可刪。

---

### 裁-12　裁定與完成（L／A／M）—— 直接矛盾

**裁定：「執行判準並產生 verdict」歸 L；「把多張票合成一個 verdict」歸 M（→ 併入 L）；「證明判準還活著」歸 M（→ 併入 L）；A 的完成裁決器刪除。**

**理由**：A 自己的不變式寫著「驗收權不在執行者手上」，而它把裁決器放在與執行者同進程、同生命週期的位置——執行者崩潰時裁定也一起消失，判準檔與執行者共用同一台機器的檔案系統。這是自我矛盾。A 應保留的不是一個子系統，而是一條**介面約束**：`評估()` 的輸入型別不得含任何「執行者自述」欄位，型別上就拿不到 done 旗標。

**反轉條件**：若堆疊只做三層且 L 不在（H＋G＋A），裁決權必須落到某處——那時它落到 G 的一個「驗證節點」，**不是**落回 A。任何情況下它都不回到 A。

---

### 裁-13　遙測（L／G／A／M）

**裁定：橫切設施（L0），但 span 的父子關係由 G 擁有。M 的軌跡帳＝G 的觀測站＋一個「父契約 id」屬性，不需要第二套儲存。**

**理由**：兩套 trace 後端會把因果樹斷成兩堆互不相連的碎片，而事後用推理把責任找回來是不可靠的路徑。

**反轉條件**：若多體協作發生在單一 H run 內（子執行者形式，不映射到 G 的 run），那棵樹是 H journal 的視圖，歸 H。

---

### 裁-14　人機交接（五層全認領）

**裁定：這不是五個子系統，是同一個 `open()` 的五個呼叫端。**

- **待審儲存**：屬 G（必須比任何程序活得久，且需要持久定時器）。
- **觸發條件**：各層自己的（H 因權限裁定、L 因升級階梯耗盡、G 因圖上的人工節點、A 因高風險動作、M 因重試預算耗盡）。這是各層的政策，不共享。
- **呈現契約**：屬 H——只有它握有真實的工具名與參數，能做出 raw action 的確定性渲染。呈現內容的 hash 必須與 journal 一致，執行者產生的任何文字不得成為呈現內容的唯一來源。

**反轉條件**：無 G 時待審表下沉到 H 的耐久記錄，代價是逾時計時依賴 H 的監督者存活——監督者重啟後計時必須從**原始時間**起算而非重啟時間，這條在 H 已有測試背書，可接受。

---

### 裁-15　入場／受理閘（H／L／G）

**裁定：三個都留，因為受理的對象是三個不同型別**（一次執行契約／一個 task／一份目標）。**但拒絕原因碼必須是同一個列舉**，否則呼叫端分不出「你的請求有問題」與「我現在不收」。

**反轉條件**：無。這是罕見的「重疊但正確」。

---

### 裁-16　自我健康與回收（H／G）

**裁定：跨程序回收歸 G；監督者自我心跳歸 H；控制面降級三態歸 G。H 的「重啟後 reconcile」限縮為「只收束本監督者成員集合對應的 run，且必須先取得租約」。**

**理由與修正**：H 原本的不變式（重啟後掃描沒有終態的 run，收束成崩潰終態）**在分散式部署下是錯的**——第二台機器可能正接手著那個 run，H 會把它誤判成崩潰。這是一個實質修正，不只是歸屬問題。詳見第六節矛盾（乙）。

## 二、孤兒：五層都沒認領但顯然需要

**孤-1　時鐘與 deadline 傳播。** 五份都用 `now()`、ttl、逾時、可控時鐘，沒有一層擁有「時間」。需要的東西具體是：單調時鐘（租約比較不能用牆鐘）、重播期間的受控時間 API、以及 **deadline 沿委派鏈單調收窄**（子呼叫的逾時不得長於父的剩餘）。沒有這一格，每一層的逾時都是獨立的相對值，巢狀之後外層等內層等到超過自己的上限。**這是最該優先補的孤兒**，因為它是純函式、成本極低、且四個層的租約與逾時測試全部依賴它才可控。

**孤-2　隱藏判準的回饋降級器。** 判準的**內容**不得洩漏（否則候選能改考卷），判準的**輸出**必須回饋（否則迴圈沒有梯度）——但失敗訊息通常逐字包含期望值。五份拆解都同時主張這兩件事，沒有一份處理它們的交集。需要的是：把期望值 token 從輸出中遮蔽的過濾器，或只回饋「哪一格紅了」的識別子，並接受梯度變弱；要完整 diff 則必須在目標檔把該格標記為「非隱藏」。詳見第六節矛盾（丙）。

**孤-3　供應端速率的全域協調。** 五層都管「自己的錢」的上限，沒有一層管「對方的容量」。多個並發 run 各自對 429 退避會產生同步重試潮。需要一個跨 run 的速率仲裁（誰先送、誰讓路），歸屬上應在 G，但它現在沒有這一格。

**孤-4　跨層刪除。** 一個主體的資料同時存在於 H 的成品庫、G 的載荷保管庫、A 的長期記憶、M/G 的軌跡帳。刪除必須是跨層交易且要留下可查的回執，而**帳與終態必須在刪除後仍可讀**（刪除不該讓帳消失）。目前每層各自有 tombstone/shred，沒有協調者。

**孤-5　判準的來源與演化。** 五層都假設「判準是給定的」。誰產生判準？判準本身版本化了嗎？改了判準之後舊的代際帳還可比嗎？「出題」這整個角色在五份拆解裡不存在。這是**最大的結構性孤兒**——沒有它，整個堆疊只能收斂到別人給的靶子，靶子的品質不受任何機制保護。

**孤-6　邊際效益停止。** 終止條件只有「上限到了」與「收斂了」，沒有「每代改善量除以每代花費低於閾值」。這是可機械化的（帳本已有全部輸入），且是唯一能在「還沒撞上限但明顯不划算」時停下來的判準。

**孤-7　部分成功的型別。** 所有終態列舉都是全有全無。「做完 70% 且那 70% 可交付」在 H 與 G 的列舉裡沒有變體；L 的 keep-best 只部分回答了這件事（它有最佳者，但終態仍是「預算耗盡」）。呼叫端因此拿到「失敗」卻附著一個可用的成果，型別上讀不出來。

**孤-8　重現包。** 崩潰或失敗後要重現，需要模型版本、prompt、種子、工作區基線、環境、輸入指紋。各層各存一片，沒有一層負責組裝出「一個可交給人的重現包」。這是稽核與除錯的最終出口，卻沒有擁有者。

**孤-9　人的注意力預算。** 五層都能升級給人，沒有一層管「人一天能處理幾件」。升級風暴在結構上等同重試風暴，且更難察覺——因為它看起來像是系統很謹慎。

**孤-10　跨 run 的知識累積。** A 有記憶存取器，但「這次 run 的產出該不該進長期記憶、誰有權讀、provenance 怎麼繼承」沒有歸屬。它的作用域跨 run，所以不屬 H；它不是編排狀態，所以不自然屬 G。這一格在三層堆疊裡**無處可去**（見第七節）。

## 三、層間契約：具體到能寫成型別

以下型別全部 `frozen=True`。三條共通紀律：
1. **成果只掛在成功變體**（用 union of frozen dataclasses，不用 `Optional` 欄位）——非成功時取成果必須在型別檢查或執行期明確失敗，不得回傳 `None`。
2. **執行者產生的位元不得以 `str` 型別跨層傳遞**——只能是 `成品參考` 或 `資料片段`，讀它要多做一步。
3. **上層給的所有上限，下層只能收窄不得放寬**。

### 3.0　跨全層的單一貨幣：配額憑證

```python
@dataclass(frozen=True)
class 配額憑證:
    憑證id: str
    父憑證id: str | None
    軸: Mapping[軸名, Decimal]      # {'金額','輸入token','輸出token','牆鐘秒','輪數','重試次數'}
    發放層: Literal['G', 'L']
    到期: 單調時刻
    # 不變式一：子憑證各軸 ≤ 父憑證當下剩餘（單調收窄）
    # 不變式二：結算沿鏈回沖至根
    # 不變式三：未結算的憑證到期即釋放（防持有者死亡造成永久預留）
    # 不變式四：超支界 = 單次最大花費 × 並發數，此值必須在契約中出現，
    #           不得被當成 bug（見矛盾丁）
```

這是**唯一一個貫穿三層的型別**。它的存在讓「上層配、下層擋」可執行，而不必讓下層知道上層的預算結構。

### 3.1　G → L

```python
@dataclass(frozen=True)
class 迴圈委派單:
    節點id: str
    run_id: str                      # G 產生，L 不得自行產生
    目標契約: bytes                  # 不透明；L 自己 parse，G 只轉交與存證
    目標契約雜湊: str
    基線: 內容位址                   # 工作區起點
    配額: 配額憑證                   # 已預留，非 L 自宣告
    截止時刻: 單調時刻               # 絕對值；L 只能收窄
    冪等鍵前綴: str                  # L 的所有副作用鍵必須以此為前綴
    輸入信任: TrustLabel             # 沿邊傳播進來的最低信任
    可用能力: frozenset[能力]        # G 授出的上限，L 只能收窄
    交接通道: 待審控制碼             # L 要人時往這裡開票，不自建待審表
    續跑點: 錨點 | None              # 非 None 時 L 必須從此續，不得重跑
```

```python
# L → G 的回傳：sum type，成果只在收斂變體
迴圈結局 = (
    收斂      { 成果: 成品參考, 帳: 用量, 錨點: 錨點 }
  | 預算耗盡  { 軸: 軸名, 最佳: 成品參考 | 無, 帳, 錨點 }
  | 停滯      { 已用階梯: tuple[str,...], 最佳: 成品參考 | 無, 帳, 錨點 }
  | 竄改      { 觸碰路徑: frozenset[Path], 帳, 錨點 }
  | 驗證器可疑 { 誘餌id: str, 作廢的綠燈: tuple[str,...], 帳, 錨點 }
  | 待人裁決  { 待審id: tuple[str,...], 帳, 錨點 }
  | 操作員中止 { 帳, 錨點 }
  | 不可恢復  { 診斷: 成品參考, 帳, 錨點 }
)
# 共同欄位只有 帳 與 錨點——它們在每個變體裡都必須有值，且都不是 None。
```

**契約要點**：`最佳` 用 `無` 這個顯式的單例而不是 `None`，讓「沒有最佳者」與「忘了填」在型別上可分。`錨點` 是強制的，因為 G 的重播必須從這裡接上。

### 3.2　L → H

```python
@dataclass(frozen=True)
class 嘗試委託:

```

```python
@dataclass(frozen=True)
class 指示信封:
    """資料/控制分界的型別化。這是整份契約裡最重要的一格。"""
    控制文字: str                       # 只有 L 能寫；來源必為目標契約或升級階梯

    目標指紋: str                       # 8 碼；每次請求都必須在場，含壓縮之後那次

    def __post_init__(self):
        # 型別層的拒絕：裸 str 不得進資料區
        for 片 in self.資料區:
            if not isinstance(片, 資料片段):
                raise TypeError('未標記來源的內容不得進入資料區')
```

```python
@dataclass(frozen=True)
class 嘗試結局:
    嘗試id: str
    終態: 執行終態                    # H 的封閉列舉，與 L 的列舉不同名不同值
    變更集: frozenset[Path]           # 已提交＋暫存＋未提交＋未追蹤，四類齊全
    帳: 用量                          # 主迴圈用量與全樹用量分開兩欄
    錨點: 錨點
    自述: 成品參考                    # 存檔用；型別上不是 str，裁定函式拿不到
    能力缺口: frozenset[str]          # 後端宣告的不支援項（續跑/中斷/權威成本）
```

**契約要點**：`自述` 的型別是 `成品參考` 而非 `str`。這一個型別選擇讓「把自述串進裁定分支」需要顯式地多寫一行取出，而那一行會在 code review 與 import 掃描裡現形。

### 3.3　H → 執行者（單體行為的邊界）

```python
class 執行者側世界(Protocol):

```

## 四、agentic 是不是一層

**裁定：拆成兩個東西，都不是層。**

**(a) 一半是橫切設施（L0）**：信任標籤與傳播、資料/控制分界、指紋、失敗分類法、遙測語彙、冪等鍵構成。這些在 H、L、G、M 都以完全相同的形狀出現。若把它們裝進「A 這一層」，其他四層要用就得依賴 A——依賴方向是反的。

**(b) 另一半是 H 的內圈，不是與 H 平級的層**：請求組裝器、窗口治理器、重錨定注入器、工具註冊表與檢索、JIT 取用、輸出契約驗證器、存活性驗證器。

**理由（用否定判準）**：層的資格是「擁有一個下層無法表達的生命週期物件」。H 擁有 run，L 擁有代際序列，G 擁有跨 run 的持久工作集。A 的所有狀態——對話歷史、壓縮次數、工具視圖、分項計量——**生死與 run 完全一致**。兩個作用域相同的東西不構成兩層，構成一層的內外圈。準確的說法是：**H 是執行者外面那層殼，A 是殼裡面那條路徑**；它們共用同一個 run id、同一份帳、同一個終態。

**第二個理由（自我矛盾）**：A 的最小核心裡有四項在別層已有更強版本（完成裁決器→L、預算閘→H、動作閘→H、執行 journal→G/H），而它列出完成裁決器的理由正是「驗收權不在執行者手上」。一個把裁決器放進自己進程的層，正在違反它自己宣稱的存在理由。這不是可以調和的重疊，這是資格問題。

**第三個理由（它自己的測試在說話）**：A 的核心不變式測試全部是「在請求出口攔截 payload」。「請求出口」是一個**邊界**不是一個**層**——攔截點屬於殼，被攔截的內容屬於內圈。

**什麼情況下這個裁定會反過來**（兩個，都是形態相依，且第一個很可能已經成立）：

1. **「一次執行」與「一個 context 生命週期」脫鉤**。長駐助理形態下，同一份 context、同一份壓縮歷史、同一份長期記憶跨越多次 run 存活。這時 A 有了自己的生命週期物件（session），它就是層——而且**位置在 H 之下**，H 變成 A 的一次呼叫，堆疊變成 G → L → A → H。孤-10（跨 run 知識累積）無處可去，正是這個反轉正在逼近的訊號。

2. **執行者是黑箱託管 runtime**。工具在對方那邊執行、context 由對方管理，H 縮成一個薄客戶端，A 的內容變成唯一能施加的控制面。那時 A 是層而 H 不是。裁-7 的反轉條件與這個是同一個。

## 五、multi-agentic 是不是 graph 的特例

**裁定：編排結構上是同一件事。多出來的是三樣，其中只有一樣是結構性的。**

**同一件事的部分**（M 的這些格與 G 的同名格是同一組不變式，不該有兩份實作）：派工契約↔task、租約、重試與隔離、取消傳播、因果樹、人工節點、計量、終止判定。M 的「回合」＝G 的 run，M 的「委派契約」＝G 的 task。

**多出來的第一樣：節點是不可信的。**
後果是訊息信封、白名單凍結、委派鏈單調收窄、寫入面不相交檢查、誘餌活性。這是**信任模型**的差異，不是拓撲的差異——把 G 的節點換成不可信執行者，G 自己就必須長出這些格。**裁定：做進 G，作為「不可信節點」這個節點種類。**

**多出來的第二樣（唯一真正結構性的）：邊是執行期產生的。**
G 的圖在發布時定死，所以能 lint（懸空邊、非終態 sink、無預算的無界迴圈）。M 的派工是執行期由某個執行者決定的，**發布時 lint 在結構上不可能執行**。這迫使兩條規則改型：懸空邊 → 每跳的委派契約編譯器（工具必須是角色能力集的子集）；無界迴圈 → 委派鏈深度上限＋配額憑證的單調收窄。**裁定：G 必須把「圖是靜態的」寫成前置條件，並提供動態邊模式，明講該模式下 lint 保證強度下降。**

**多出來的第三樣：裁定是有爭議的。**
G 的節點成功與否由回傳碼決定；M 的候選好壞由判官決定，而判官本身不可信。後果是位置交換、作者去識別、獨立性登記、聚合純函式、誘餌活性監督。**這不是編排，是裁定理論。裁定：歸 L**，因為裁定是收斂的組成部分，而收斂是 L 的生命週期物件。

**結論**：`M = G(不可信節點 profile) + G(動態邊模式) + L(合議與活性擴充)`。M 不需要是獨立的一層——它沒有自己的生命週期物件，也（如第三節所示）**沒有新增任何回傳型別**。

**什麼情況下這個裁定會反過來**：若出現「沒有共享目標、只有協商」的形態——市場、拍賣、對抗博弈、多方各有各的效用函式。那時不存在單一 run，也不存在單一外部判準；G 的「一個 run 一棵有根樹」模型直接崩掉（會出現多根或有環），M 需要自己的協定層（出價、承諾、爭議解決、不可否認）。

判準說得更緊一點：**只要所有參與者服務於同一個外部判準，M 就是 G 的 profile；一旦效用函式分歧，它就是新的層。** 這條界線是可檢查的——問「有沒有一個所有參與者都不能寫、且能宣告全體成敗的判準」，有就是 profile。

## 六、矛盾：列出並裁定

**甲　活性偵測有沒有殺權。**
H 明講：巡檢只標記、不得終止，「活性偵測不該有殺權」，負控是「把處置從標記改成終止就轉紅」。G 明講：租約過期必被回收，狀態回 ready、attempt 加一、另一個工作者能接手。
**裁定：不是同一件事，但必須分名，否則實作時必撞。** H 說的是「不得殺程序」，G 說的是「得奪執行權」。可並存的唯一形狀是：G 奪租約後，舊持有者的 ack 因 epoch 不符被拒，它的程序由 H 的牆鐘上限自然收場。**若把 G 的回收實作成「順便殺掉舊工作者的程序」，就與 H 直接衝突**，且會殺掉正在正常運作只是比較慢的工作。裁定：**回收只改狀態不殺程序；殺程序只能由上限強制器（牆鐘/記憶體）觸發。**
*反轉*：若資源極度稀缺、慢工作者的成本高於誤殺成本，可加一條「回收後寬限 N 秒再強制終止」，但那是上限強制器的一個新維度，不是巡檢長出殺權。

**乙　崩潰能不能被可靠偵測。**
H 的核心不變式：監督者被 SIGKILL 重啟後，reconcile 掃描沒有終態的 run，收束成崩潰終態。G 明講：非同步環境下無法可靠偵測崩潰，存活偵測必須用保守近似（租約到期）。
**裁定：H 的不變式只在「單一監督者、同一台機器」這個特權位置成立**——它能看到自己的成員集合、能確認程序真的不在。**搬到有第二台機器接手的部署就是錯的**：reconcile 會把正在別台跑的 run 誤判為崩潰。**修正**：H 的 reconcile 限縮為「只收束本監督者成員集合識別對應的 run，且必須先取得該 run 的租約」。這是實質修正，不只是歸屬調整，且需要一條新測試（造一個「別的持有者租約仍有效」的情境，斷言 reconcile 不收束它）。
*反轉*：若部署永遠是單監督者且租約層不存在，原始不變式成立且更強，不必加租約條件。

**丙　判準的輸出能不能進 prompt。**
L 的回饋淨化器要把判準原始輸出包成資料信封餵給下一輪（否則迴圈沒有梯度）；L 的持有權守衛要求 `redact_for_prompt` 保證判準指令與期望值不出現在送給執行者的文字裡；A 的完成裁決器不變式二更強：判準內容不出現在任何 payload 或執行者可讀的檔案中，用高熵哨兵掃描斷言零命中。
**這是真矛盾**：失敗訊息通常逐字包含期望值（assert 的 repr 就是期望值）。三份拆解沒有一份處理這個交集。
**裁定：新增「隱藏判準回饋降級器」（見孤-2）。** 判準輸出必須先過洩漏過濾器（遮蔽期望值 token，或只回饋「哪一格紅了」的識別子），接受梯度變弱；要完整 diff 的格，必須在目標檔顯式標記為「非隱藏」，並在竄改稽核裡把該格的相依檔案移出保護清單——**代價要在目標檔上可見，不能靜默發生**。
*反轉*：若判準的期望值本身沒有洩漏價值（例如判準是「這支程式在這組輸入下不得 crash」，沒有可抄的答案），隱藏就是純成本，該格應預設為非隱藏。

**丁　硬上限與並發不可兼得？**
M 明講：全域硬上限若持鎖到成本落盤，並發回合會被序列化，要並發就得接受軟配額，二選一。H 的帳本則主張預留憑證能同時做到防雙花與並發，總支出 ≤ 上限 + 一次跨越量。
**裁定：採 H。M 把「硬上限」誤解成「精確上限」。** 預留不需要持鎖到落盤，只需要原子扣減；「一次跨越量」就是軟配額的界，而且是可計算的：**超支界 ＝ 單次最大花費 × 並發數**。這個界必須寫進配額憑證的契約（見 3.0 不變式四），當成規格而不是 bug。
*反轉*：若單次最大花費不可預估（後端不回報上限、也無法從上限組推出），超支界不可計算，這時只能退回 M 的二選一。

**戊　重試在哪一層。**
A：4–5 次退避重試、3–5 次失敗熔斷。G：attempt 上限 K=3 後進隔離區。H：冪等才重跑、非冪等一次交回。三者各自都「有上限」，疊起來是 60 次。
**裁定（同裁-10）：A 的重試只准對尚未送達的請求生效。** 這要求 A 的例外路由器新增一格它現在沒有的區分：「已送達但回應失敗」vs「未送達」。前者的重試權上交 H 的冪等閘。
*反轉*：若重試也從配額憑證的「重試軸」扣減，多層重試可並存且不會相乘（因為總量有界）。這是更好的設計，成本是憑證要多一個軸。

**己　誰擁有 exit code。**
H、L、G、M 各有一個封閉列舉，且不只一份宣稱「與 exit code 一一對應」。多層往同一個 exit code 空間映射必撞。
**裁定：只有最外層（面對人的那一層）擁有 exit code 映射權。** 內層終態只映射到內層型別，跨層轉換必須是顯式的、可測的函式，且允許多對一（內層的多個終態映射到同一個外層 exit code 是可以的，反過來不行）。

**庚　先 commit 還是先稽核。**
L 主張「先 commit 後驗證」以防判準副作用混入候選；M 的權限格主張「產出混合 diff 的候選應被拒收」。若先 commit 才稽核，竄改已經進入歷史。
**裁定：不矛盾，但兩份都說得不夠精確。** commit 的對象是**隔離工作區內的分支**，目的是快照不是採納；稽核發生在合併之前。「先 commit」保證的是「判準跑的時候工作區狀態被釘住」，不是「候選已被接受」。這一點必須寫進契約，否則實作者會把 commit 讀成採納。

**辛　靜態 lint 的保證強度。**
G 宣稱兩條 lint 規則「擋掉最貴的一類只在稀有路徑發作的錯誤」，成本只有幾十行。M 的委派是執行期產生的邊。
**裁定：G 的保證在動態邊形態下不成立，必須寫成前置條件。** 這不是小事——「幾十行擋掉最貴的錯誤」是一個很有說服力的主張，若它在實際形態下失效而沒人明講，讀的人會以為那類錯誤已被擋住。（見第五節「多出來的第二樣」。）

**壬　遙測要不要捕捉內容。**
A：預設關閉、opt-in、遮蔽，並用哨兵字串斷言零命中。M：把輸入輸出訊息直接當 span 屬性帶，以支撐失敗歸因。
**裁定：採 A。** M 的歸因需求由 payload 指標（保管庫 ref）滿足，不需要內文進 span——ref 一樣能重建因果樹，而且順帶讓孤-4（跨層刪除）可行：刪除只要 shred payload，span 樹保持完整。

## 七、最小可行堆疊：只做三層

**裁定：H（執行器）＋ L（迴圈）＋ G（圖）。A 溶進 H 的內圈，M 溶進 G 與 L。**

**理由一（層的資格）**：這三層各自擁有一個下層無法表達的生命週期物件——run、代際序列、跨 run 持久工作集。A 與 M 沒有（第四、五節已證），所以它們不是被「砍掉」，是本來就不該佔名額。

**理由二（核心不變式互為輸入）**：H 的終態是 L 的輸入型別，L 的帳是 G 的計費對象，G 的持久狀態是 H 崩潰後的唯一憑據。抽掉任一層，另兩層的核心不變式都退化成「只在同一個程序活著時成立」——而那正是這五門學科共同要消滅的東西。

**理由三（正面拒絕「L 是 G 的一個環」）**：把迴圈做成圖上的環很誘人，但不行。G 的節點成功由回傳碼決定，L 的一代成功由外部判準＋竄改稽核＋keep-best 決定，後者需要「每輪從基線重建工作區並算出四類變更集」這個 G 沒有的概念。硬做的話，L 的三個核心會變成三個特殊節點，而它們之間最重要的不變式（可寫集合與判準相依集合不相交）**在圖的型別上無法表達**——圖表達的是節點之間的順序，不是節點內部的權限拓撲。

### 建置順序（不是同時做完時）

**H → L → G。**
沒有 H，L 的每一輪都無界；沒有 L，H 只是一次性工具，沒有收斂；沒有 G，前兩者在單機單程序下仍成立。所以 **G 最可延後——但延後的代價必須明講：接受「機器重開＝進度歸零」與「副作用可能重複」。** 這兩件事不會自己好，也不會在測試裡現形（單機測試永遠綠），只會在生產第一次崩潰時一次還清。

### L0 不佔層的名額

橫切設施（時鐘與 deadline 傳播、信任標籤、指紋、失敗分類法、遙測語彙、配額憑證）**必須先於三層存在**，否則三層各自長一份、各自的容忍清單不一致。但它不是一層——它沒有生命週期物件，它是一個 library。把它算成「第四層」是名額的浪費，把它延後則是三層都要重做的代價。

**什麼情況下這個裁定會反過來**（三個，按可能性排序）：

1. **負載形態從「少量長任務、單租戶」變成「大量短任務、高並發、多租戶」**。短任務不需要收斂迴圈，L 可延後；G 變成第一優先。三層變成 **G ＋ H ＋ L0**，L 退化成「重試三次」。**最小堆疊是負載形態的函式，不是普遍真理**——這是本節最重要的但書。

2. **context 生命週期脫離 run**（長駐助理形態）。A 取得層資格，堆疊變成 G → L → A → H，被擠掉的是 G 或 L 其中之一。孤-10 無處可去正是這個轉變的早期訊號。

3. **執行者變成黑箱託管 runtime**。H 縮成薄客戶端，能施加的保證從「強制」降為「宣告」，A 變成唯一控制面。這時三層是 G ＋ L ＋ A，而 H 這一格的保證強度必須全面重寫——不是搬移，是降級。
