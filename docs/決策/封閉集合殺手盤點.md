# 封閉集合成員的殺手盤點

**這份是「已裁定」的結構化紀錄，不是掃描器輸出。**
sol 在 R16 裁定 discovery 與 authority 必須分開：

- **廣召回掃描器只負責找候選，永遠不裁真假。** 它的殺手判定靠散文比對，一定會誤報
  （`POLICY_STOP` 就是現成的例子——08:684 有真殺手，掃描器沒認出來）。
- **候選分批人工確認，每批最多六個，按同一個集合宣告切**，不按檔案數硬湊。
- **hard gate 只讀這份已裁定的資料**，不讀掃描器輸出。
- 清到零後移除 debt baseline，改成絕對不變式；散文掃描器永遠退回 audit-only。

判定值三選一：

| 值 | 意思 |
|---|---|
| `FALSE_POSITIVE` | 掃描器誤報，成員有真殺手（附 locator） |
| `MISSING` | 確認沒有命名殺手，要補 |
| `DECLARATION` | 刻意 record-only／不可准入，機械權力已明文剝奪（附裁定出處） |

**候選總數 42**（22 份計畫，全集來源＝fenced `NAME = "NAME"` 加散文宣告行）。
本檔只收已裁定的；未列出的仍是未裁定候選。

### `SEEDED_OUTPUT_REPEATABILITY_OBSERVED`：五格全在升級路徑，授予側零殺手

01B 那五格固定負控（01B:229–241）我逐條讀過，**全部守的是「不得升級成
`OUTPUT_DETERMINISM`」**：

- `probe-upgraded-to-determinism`、`nth-plus-one-differs`、`forged-mechanistic-ref`、
  `wrong-claim-ref`、`contract-claim-cannot-bind-mechanical`

**沒有一格守「後端沒做合規的 N 次 probe 卻拿到 `SEEDED_OUTPUT_REPEATABILITY_OBSERVED`」。**
授予側目前只有防恆真格（01B:246「帶合規 N 次 probe 的後端取得 supported」）——
那是正控，證明拒絕不是無條件，**不是殺手**。

`nth-plus-one-differs` 看起來最接近，但那個後端**確實做了 probe**（前 N 次逐 byte 相同），
它的 evidence 記為 repeatability 是正確的；那一格測的是下游別把它當 determinism。

**我不確定的部分明講**：授予條件是否屬於 01B 的保證範圍，還是留給消費端，
這要規格作者裁。我只確認「沒有殺手」這個事實。

### `CATALOG_DIGEST_MISMATCH`：同一封閉集合的兄弟碼有斷言，它沒有

01:1028 宣告失敗碼封閉為 `UNADMITTED_PRIMITIVE_CATALOG`、`CATALOG_DIGEST_MISMATCH`、……
其中 `UNADMITTED_PRIMITIVE_CATALOG` 在 1098 有斷言，`CATALOG_DIGEST_MISMATCH`
全份**只出現在 1028 那一行宣告**。

**這是「宣告做一半」的第三個實例**，前兩個是 `建規格目錄.py` 宣告 `--check` 卻消費
未宣告的 `--write`、`驗全系統.py` 宣告 `--quick`／`--release` 卻消費未宣告的
`--self-test-failure-propagation`（R15-04）。同一支工具、同一個封閉集合、
**宣告了一部分就停手**。
