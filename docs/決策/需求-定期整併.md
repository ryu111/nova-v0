# 需求：定期整併（simplify ＋ review）

> 我的立場：**該做**。它補的是這個架構目前唯一沒有對手的力量——**累積**。
> 但它有一個核心難題必須先解，否則它會變成最典型的「度量在量錯東西」。

## 一、為什麼需要它

這個系統的每一個機制都是**單調增加**的：

- 約束會累積（每次事故加一條，沒人敢刪）
- 保證會累積（而其中一部分會退化成恆真格）
- 狀態機的節點與邊會累積
- 適配器與能力宣告會累積
- 知識會累積（有 TTL，但續期比撤銷容易）

**沒有一個機制的預設方向是「減少」。** 而一個只會加的系統，
最終會到達「沒有人敢動任何東西，因為不知道哪條還有意義」的狀態。

定期整併就是那個反向力量。

## 二、核心難題：`simplify` 沒有 verifier

「更簡單」不是可機械判定的性質。而一旦用度量去定義它，就會得到度量最佳化——
這個專案有**五次**「度量在量錯東西」的實例，每一次都是機制看起來在運作、實際在量別的東西。

所以**不能**這樣做：

- ❌ 「行數減少 X%」——會得到把三行擠成一行
- ❌ 「圈複雜度下降」——會得到把分支藏進查表
- ❌ 「重複度下降」——會得到過早抽象，那比重複更難改
- ❌ 「由 LLM 判斷是否更簡單」——judge 有位置偏差、冗長偏差與自我偏好，
  而且它在評自己的產出

## 三、解法：把「簡化」變成一種**工作型別**，走同一套流程

關鍵是把兩件事分開：

| | 角色 | 是否可機械判定 |
|---|---|---|
| **「更簡單」** | **目標方向** | 否——由人或判官給方向，不是驗收判準 |
| **「保證沒有變弱」** | **不變式** | **是**——這是可以硬驗的 |

於是驗收判準變成：

> **簡化後，保證集合不得縮減，且每一條保證的固定反例仍然殺得掉。**

這句話可以完全機械化：
- 保證集合的 digest 前後比對（只准不變或**嚴格增加**）
- 每條保證的正控仍綠、**固定反例仍紅**
- 逃生路徑（guard 的例外出口）使用次數**不得增加**

「更簡單」則是**目標敘述**——它由提案者主張、由人或判官判斷值不值得，
但**它不是收斂判準**。收斂判準是上面那條不變式。

**這正好是這個架構已經有的形狀**：目標由外部給、判準在執行者碰不到的地方、
候選只能提交。簡化不需要新機制，它是既有機制的一個**工作型別**。

**負控**：讓一個簡化候選在「某條保證的反例不再被殺」的情況下仍能收斂，
該格必須轉紅。

## 四、什麼時候觸發：訊號，不是時間也不是計數

「跑幾個任務之後跑一次」是**任意的**，而且會被 Goodhart。

正確的是**可量測的結構訊號**，而且每個門檻**必須版本化**——
否則「客觀」只是把作者的偏好藏在常數裡。

候選訊號（每一條都要能機械算出來）：

| 訊號 | 它在說什麼 | 為什麼它不容易被玩 |
|---|---|---|
| **新增程式碼量 ÷ 新增保證數** | 加了很多碼但沒加保證 | 分母是保證，而保證要有反例才進得來 |
| **同一條保證的反例被修改的次數** | 那條保證不穩定，可能一開始就寫錯了 | 修改次數是歷史事實，改不掉 |
| **一個檔案被幾個不同權威的變更觸及** | 職責滲漏 | 權威歸屬是宣告的，不是猜的 |
| **guard 逃生路徑的使用次數** | 宣告式狀態機正在退化成「宣告 ＋ 一堆例外」 | 每次使用都要落盤且要有理由 |
| **規格與實作 digest 對不上的次數** | 兩者正在漂移 | digest 是機械算的 |
| **告知型約束佔用的上下文比例** | 疤痕組織正在擠掉真正的內容 | 可直接量 token |

**這些是「該看一下」的訊號，不是「必須簡化」的判準。**
它們的產出是**提案**，不是動作。

## 五、`code-review` 是判官，所以只能提案

判官有已知偏差（位置、冗長、自我偏好），而且在這裡它常常在評**自己這一族**的產出。

所以：

- review 的產出是**帶證據的提案**，不是裁決
- 提案進入一般工作流程，被同一套判準裁定
- **review 本身不得改變任何保證的狀態**

**負控**：讓 review 的輸出可以直接改變保證狀態，該格必須轉紅。

## 六、規模由誰決定

使用者提到「多少內容還要再評估」。我的主張是**不要現在訂一個數字**，
因為現在沒有資料可以訂。

正確的形狀是：
1. 先把**訊號**做出來並開始記錄（成本很低，都是既有資料的函式）
2. 累積幾輪之後，看哪些訊號**真的先於問題出現**
3. 只有被驗證有預測力的訊號，才配得上一個門檻

**在那之前，整併由人在階段邊界手動觸發。** 這不是逃避——
是拒絕在沒有資料時把偏好寫成常數。

## 七、出口條件

1. `簡化候選不得縮減保證集合` —— 負控：讓它刪掉一條保證仍能收斂
2. `簡化後每條保證的固定反例仍被殺` —— 負控：讓一個反例存活仍算通過
3. `逃生路徑使用次數不得增加` —— 負控：拿掉這道檢查
4. `review 輸出不得改變保證狀態` —— 負控：給它寫入權
5. `每個觸發門檻都有版本與理由` —— 負控：塞一個沒有理由的常數
