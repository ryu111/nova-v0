# 架構草案：兩份獨立推導的收斂與分歧

> 兩個獨立來源：一個帶著四輪脈絡並做了自我污染審計，一個完全沒有前情、
> 且在讀任何既有結論之前先固定了自己的資格判準。
> 本文只記**兩邊都成立的**、**分歧且可裁決的**、以及**還沒有人回答的**。

## 一、獨立收斂的部分（兩邊都到）

1. **「有自己的生命週期」不足以成為一層。** 否則每張有 status 欄的表都能升格。
2. **執行者的形態不影響上層切分。** 換成 CLI、本地模型或純函式重播器，
   上層生命週期不該改變；一個工作有一位或多位執行者也只是協調策略。
3. **三種宣告必須分開，不得互推**：
   - 「這次執行結束了」——只有執行權威能說
   - 「產物符合凍結定義」——只有評估權威能說
   - 「結果已在外部世界可驗證地生效」——只有生效權威能說

   把任一條捷徑接成「執行者輸出 success 就直接生效」，端到端格必須轉紅。
4. **外部副作用不可能與本機記錄同一交易。** 只能 outbox ＋ 冪等目的端 ＋
   **逐 endpoint** 明講 at-least-once 或 at-most-once。
5. **判準裁定必須是獨立信任域**，不只是邏輯上的另一層——
   同程序、可讀檔案、可回看 raw stack 都會讓邏輯分層在程序邊界上全毀。

## 二、分歧，以及分歧的來源

| | 來源 A（有脈絡） | 來源 B（無前情） |
|---|---|---|
| 形狀 | 八個權威群組構成的**圖** | **三個垂直層 ＋ 三個橫向控制面** |

**目前已識別、且足以解釋層數差異的判準是第三條；是否唯一，未查證。**
（我原本寫「唯一來源」是越權——投影後看起來一樣，不證明原始權責完全等價。） B 用四個合取條件，其中第三條 A 沒有：

> 它**透過窄且可替換的契約，調用或組合下一層的多個生命週期**；
> 只被「附帶查詢」不算。

A 只用「獨立生命週期 ＋ 單一寫入者」，於是預算保留、租約、outbox 意圖全都升格成權威，
結論自然變成「這不是堆疊」。

**採 B 的判準**，理由：它能排除層數膨脹，而 A 的結論在加上這條之後會自然收斂到 B。

### 對應關係

| A 的權威 | B 的位置 |
|---|---|
| 執行權威 | 第一層：執行封套 |
| 作業權威 | 第三層：持久工作協調 |
| 定義權威 ＋ 評估權威 | 橫向：判準裁定面——**幾何位置對，權限合併錯**（見下） |
| 資源權威 | 橫向：**資源准入與核銷面**——只有事後記帳形成不了硬上限 |
| 生效權威 | 橫向：效果交付面——要再分「誰原子寫入意圖」與「誰對外 relay」 |
| 證據庫 | 內容定址儲存 ＋ **append-only 索引**——CAS 證明位元組相同，**不證明位元組可採信** |

### 兩個真正未解的

**未解一：「目標追求」是一層，還是工作項的狀態？**

- A：不必先成層。代次、目前最佳、停止條件可先當工作項的狀態。
  **拆分判準**：同一作業能同時持有兩個獨立搜尋活動，任一活動結束都不終結作業。
- B：是層。理由是**單次執行成功不能回答目標是否成立**；
  同一次追求可替換後端、換策略、重播既有結果，而「何時算成立」的權威不變。

兩邊給的是同一類判準，所以這題可以裁決——**需要的是產品需求，不是更多論證**。

**未解二：跨工作知識歸誰。**
A 設了獨立的知識權威；B 說「維護提案是一種工作來源與工作型別」，沒有給知識明確歸屬。

## 三、B 對「層」的四條資格判準（採用）

1. 擁有穩定身分與獨立生命週期；有建立、進展、**封閉終態**，且終態不是呼叫端臨時算出來的
2. 擁有**不可下推的保證**——拿掉它，下層即使完全正確也補不回那些保證
3. 透過**窄且可替換的契約，調用或組合下一層的多個生命週期**；只被附帶查詢不算
4. 對自己的權威狀態負責：崩潰後知道從哪恢復、誰可寫、何時**永遠不再重啟**

## 四、三個垂直層的終態（兩邊都強調不可壓成 success/failed 二元）

| 層 | 物件 | 終態至少要分 |
|---|---|---|
| 執行封套 | 一次對不可信執行者的**受限呼叫** | SUCCEEDED／FAILED／TIMED_OUT／TURN_LIMIT／SPEND_LIMIT／CANCELLED／BACKEND_ERROR／**SUPERVISOR_ERROR** |
| 目標追求 | 目標＋凍結判準版本＋總預算＋零到多次執行 | SATISFIED／ATTEMPT_LIMIT／DEADLINE_EXHAUSTED／SPEND_EXHAUSTED／CANCELLED／**CRITERION_ERROR**／POLICY_STOP |
| 持久工作協調 | 跨程序、跨崩潰存在的工作 | COMPLETED／FAILED_FINAL／QUARANTINED／CANCELLED |

`SUCCEEDED` **只表示這次封套正常產出**，不表示目標被接受。
把所有非成功壓成 failed，會讓「東西做錯」與「裁判壞掉」**不可核銷也不可恢復**。

## 五、「一定會停」的正確來源

不是「看起來沒有進展」，是**外部可單調耗盡的總額度**：
每次進入執行前先**原子保留**最壞成本或一個可證明有限的配額；沒有剩餘額度就直接進封閉終態。

## 六、還沒有答案、而且不能靠論證解決的

**在裁定儲存之前必須先量的（workload envelope）**：

最大同時追求數／每次付費呼叫數／事件持久粒度／租約週期／**最長讀交易**／
outbox fan-out／允許恢復時間／是否跨主機／資料保留量／備份 RPO 與 RTO。

理由：「平均每秒寫入」是錯的指標。真正會咬人的是 **burst**——
SIGKILL 後大量租約同時過期、排程 tick 同時釋放 timer、供應商用量批次回補、
outbox 目的端恢復。要量的是 **p95／p99 交易延遲、BUSY 比率、最長讀鎖與恢復時間**。

而且純函式重播器可以讓一次執行以**毫秒**計——那正是最容易撞出鎖與交易錯誤的負載。

## 七、第二輪的修正（採用）

### 架構形狀改為：三層 ＋ **四個**橫向權威面 ＋ 內容定址基礎設施

第四個是**知識治理面**——跨工作知識不能塞回工作協調層，也不是 CAS。
它擁有知識主張的**准入、過期、撤銷與溯源**；工作只綁定**知識快照**，不擁有知識真相。

### 定義與評估必須分權（同一面，不同筆）

- **定義權威**：建立不可變的判準版本、公開條款映射、隔離需求、回饋政策、有效期與取代關係
- **評估權威**：讀凍結版本、執行觀察、寫證據與裁決；**不得更新判準版本**

> **評估者若能改定義，就可以在看過答案之後移球門。**

第一版可以部署在同一個服務裡，但**資料庫權限要分 table／command**——
否則「以後再拆程序」時已經沒有可驗證的寫入邊界。**共同部署不是共同權威。**

### 目標追求：現在就拆

產品需求（多策略平行 ＋ 換後端接手而工作不終結）已命中拆分判準。
正確基數是 **工作 1→N 追求 1→N 執行**。
第一版排程器可以把「同時平行追求數」設為 1 保留序列用法——
**那只是 rollout policy，不應反向污染資料本體。**

啟用真平行前要三道閘：獨立性 manifest 可驗證、每個追求有獨立工作區與證據範圍、
組合預算原子分配。**少任何一道，多個追求只是會互踩資料且一起超支的多個程序。**

### envelope 是三類，不是兩類（我少了一類）

1. **外部需求／SLO**——主機數、RPO／RTO、保留期、允許恢復時間
2. **架構政策上限**——併發、fan-out、事件粒度、租約、讀交易上限、單筆 payload
3. **待驗證結果**——p99 延遲、鎖爭用比率、burst 清空時間、崩潰恢復、備份還原

**所以第六節「裁定儲存之前必須先量」寫錯了。** 正確的是：
**先裁定 design envelope；再以相同 envelope 量候選，通過才定案。**
儲存選擇可以現在往前，**驗收不能免**。

### 由 envelope 推出的儲存決策（待裁定）

固定到**官方已修版本**的 SQLite、**專用 state-owner 程序**、**單一 connection**、
**rollback journal**（不是 WAL）、`synchronous=FULL`、大內容先進 CAS、
**worker 與評估者都不得直接開 DB**。

- WAL 的取捨是**拓撲推論**不是版本恐懼：單 connection 下 WAL 沒有讀寫並行的主要收益，
  卻增加 checkpoint 與 WAL／SHM 檔管理。引入 snapshot reader 或直讀池時再以同一 envelope 比較。
- 版本政策是「pin 到已修版本並把版本寫進證據」，**不是永久禁 WAL**。
- **CAS 與 DB 的寫入順序固定：blob 先、metadata 交易後。**
  前者成功後者失敗只留下可回收的孤兒；**反過來會留下已提交但永遠讀不到的 ref。**

### 編號不能當識別碼

我兩輪題目裡的「性質 7」指的是不同東西。
保證的識別碼要用**語義 id**（如 `execution.wall_limit.external`、
`knowledge.provenance.revocable`、`effect.delivery.at_least_once`），
章節編號只能是 source locator。
