
### LLM 推論的不決定性：逐 byte 相同的輸入是否保證逐 token 相同的輸出

**裁決**：兩層都查到了，地基是「缺一塊」——缺的那塊在**官方層**。官方層（Anthropic、OpenAI、IEEE 754-2019、NVIDIA cuBLAS、PyTorch、vLLM）只給了兩件事：輸入端的位元組級比對規則（prompt caching 的 exact matching／累積 hash／tools→system→messages），以及輸出端的一句免責——「Even with temperature set to 0, the results will not be fully deterministic and identical inputs may produce different outputs across API calls」。官方**沒有任何一份文件說明失效機制、失效條件、或在什麼組態下反而可以保證**；IEEE 754-2019 唯一給出的線索是把 sequence of operations 列為結果的自變數，但它不知道也不管誰在改那個順序。權威層補上的正是這一塊：不決定性的自變數是 **batch size 與規約順序**，而不是取樣隨機性；因此對本題的答案是分岔的——**在公開託管 API 上，逐 byte 相同的輸入不保證逐 token 相同的輸出，這是廠商自己聲明且有 arXiv:2408.04667（10 次重跑無任何模型能全數逐字重現）、DOI 10.1145/3697010（47.56%–75.76% 的題目沒有任何兩次輸出相同）背書的既成事實；但在自控的推論堆疊上，batch-invariant kernel 已實測做到 1000/1000 逐 token 相同（Qwen3-235B、單 GPU vLLM、temperature=0），代價約 +60% 延遲。** 所以 nova 那條「兩次跑同樣輸入要得到同樣結果與同樣 digest」在**模型輸出這一段，經由公開託管 API 時是根本不可能成立的**——不是實作沒做好，是呼叫端無權控制決定它的自變數（伺服器端的 batch 組成與後端組態）。這條宣稱必須降級成 typed 的能力查詢，不能當成無條件公理。

**權威層**：
- [Horace He（PyTorch 核心開發者）與 Thinking Machines Lab，2025-09-10] **Defeating Nondeterminism in LLM Inference（batch invariance 論點）** — https://thinkingmachines.ai/blog/defeating-nondeterminism-in-llm-inference/ ；程式碼 thinking-machines-lab/batch_invariant_ops。（非同儕審查，屬具名公認實務者論點；其結論已被 vLLM 官方 Batch Invariance 功能與下述 arXiv:2601.17768 引用採納。）
    補了：官方只說「不保證」，這篇補上**為什麼**與**要怎樣才保證**。它明確駁回流行的「concurrency + 浮點非結合律」解釋，指出前向傳播「atomic adds are not necessary for the vast majority」，真正的機制是：伺服器負載波動 → batch size 波動 → kernel 的規約順序隨 batch size 改變 → 同一筆請求拿到不同數值。因此不決定性的判準不是「kernel 有沒有隨機」，而是 **batch invariance**：「a specific element in the batch gets identical results regardless of batch size or other parallel requests」。實測：Qwen3-235B-A22B-Instruct-2507、單機 vLLM、temperature=0、同一 prompt 跑 1000 次生成 1000 token，得到 **80 種不同完成**；前 102 個 token 完全一致，**從第 103 個 token 開始分歧**（992 次「Queens, New York」對 8 次「New York City」）。換上 batch-invariant kernels 後，**1000 次全部逐 token 相同**。這是本題最直接的答案：逐 byte 相同的輸入**不保證**逐 token 相同的輸出，但在受控組態下**可以做到**。代價量測：vLLM 預設 26 秒 → 未優化決定性版 55 秒 → 改良 attention kernel 後 42 秒（約 +60% 未優化／約 +60→+62% 區間，優化後仍顯著）。
    失效：作者自己列出失效與代價邊界：① RMSNorm 在小 batch 下失去平行度，作者選擇犧牲效能保住不變性；② matmul 因無法隨 batch size 切換 tensor-core 指令，較 cuBLAS 慢約 20%；③ 最關鍵的 attention——FlashDecoding 的 split-KV 本質上要依 batch size 決定切分數，他們改用 fixed split-size，且明講「requires some internal FlexAttention changes that are not included in our code release」。也就是說**這個保證綁定在特定 kernel 實作與特定執行組態上**；換 kernel、換切分策略、換硬體，保證即失效。文中的 1000/1000 是**單 GPU 單一組態**的結果，不是跨機器、跨版本的宣稱。
- [Jiayi Yuan、Hao Li、Xinheng Ding、Wenya Xie、Yu-Jhe Li、Wentian Zhao、Kun Wan、Jing Shi、Xia Hu、Zirui Liu，2025-06-11（v1）／2025-10-24（v2）] **Understanding and Mitigating Numerical Sources of Nondeterminism in LLM Inference** — arXiv:2506.09501 ；https://arxiv.org/abs/2506.09501
    補了：把不決定性從「輸出字串不同」量化成**下游指標的漂移**。在 bfloat16 + greedy decoding（等同 temperature=0）下，僅改變 evaluation batch size、GPU 數量、GPU 型號，DeepSeek-R1-Distill-Qwen-7B 出現 **最高 9% 的 accuracy 變動**與 **9,000 個 token 的回應長度差異**。機制歸因於「the non-associative nature of floating-point arithmetic under limited numerical precision」：推理型模型早期 token 的捨入差異會**級聯**成完全不同的推理鏈。提出 LayerCast——權重存 16-bit、計算用 FP32——用數值穩定度換記憶體效率，是「提高精度以縮小分歧窗口」這條與 batch invariance 正交的路線。
    失效：明確指出失效條件是**系統組態變動**本身：batch size、GPU 數、GPU 版本任一改變即失效——這正是 nova 若把「同樣輸入」只定義成 prompt 位元組相同時會漏掉的那組自變數。LayerCast 是**緩解**不是保證：提高精度縮小每步誤差，但沒有消除規約順序這個自變數，論文未宣稱 bitwise 決定性。

    補了：從**託管 API 的呼叫端視角**做系統性量測——這正是 nova 的處境（呼叫端無法控制伺服器的 batch 組成）。5 個 LLM（GPT-3.5 Turbo、GPT-4o、Llama-3-70B-Instruct、Llama-3-8B-Instruct、Mixtral-8x7B-Instruct）、8 個任務、zero-shot 與 few-shot、各跑 10 次，全部設定成應為決定性（temperature=0、top-p=1、固定 seed）。摘要逐字：「We see accuracy variations up to 15% across naturally occurring runs with a gap of best possible performance to worst possible performance up to 70%. - [Shuyin Ouyang、Jie M. Zhang、Mark Harman、Meng Wang（King's College London／UCL／Bristol），2023-08-05 首版，2024 修訂；發表於 ACM TOSEM] **An Empirical Study of the Non-determinism of ChatGPT in Code Generation** — arXiv:2308.02828 ；DOI 10.1145/3697010

    補了：指出「輸出字串相同」是**過於粗的觀測**：即使生成文字看起來一致，底層 token 機率仍在變動。摘要逐字起手：「The execution of Large Language Models (LLMs) has been shown to produce nondeterministic results when run on Graphics Processing Units (GPUs), even when they are configured to produce deterministic results。」關鍵發現是不決定性的影響**與機率位置強相關**：token 機率落在 0.1–0.9 區間時影響顯著，趨近 0 或 1 時影響小得多。對 nova 的意義是：**「這次輸出跟上次一樣」不等於「這次執行跟上次一樣」**——貼近決策邊界的那些 token 是隨時會翻的，字串相同只是還沒翻到。

- [Raja Gond、Aditya K Kamath、Ramachandran Ramjee、Ashish Panwar，2026-01-25（v1）／2026-01-30（v2）] **LLM-42: Enabling Determinism in LLM Inference with Verified Speculation** — arXiv:2601.17768 ；https://arxiv.org/abs/2601.17768
    補了：對 batch invariance 這條路線提出**成本結構上的批評**，並給出替代設計。摘要逐字歸因：「this non-determinism arises from floating-point non-associativity combined with dynamic batching and GPU kernels whose reduction orders vary with batch size」——與 Horace He 的歸因一致。但指出把 kernel 做成 batch-invariant「tightly couples determinism to kernel design, requiring new implementations」，且「imposes fixed runtime overheads, regardless of how much of the workload actually requires determinism」。改以排程層的 verify-rollback 迴圈重放候選 token，只 commit「guaranteed to be consistent across runs」的部分，讓成本**與真正需要決定性的流量成正比**。對 nova 的直接啟示：決定性應該是**逐請求可選的等級**，不是全域開關。

- [Hadi Jooybar、Wilson W. L. Fung、Mike O'Connor、Joseph Devietti、Tor M. Aamodt（UBC／NVIDIA／Penn），ASPLOS '13，2013] **GPUDet: a deterministic GPU architecture** — DOI 10.1145/2451116.2451118（ASPLOS '13）；亦見 ACM SIGARCH Comp. Arch. News 41(1) DOI 10.1145/2490301.2451118
    補了：把 GPU 不決定性放回**體系結構**層，證明這不是 LLM 時代的新問題，也不是驅動程式 bug：要在 GPU 上取得決定性執行需要專門的硬體機制。論文指出 SIMD 硬體在 wavefront 內部本來就是決定性的（可零成本利用），真正的不決定性來自平行、亂序的記憶體寫入，他們借用既有的 Z-Buffer Unit 來把亂序寫入變成決定性輸出。這條是 nova 的「地基之下的地基」：**決定性在 GPU 上是要被額外構造出來的性質，不是預設值**。
    失效：作者提出的是需要硬體支援的架構方案，在商用 GPU 上並不存在；且決定性執行是以效能為代價換來的（該研究線的一貫結論）。本次僅取得書目與方法摘要，未取得該論文的效能減損數字（未查證）。

**nova_fit**：把「同樣輸入 → 同樣 digest」這條**單一宣稱拆成兩條獨立的宣稱，並讓不成立的那條有型別可回**，做法具體如下。

一、**輸入端 digest 照舊，且要對齊官方的比對規則。** 官方 prompt caching 的 exact matching 與累積 hash 已經證明「輸入位元組的相同性」是可判定、可雜湊的。nova 的 `request_digest` 應該覆蓋**官方階層的全部三段**：`tools`、`system`、`messages`，且順序寫死為官方的 tools→system→messages——不要自己另發明序列化順序，那會讓 nova 的 digest 與供應商的 cache 命中判斷分岔。這一段的決定性是**真的**，該保就保。

二、**輸出端不能共用同一個 digest 欄位。** 新增與 `request_digest` 平級的 `response_digest`，並且**強制**它旁邊掛一個 `determinism_class` 欄位，取值至少要有三格：
- `BITWISE_DETERMINISTIC`——只有在執行環境自報 batch-invariant 且環境 digest 完全相符時才可宣告；
- `SEMANTIC_STABLE`——輸出位元組可能不同，但經指定 extractor 抽出的結構化欄位相同（對應 arXiv:2408.04667 的 TARa 概念）；
- `NONDETERMINISTIC`——預設值，也是任何託管 API 後端的唯一合法值。
`determinism_class` 不可省略、不可預設為前兩者：依 CLAUDE.md 的 fail-closed 原則，**沒宣告就是 `NONDETERMINISTIC`**。

三、**把「執行環境」升格成 digest 的一等輸入，而不是註記。** 權威層列出的自變數全部要進一個 `execution_env` 物件並參與雜湊：`backend_id`、`engine_version`、`model_id`、`device_arch`、`device_count`、`sm_count`、`toolkit_version`、`batch_invariant`（bool）、`max_batch_size`、`dtype`、`tensor_parallel_size`，外加一格 `vendor_fingerprint`（供應商若像 OpenAI 那樣提供 system_fingerprint 就填，Anthropic 這類沒有的就明確填 null——**null 本身是資訊，代表基準漂移不可偵測**）。少任何一個欄位，`BITWISE_DETERMINISTIC` 就不得被宣告。

四、**能力不足只回 typed 拒絕，不得靜默降級。** 依 CLAUDE.md「v1 isolation」那條的同一模式，當某個 claim 要求 `BITWISE_DETERMINISTIC` 而後端做不到時，回 `UNSUPPORTED_BITWISE_DETERMINISM`（或既有 `UNSUPPORTED_*` 家族的對應碼），**不得**退回成「跑兩次比字串，剛好一樣就算過」。PyTorch 官方在這件事上的做法可以整份照抄：沒有決定性實作的運算就丟錯，而不是偷偷用非決定性的那個。

五、**ClaimSpec 閘要有一格負控專門打這件事。** 目前的風險是「假綠」：託管後端在低負載時段連跑兩次剛好逐字相同，測試就綠了，而它其實從來沒有保證。負控要能證明閘抓得到「宣告 `BITWISE_DETERMINISTIC` 但 `execution_env.batch_invariant` 為 false／null」這種組合——**這是靜態可判定的，不需要真的去跑模型，因此不會撞上「燒錢測試三擇一」那條**。同時建議把 TARr@N／TARa@N 兩個量測分開記錄成 `repeat_identical_rate_raw` 與 `repeat_identical_rate_parsed`：權威層的數字顯示這兩者可以差到 0% 對 99.6%，混成一個數字會直接毀掉判讀。

六、**決定性是逐請求的等級，不是全域開關。** arXiv:2601.17768 的成本論證直接適用：`determinism_class` 應該是 claim 可以**要求**的東西，而不是 nova 全域打開的模式，否則所有不需要 bitwise 決定性的流程都要付那 +60% 的帳。

七、**「兩次輸出一樣」不可作為決定性的證據。** arXiv:2601.06118 的結論要寫進相關欄位的 docstring：字串相同只代表這次沒翻到邊界上的 token。任何從「重跑相符」推導出「該後端具決定性」的程式路徑，都是把觀測誤當保證。

**坑**：
- 把「輸入位元組相同」等同於「執行相同」。IEEE 754-2019 逐字把 sequence of operations 列為結果的自變數，而那個順序由伺服器端的 batch 組成決定，呼叫端一個 byte 都沒改也管不到它。digest 只雜湊 prompt 等於漏掉真正的自變數。
- 誤以為 temperature=0 就是決定性。Anthropic 官方逐字否認（「even with temperature set to 0, the results will not be fully deterministic」），OpenAI 對 seed 也只承諾 best effort。DOI 10.1145/3697010 量到 47.56%–75.76% 的題目連兩次相同的輸出都沒有。這是本題最普遍、且有廠商白紙黑字打臉的誤解。
- 把不決定性歸因成「取樣隨機」或「並發加 atomics」。Horace He 明確駁回後者（「atomic adds are not necessary for the vast majority」）。歸錯因會導致修錯地方——去設 seed、去關並發，都不會讓 batch size 這個真自變數消失。
- 「重跑兩次剛好一樣」被當成決定性的證明。這是 CLAUDE.md 已寫的「換個情境跑綠不能判定假紅」的同型錯誤：低負載時段 batch size 剛好穩定，測試就綠了。arXiv:2601.06118 更進一步指出字串相同時底層 token 機率仍在變，貼近 0.1–0.9 的 token 隨時會翻。
- 把 vLLM 的 VLLM_BATCH_INVARIANT=1 或 Thinking Machines 的 1000/1000 當成無條件保證。官方文件狀態是 beta，要求 compute capability ≥ 8.0，只列舉了驗證過的模型系列，且**只承諾同一組態內**——沒承諾跨 GPU 型號、跨 tensor parallel 度、跨版本。原作者自己也說最關鍵的 attention 固定切分「not included in our code release」。
- 把 cuBLAS 的 bitwise 保證讀成無條件。官方合約有四個前提：同 toolkit 版本、同架構、同 SM 數、單一活躍 stream；多 stream、atomics、跨版本、fixed-point emulation 任一發生即失效。抄一半就變成拿沙子當混凝土。
- 忽略「同樣輸出」與「同樣下游結論」是兩件事。arXiv:2408.04667 的 TARr 與 TARa 可以差到 0% 對 99.6%；arXiv:2506.09501 則量到相反方向——僅改 batch size／GPU 數／GPU 型號就造成最高 9% accuracy 變動與 9000 token 長度差。只記一個數字，兩個方向都會誤判。
- 把提高數值精度（如 LayerCast、FP32 累加）當成決定性的解法。它縮小每步誤差、延後分歧點，但沒有消除規約順序這個自變數；論文本身也沒宣稱 bitwise 決定性。這是緩解，不是保證，兩者不可互換。
- 對供應商 fingerprint 的缺席保持沉默。OpenAI 有 system_fingerprint 可偵測後端漂移，Anthropic 公開 API 目前沒有對應欄位（本次查證中未見）。把該欄位在缺席時留空而不標記，等於讓「基準已經換過」這件事變成靜默失敗。
- 把不決定性當成 LLM 時代的新問題而低估其深度。ASPLOS '13 的 GPUDet（DOI 10.1145/2451116.2451118）早已證明 GPU 上的決定性執行需要專門的硬體機制才有——決定性是要被構造出來的性質，不是預設值。

### prompt 當版本化 artifact：官方基準之上的權威層（prompt 敏感度、脆弱性、可重現性）

**裁決**：兩層都查到，但**地基本身缺一塊、而且有一根柱子正在被廠商自己抽掉**。官方層確實把 prompt 定成版本化 artifact（Bedrock 的 version 逐字是 "a snapshot ... at a point in time"、Agents SDK 的 id+version+variables），但同一批官方文件也自己承認 **prompt 身分不等於行為身分**：OpenAI 逐字說 Chat Completions 預設非決定性、seed 只給 "(mostly) deterministic"、system_fingerprint 會因為服務端改動而變。更關鍵的是 OpenAI 已公告 2026-06-03 棄用、2026-11-30 關閉 v1/prompts 與 reusable prompt objects，官方改推「prompt 進 code、用 git history / PR review / release tags / feature flags」——所以**能抄的地基是「prompt 是可版控的不可變 snapshot」這個語意，不是「廠商託管的 prompt registry」這個實作**。權威層補的正是官方沒寫的失效條件，而且指出四個 prompt 版本化完全管不到的隱藏輸入：格式／單字元（Sclar ICLR 2024 最高 76 分、Su 等 ±23%）、tokenizer（Land & Bartolo EMNLP 2024、TokSuite ICML 2026）、模型端無聲換版（Chen/Zaharia/Zou，同名 GPT-4 三個月從 84% 掉到 51%）、伺服器 batch size（Horace He，1000 次相同請求出 80 個版本）。真正**缺**的那一塊：查不到把「同一個 prompt id 底下內容漂移直接導致線上事故」端到端量化的同儕審查研究；最接近的替代證據是 MSR 2025 的「只有 21.9% 的 prompt 變更有被記錄」，那是漂移的**可觀測性**被量化，不是後果被量化。

**權威層**：
- [Melanie Sclar、Yejin Choi、Yulia Tsvetkov、Alane Suhr（UW／AI2／Berkeley），ICLR 2024] **FormatSpread：量化 prompt 格式這種「spurious feature」造成的 spread** — arXiv:2310.11324（ICLR 2024）
    補了：官方只說「prompt 有版本」，這篇量化了「語意保持、只改格式」能造成多大差距：跨 53 個 task、320 種格式，LLaMA-2-13B 最高 spread 達 76 accuracy points，GPT-3.5 最高 56、median 6.4。結論是評測應該報「格式上的 spread 區間」而非單一格式的單一數字。
    失效：明講敏感度不會被規模化解掉——模型變大、few-shot 例子變多、換成 instruction-tuned 版本都仍在。更關鍵：格式表現在模型之間「only weakly correlates」，所以在 A 模型上挑到的最佳格式搬到 B 模型不成立。
- [Moran Mizrahi、Guy Kaplan、Dan Malkin、Rotem Dror、Dafna Shahaf、Gabriel Stanovsky，TACL 2024, vol.12, pp.933-949] **State of What Art? A Call for Multi-Prompt LLM Evaluation** — DOI 10.1162/tacl_a_00681（ACL Anthology: 2024.tacl-1.52）
    補了：規模最大的一份 paraphrase 敏感度研究：6.5M instances、20 個 LLM、39 個 task、3 個 benchmark。結論是不同 instruction template 造成的差異不只絕對值，連**相對排名**都會變；因此提出多 paraphrase 的一組指標取代單 prompt 分數。
    失效：指出單一 prompt 的評測結論不可外推——「這個 prompt 比較好」若只跑過一種措辭，該結論沒有效力。
- [Jingtong Su、Jianyu Zhang、Karen Ullrich、Léon Bottou、Mark Ibrahim（Meta FAIR／NYU），2025] **A Single Character can Make or Break Your LLM Evals** — arXiv:2510.05152
    補了：把敏感度壓到最小單位：in-context 例子之間的**分隔字元**一個字元之差，MMLU 上表現可變動 ±23%；並示範可以只改這一個字元，把任一模型推上排行榜第一。
    失效：明講此現象跨 topic、跨 model family，且**不隨規模改善**。提出的緩解是把選用的 delimiter 明寫進 prompt。注意：同儕審查場地未查到，目前為 arXiv preprint。
- [Lingjiao Chen（Stanford）、Matei Zaharia（UC Berkeley）、James Zou（Stanford），Harvard Data Science Review, 2024] **How Is ChatGPT's Behavior Changing Over Time?** — DOI 10.1162/99608f92.5317da47（arXiv:2307.09009）
    補了：直接量化「同一個名字底下內容漂移」的模型端版本：prompt 一個字都沒改，GPT-4 判質數／合數 2023-03 版 84% 準確、2023-06 版掉到 51%。跨數學、敏感問題、程式碼生成、USMLE、視覺推理多個 task 都觀察到時間上的大幅變動。
    失效：指出 prompt 版本化管不到的那一半：呼叫端字串完全固定，行為仍會因為服務端換版而漂移，而使用者從介面上看不出來。
- [Sander Land、Max Bartolo（Cohere），EMNLP 2024 main track] **Fishing for Magikarp：自動偵測 under-trained tokens** — arXiv:2405.05417（EMNLP 2024 main）
    補了：指出 tokenizer 的建立與模型訓練是脫鉤的兩件事，因此 vocabulary 裡會存在幾乎或完全沒被訓練過的 token（如 SolidGoldMagikarp 類 glitch token）；提出用 tokenizer 分析＋模型權重指標＋探測 prompt 自動找出這些 token，並證明它們在多種模型上普遍存在。
    失效：這就是「同一份 bytes 在不同 tokenizer 下行為不同」的機制證據：只要那份 bytes 切到 under-trained token 上，行為不可預期，且這與 prompt 內容的語意無關——版本化 bytes 不等於版本化行為。
- [Gül Sena Altıntaş、Malikeh Ehghaghi、Brian Lester、Fengyuan Liu、Wanru Zhao、Marco Ciccone、Colin Raffel，ICML 2026] **TokSuite：把 tokenizer 的影響從模型裡隔離出來量測** — arXiv:2512.20757（ICML 2026）
    補了：訓練 14 個「除了 tokenizer 之外完全相同」的模型（同架構、同資料、同訓練預算、同初始化），首次把 tokenizer 當唯一變因做受控比較；並釋出跨五語（英、中、波斯、義、土）的真實文字擾動 robustness benchmark。
    失效：證明 tokenizer 是獨立於「模型版本」的第二個變因：同樣的文字、同樣的架構與資料，換 tokenizer 就換行為與 robustness。所以把 model_id 釘住還不夠，tokenizer 必須是版本身分的一部分。
- [Marco Tulio Ribeiro 與 guidance team（Microsoft Research），The Art of Prompt Design 系列] **Prompt boundary problem 與 token healing** — https://guidance.readthedocs.io/en/latest/example_notebooks/art_of_prompt_design/prompt_boundaries_and_token_healing.html
    補了：具名實務者的機制說明：tokenizer 是 greedy 的、偏好較長的 token，因此 prompt 結尾落在哪個 token 邊界會直接扭曲下一個 token 的分布。具體例：prompt 以 `http:` 結尾時生出 `http: //www.google.com`（多一個空格），改成以 `http` 結尾就正確生出 `http://...`；因為完整 URL 用的是 `://`（token 1358），而以冒號結尾強迫模型看到單獨的 `:`（token 27）。約 70% 的常見 token 可以被延伸成更長的 token，所以這問題是普遍的而非邊角。
    失效：直接命中「變數插值」這個場景：template 版本沒變、變數值一換，token 邊界就換，行為跟著換——記錄 template 的 hash 完全看不出這件事。緩解是 token healing（回退一個 token 並約束首個生成 token 的前綴）。
- [Horace He（PyTorch 核心開發者）與 Thinking Machines Lab，2025-09-10] **Defeating Nondeterminism in LLM Inference（batch invariance）** — https://thinkingmachines.ai/blog/defeating-nondeterminism-in-llm-inference/
    補了：把「temperature 0 為何仍不決定性」歸因到 kernel 缺乏 batch invariance：浮點非結合律只是前提，真正的隨機源是伺服器負載讓 batch size 隨機變動，而 kernel 在不同 batch size 下給出不同結果。實測：Qwen3-235B、temperature 0、1000 次完全相同的請求，產生 **80 個不同版本**；前 102 個 token 全部相同，第 103 個 token 才分岔（992 個生成 "Queens, New York"，8 個生成 "New York City"）。
    失效：明講 temperature 0 與 seed 都不足以達成可重現：「LLM APIs are still not deterministic in practice」。也就是**伺服器當下的負載是一個你沒宣告、也記不到的隱藏輸入**——把 prompt bytes 鎖到 100% 仍不可重現。
- [Mahan Tafreshipour、Aaron Imani、Eric Huang、Eduardo Almeida、Thomas Zimmermann、Iftekhar Ahmed，MSR 2025] **Prompting in the Wild：prompt 演化的實證研究** — arXiv:2412.17298（MSR 2025 accepted）
    補了：這是最接近「同一個 prompt 名字底下內容漂移」被量化的一份：挖 243 個 GitHub repo 的 1,262 個 prompt 變更，發現**只有 21.9% 的 prompt 變更在 commit message 裡有被記錄**；prompt 演化以「加東西」為主，且變更會引入邏輯不一致、以及 prompt 修改與 LLM 回應之間的失準。
    失效：指出「有版控」不等於「有記錄」：prompt 躺在 git 裡照樣無聲漂移，因為沒人寫下改了什麼、也沒有測試框架擋。作者明講缺的是 specialized testing frameworks 與 automated validation tools。
- [Sebastian Baltes 等 22 位作者，Empirical Software Engineering（已接受）] **Guidelines for Empirical Studies in Software Engineering involving LLMs** — arXiv:2508.15503（Empirical Software Engineering, accepted）
    補了：社群層級的可重現性要求清單，明列三條：report model versions, configurations, and customizations；document the system and prompt design beyond the model；report session traces（互動日誌與 runtime traces）。理由是 LLM 的 non-determinism、不透明訓練資料與快速換版。
    失效：直接說明 prompt 文字本身不足以構成實驗脈絡——只記 prompt 不記模型版本、系統設計與 session trace，研究就不可重現。

**nova_fit**：結論是：**prompt 不能用名字定址，也不能只用內容定址。** 落到 nova 的資料結構：

一、prompt 註冊表以 `(prompt_id, prompt_content_sha256)` 為主鍵，`prompt_id` 是跨程序 semantic id（ASCII）。同一個 `prompt_id` 出現兩個不同 hash 而沒有走過修訂流程，是硬錯誤，failure code `PROMPT_CONTENT_DRIFT`，不是警告。這一條有 MSR 2025 的 21.9% 背書：靠人在 commit message 寫下來已經被量測證明不可靠。

二、「一次執行的行為身分」是一組欄位，不是一個 hash。至少要有：
`prompt_content_sha256`（template 本體）、`rendered_prompt_sha256`（變數代入後、真正送出的那一份）、`token_ids_sha256`（tokenize 之後的 id 序列）、`tokenizer_id` + `tokenizer_sha256`、`model_id`、`model_build_id`、`decode_params`（含 seed 與 temperature）。`rendered` 與 `template` 必須分開存——token boundary 的證據說變數插值本身就會改變行為，只存 template 看不出來。`token_ids_sha256` 是把 tokenizer 這個變因釘死的唯一辦法，TokSuite 的受控實驗就是為此。

三、**廠商不給 `model_build_id` 時不得靜默視為「沒變」。** 這正好是 CLAUDE.md 那條「不得靜默降級」的實例：欄位缺席要回 typed `UNSUPPORTED_*`，或把該次執行的 claim 自動降級成「不可重現」，不能假裝可重現。這個降級規則本身要有負控測試——刻意餵一個沒有 build id 的回應，證明閘會紅。

四、**單次輸出相等不能當判準。** Horace He 的 1000/80 實測與 OpenAI 自己的 "(mostly) deterministic" 說明：把 `expected_output == actual_output` 當 claim 的判準，是把伺服器負載寫進驗收條件。判準要綁事前命名的 predicate 加上重跑，claim 上需要 `n_runs`、`observed_spread` 這種一等公民欄位，並且 spread 超過事前宣告的界線就紅——Sclar 與 Mizrahi 的建議（報區間不報單點）在這裡是可以直接寫成測試的。

五、保護清單要涵蓋這一整組：候選執行者不能寫 prompt 註冊表、不能改 `tokenizer_id` 綁定、不能重寫 `rendered_prompt`、不能改 `n_runs` 或 spread 界線。它可以提出修訂，接受權仍在 ClaimSpec 閘。

六、「全集」宣稱同理：要列出某個 prompt 的所有 variant，直接列舉註冊表裡該 `prompt_id` 的所有 row，不從呼叫點推導。

**坑**：
- 把 prompt bytes 相同當成行為相同。tokenizer、model build、伺服器 batch size 全是沒被宣告的隱藏輸入，四者各自有實證。
- 以為 temperature 0 或 seed 就等於可重現。實測 1000 次相同請求產出 80 個不同版本，前 102 個 token 還全部一樣——短測試會誤判成穩定。
- 只記 template hash 不記 rendered prompt hash。變數插值會移動 token 邊界，`http:` 結尾與 `http` 結尾生出不同東西，而 template 完全沒變。
- 拿在 A 模型調好的格式直接搬到 B 模型。Sclar 等明講格式表現在模型之間 only weakly correlates；搬過去等於重新賭一次。
- 用單一 prompt 跑一次的結果宣告「這版比較好」。單一分隔字元就能造成 MMLU ±23%、並把任一模型推上第一——沒有 spread 的比較沒有效力。
- 把廠商託管的 prompt registry 當成唯一真相來源。OpenAI 已公告 v1/prompts 於 2026-11-30 關閉，官方自己改推 prompt 進 code 用一般版控。
- 相信「東西在 git 裡」就等於漂移有記錄。實測只有 21.9% 的 prompt 變更在 commit message 裡寫了改什麼。
- 廠商回應裡沒有 fingerprint／build id 就當作「跟上次一樣」。這是教科書等級的靜默降級，必須 fail-closed 或回 typed UNSUPPORTED_*。
- 只版控 prompt 而不版控模型端。同名模型三個月內從 84% 掉到 51%，呼叫端一個字都沒改。
- 把「格式敏感度會隨模型變大而消失」當成可以等的問題。Sclar（規模、few-shot 數量、instruction tuning 皆無效）與 Su 等（不隨 scale 改善）兩份獨立證據都否定它。
- 引用時把 arXiv preprint 當同儕審查。本次清單中 arXiv:2510.05152 的審查場地未查到；Thinking Machines 與 guidance 那兩條是具名實務者論點而非論文，標成論文就是拿沙子當混凝土。

### LLM-as-judge 的偏誤量測與「獨立驗證」定義：judge 分數能不能當閘

**裁決**：兩層都查到了，但形狀不對稱，地基是**缺一塊**——而且缺的那塊正好是接縫。官方層只回答「怎麼量」（Vertex：human ratings 當 ground truth、二元／多值分開挑指標、F1 與 confusion matrix），**查不到任何門檻數字，也查不到「校準到什麼程度就可以當閘」或「不得當閘」的官方敘述**；獨立性的官方定義得跳到另一套完全不同的標準（NASA-STD-8739.8B §4.4.1.2 與 IEEE 1012-2016 Annex C 的 technical／managerial／financial 三參數）才拿得到，而那套標準的正文從頭到尾沒有一個字提到 LLM 或自動評分器。權威層補得很滿：三種偏誤都有實測量級（position 一致率低到 23.8%、verbosity 攻擊失守 91.3%、self-enhancement +10～+25pp、judge 與人 85% vs 人與人 81%），並補上官方沒寫的失效條件（品質接近時 position bias 最強、exact-match 高估 33–41pp、穩定 >0.95 與 position bias >0.10 可以並存、forced-choice 驗證選錯 judge 差 31%）。**關鍵問題的答案：權威層沒有任何一篇明文說 judge 分數「不得」作為 gate——未查到禁令。** 實際立場是條件式允許，而且條件是具名可執行的：alt-test（ω≥0.5、ε 依標註者等級 0.1／0.15／0.2、FDR q=0.05、≥3 標註者、≥30 且建議 50–100 instance）、PPI 無偏修正（需隨機抽樣的 human 子集，產出區間而非裸分數）、機率校正的 agreement、position-swap 一致性。最強的反面證據不是「禁止」而是「一旦成為優化目標即失效」：ICLR 2025 Oral 的 null model 用固定無關回覆在 AlpacaEval 2.0 拿到 86.5% LC win rate。**「換一家廠商的模型當 judge」在研究上不算獨立，有量測反對**：Goel 等人（arXiv:2502.04313，preprint）用 CAPA 測到 judge 分數與被評模型相似度的平均 Pearson r=0.84（p<0.01），控制正確率後仍顯著，並明講效應「extends beyond self- or family-preference to all models that are functionally similar」——vendor 是 similarity 的劣質代理。支持面只到「多家組成的 panel 比單一大 judge 好且 intra-model bias 較低」（PoLL，preprint），是降低不是消除。對照 IV&V 三參數：換廠商最多碰到 technical independence 的一部分，managerial（誰決定測什麼、findings 能不能被開發方擋下）與 financial 兩項完全沒碰到。**缺的那塊**：沒有任何官方或權威把「judge 校準」與「IV&V 獨立性」接起來——這個接縫是 nova 自己的組合契約，必須標成拆解決定而非地基，否則就是拿沙子當混凝土。

- [Shashwat Goel, Joschka Strüber, Ilze Amanda Auzina, Karuna K Chandra, Ponnurangam Kumaraguru, Douwe Kiela, Ameya Prabhu, Matthias Bethge, Jonas Geiping，2025（arXiv preprint，非同儕審查）] **Great Models Think Alike and this Undermines AI Oversight** — arXiv:2502.04313 ；https://arxiv.org/abs/2502.04313
    補了：**這篇直接回答「換一家廠商當 judge 算不算獨立」，而且答案是不算。** 提出 CAPA（Chance Adjusted Probabilistic Agreement），用「錯在同一題的重疊程度」量模型相似度，而非用能力分數。實測 9 個 judge、39 個來自多家開發者的模型：judge 給的分數與「被評模型和 judge 的相似度」有顯著正相關，平均 Pearson r=0.84（p<0.01），且做 partial correlation 控制被評模型本身的正確率之後仍然顯著。論文逐字說這個效應「extends beyond self- or family-preference to all models that are functionally similar」。具體案例：Qwen2.5-72B-Instruct 當 judge 時給 Qwen2.5-7B-Instruct 71% 正確，給實際更強（MCQ 準確率 51% vs 41%）的 Llama-3.1-70B-Instruct 只有 67%。附帶警告：模型的錯誤正在隨能力提升而變得更相似。

- [Nitay Calderon, Roi Reichart, Rotem Dror，2025（arXiv preprint）] **The Alternative Annotator Test for LLM-as-a-Judge（alt-test）** — arXiv:2501.10970 ；https://arxiv.org/abs/2501.10970
    補了：**這是「若允許，前提條件是什麼」目前最具體的可執行程序。** 對每一位人類標註者做 leave-one-out 檢定：問 LLM 是否比該標註者更能預測其餘標註者的判斷。決策規則逐字：winning rate ω 為「the proportion of rejected null hypotheses」，「If ω≥0.5, we conclude that the LLM is more likely to hold an advantage over human annotators」。成本補償超參數 ε 依標註者等級設定：專家 ε=0.2、受訓標註者（如大學生）ε=0.15、群眾外包 ε=0.1。顯著性用 FDR q=0.05。最低樣本量：至少三位標註者，至少 30 個 instance（t-test 常態性假設），實務上 50–100 個 instance 多半足夠。

- [Shreya Shankar, J.D. Zamfirescu-Pereira, Björn Hartmann, Aditya G. Parameswaran, Ian Arawjo，2024，UIST 2024] **Who Validates the Validators? Aligning LLM-Assisted Evaluation of LLM Outputs with Human Preferences** — arXiv:2404.12272 ；https://arxiv.org/abs/2404.12272
    補了：指出 judge 校準的循環困境，作者命名為 criteria drift：「users need criteria to grade outputs, but grading outputs helps users define criteria」。也就是評分準則不是事前可以定死的，而是在看實際輸出的過程中才浮現，因此 judge 的 rubric 需要人反覆對齊，不是一次寫好。

- [Justin D. Norman, Michael U. Rivera, D. Alex Hughes，2026-06-17（arXiv preprint，**非同儕審查**，收錄於此僅因它提供的數字直接打到官方基準）] **Reliability without Validity: A Systematic, Large-Scale Evaluation of LLM-as-a-Judge Models Across Agreement, Consistency, and Bias** — arXiv:2606.19544 ；https://arxiv.org/abs/2606.19544
    補了：21 個 judge、約 541,000 次判斷。兩個直接影響閘設計的數字：(1) **kappa deflation is universal**——同一批資料用 exact match 算 agreement 與用 Cohen's kappa 算，在 MT-Bench 上差距達 33–41 個百分點，也就是未做機率校正的一致率系統性高估 judge 的鑑別力；(2) 兩個已上線的 judge 同時具備 test-retest reliability >0.95 與 severe position bias >0.10——**穩定與無偏是兩件事，穩定地偏誤仍然是偏誤**。作者提出 Minimum Viable Validation Protocol。
    失效：作者自陳的建構效度限制：reliability 被操作化成 accuracy／agreement／bias probe 這幾個代理，未涵蓋 calibration、長篇 rationale 品質、領域特定一致性。此外這是 2026 年的 preprint，**不得當成同儕審查結論引用**；引用時應把它當「數字待複驗的線索」。

**nova_fit**：**一、judge 產出的型別不是 verdict。** judge 只能產生 advisory 型 evidence，接受權仍在 ClaimSpec 閘。落到結構上：judge 的輸出物件加 `evidence_role` 欄位，值域只允許 `ADVISORY`；任何試圖把它寫成 `VERDICT` 的路徑一律 fail-closed，回 typed failure code 而非靜默降級。理由是官方層查不到「可當閘」的背書，而權威層有 null model 的反例——沒有官方出處的東西不是地基，這條要標成 nova 的額外拒絕。

**二、`judge_calibration` 是一等公民物件，不是附註。** 建議欄位（ASCII，跨程序 schema 欄位名）：`judge_id`、`judge_model_snapshot`（含供應者與版本字串，不可用「廠商名」單獨當 key）、`rubric_id`、`rubric_revision`、`human_ground_truth_set_id`、`n_instances`、`n_annotators`、`balanced_accuracy`、`f1`、`cohens_kappa`、`exact_match_agreement`、`position_swap_consistency`、`alt_test_winning_rate`、`alt_test_epsilon`、`fdr_q`、`calibrated_at`、`expires_at`。兩個非慣例的設計決定要寫進 docstring：(1) `cohens_kappa` 與 `exact_match_agreement` **兩個都存**，因為兩者的差距本身就是「這份校準有沒有被高估」的訊號；(2) 校準的 key 是 `(judge_model_snapshot, rubric_revision, task_id)` 三元組，任一項變動即 `expires_at` 立刻到期——權威層實測校準結論綁在這個三元組上。

**三、不可能用 `vendor` 欄位表達獨立性。** 建立 `independence` 物件，三個欄位對齊 IV&V 標準：`technical`、`managerial`、`financial`，值域 `INDEPENDENT` / `PARTIAL` / `NONE` / `UNKNOWN`，預設 `UNKNOWN`。硬規則：judge 與被評對象來自不同供應者，**至多**只能把 `technical` 標成 `PARTIAL`，不得自動標 `INDEPENDENT`，且要另填 `similarity_evidence`（CAPA 或等價的錯誤重疊量測，附量測值）才能升級。`managerial` 與 `financial` 在單一自動化管線內預設就是 `NONE`——決定要評什麼、findings 能不能被擋下、誰付這筆 token 費用，全都在被評的那一側。這三格填什麼**候選執行者不可寫**，與「不能自報完成、不能改 criterion」同一條線。

**四、每次 judge 呼叫必須成對執行。** 同一組候選以正序與逆序各跑一次，`position_swap_agreement` 進 effect receipt。兩次不一致的 case 的處置寫死為**不計入通過**，而不是取多數或取平均——權威層的失效條件是「品質接近時偏誤最強」，取多數等於在最不可信的區域強行造出一個答案。

**五、真要拿 judge 的統計量進 claim，走區間不走點。** 欄位加 `human_labeled_subset_id`（必須是隨機抽樣）、`ppi_corrected_estimate`、`confidence_interval_lower`、`confidence_interval_upper`，claim 一律落在下界。沒有 `human_labeled_subset_id` 就沒有這條路徑可走，回 `UNSUPPORTED_*` 而非退回裸分數。

**六、擴充點語意。** 上述都是在既有能力上「增加拒絕」，屬合法加蓋動作①；若日後要讓某個已校準的 judge 取得更大的接受集合，必須走已宣告、具命名空間、具版本的擴充點，且未理解該擴充的舊元件要 fail-closed 或回 `UNSUPPORTED_CAPABILITY`。

**七、以上每一條都要有會 fail 的測試背書。** 至少四格負控：未校準的 judge 被當成通過、`expires_at` 過期後仍被採用、position swap 不一致卻計入通過、`independence` 三格全 `UNKNOWN` 卻產出 `VERDICT`；外加一格防恆真——「校準齊備且 swap 一致時，正常路徑不被誤殺」。

**坑**：
- 用未做機率校正的 exact-match agreement 當 judge 驗收指標。實測 kappa deflation 在 MT-Bench 上達 33–41 個百分點，等於系統性高估 judge 的鑑別力（arXiv:2606.19544，preprint，數字待複驗）。
- 把「換一家廠商的模型當 judge」當成獨立性。量測反對：judge 分數與相似度的平均 Pearson r=0.84，控制正確率後仍顯著，且效應涵蓋所有 functionally similar 的模型而非只有同家族（arXiv:2502.04313）。對照 IV&V 三參數，換廠商連 technical independence 都只碰到一半，managerial 與 financial 完全沒動。
- 把 judge 分數當成可被優化的門檻。ICLR 2025 Oral 實測：永遠輸出同一段無關回覆的 null model 在 AlpacaEval 2.0 拿到 86.5% LC win rate、Arena-Hard-Auto 83.0、MT-Bench 9.55，且這些榜單已內建長度控制與風格解耦（arXiv:2410.07137）。
- 只跑一個答案順序就採信結果。position bias 的一致率實測 Claude-v1 僅 23.8%、GPT-3.5 46.2%、GPT-4 65.0%（arXiv:2306.05685），且候選品質越接近偏誤越強（arXiv:2406.07791）。
- 把高 test-retest reliability 讀成可信。實測有已上線 judge 同時具備 >0.95 的重測穩定度與 >0.10 的嚴重 position bias——穩定地偏誤仍然是偏誤（arXiv:2606.19544，preprint）。
- 用單一 forced-choice 的 human label 當 ground truth 做 judge 選型。在評分準則存在多個合理解讀時，這會選出比正確方法差達 31% 的 judge（arXiv:2503.05965，NeurIPS 2025）。

- [Evan Miller（Anthropic），2024-11] **Adding Error Bars to Evals: A Statistical Approach to Language Model Evaluations** — arXiv:2411.00640 — https://arxiv.org/abs/2411.00640

**nova_fit**：落到 nova：**「省了多少 token」不能是一個數，必須是一個帶指紋的分佈**，而且品質那一半要有下界才准通過閘。

三個資料結構：

① `token_measurement_fingerprint`（釘住情境，任一欄不同即不可比）：`model_id`、`tokenizer_version`、`endpoint`、`api_version`、`counted_by`（`billed_usage` ／ `count_tokens_estimate`，兩者不得混用聚合）、`cache_state`（`cold` ／ `warm`）、`cache_breakpoints`、`cache_min_tokens`、`reasoning_budget_tokens`、`system_prompt_hash`、`tool_schema_hash`、`sampling`（`temperature`／`top_p`／`seed`）、`serving_stack`、`batch_policy`。

② `token_measurement_sample`（一次跑一列，不預先聚合）：`input_tokens`、`output_tokens`、`cache_read_input_tokens`、`cache_creation_input_tokens`、`reasoning_tokens`、`cached_tokens`、`rounding_granularity`（有廠商是 128，向下取整）、`hidden_tokens_excluded`（bool）、`latency_ms`、`call_count`、`turn_count`、`retry_count`。後六個是為了不重蹈 The Efficiency Misnomer 點名的「只報一個成本指標」。

③ ClaimSpec 的 claim 本體是 `paired_difference` 而**不是**點值：`n_items`、`k_repeats_per_item`、`delta_tokens_mean`、`delta_tokens_ci_low`／`ci_high`、`quality_delta_ci_low`、`quality_metric`、`judge_calibration_ref`。接受條件寫成兩條合取——`delta_tokens_ci_high < 0`（省 token 的區間整段在零以下）且 `quality_delta_ci_low >= -epsilon`（品質的**下界**不掉超過事前宣告的 epsilon）。點值一律不構成 claim。

```
        單次點值                       nova 要的
    A: 1200 tok                   A vs B 配對差分
    B:  900 tok        ==>        Δtok  CI [-340, -260]   <- 整段 < 0
    "省 25%"                      Δqual CI [-0.9, +0.4]   <- 下界 >= -eps
                                  情境指紋 hash 相符才可比
```

固定負控（`must_fail_exactly`）至少兩格，缺一不可：
- **恆真格**：把 baseline 與 candidate 指向**同一份設定**跑同樣的 K 次，claim 必須紅——因為兩邊只差雜訊，`delta_tokens_ci_high` 不會小於零。這格專門抓「把重跑波動當成改善」。
- **指紋格**：兩邊指紋不同（例如 `tokenizer_version` 或 `cache_state` 不一致）時，閘必須拒絕而不是照算，failure code 用 `INCOMPARABLE_FINGERPRINT`。

擴充點的 fail-closed：後端沒有 `cache_read_input_tokens` 或 `reasoning_tokens` 這類欄位時，回 typed `UNSUPPORTED_TOKEN_ACCOUNTING`，**不得用 0 補**——用 0 補會讓隱藏成本靜默消失、把「沒量到」誤判成「沒發生」，正是 CLAUDE.md 禁的靜默降級。同理，`k_repeats_per_item < 2` 時回 `UNSUPPORTED_SINGLE_SHOT_CLAIM`，因為單次量測連區間都算不出來。

檢定力放在准入前而非事後：ClaimSpec 要求事前宣告最小可偵測效果量 `min_detectable_delta`，用 Miller 的樣本數公式檢查這份題庫有沒有能力測它；測不動就在准入階段直接擋掉，而不是讓一個註定測不出來的實驗跑完再解讀。

**坑**：
- **拿 count_tokens 的估計值當節省證據。** 官方逐字說那是 estimate，且可能含「你不會被計費」的 system-added token；官方 FAQ 另外明講它不套用 caching 邏輯，所以它**量不到任何 cache 帶來的節省**。要用實際回應的 usage 欄位，不是事前估計。
- **跨模型比 token 數＝拿兩把不同的尺量。** Anthropic 官方寫 Claude 4.7 起的 tokenizer 對同一段文字產生約多 30% 的 token，並明確要求不要沿用舊模型量到的數字。任何「換了模型之後省了 X%」若沒把 tokenizer 版本釘進指紋，數字沒有意義。
- **cached_tokens 會向下取整到 128 的倍數，並先扣掉隱藏的 system token。** 這代表小於 128 token 的節省在這個欄位上恆為 0，看起來像「完全沒省」；而多筆小節省累加後也會被逐筆截斷、系統性低估。
- **cache 命中不是純函數。** Anthropic 預設 TTL 5 分鐘、且明列同樣請求也可能 miss；OpenAI 的 cached state 綁在個別機器上、能否命中取決於路由與負載。同一個 prompt 兩次跑出不同的 `input_tokens` / `cache_read_input_tokens` 分帳，多半不是你的裁切法變了，是冷熱狀態變了。量測必須把 `cache_state` 釘成實驗變數，冷跑與熱跑分開報。
- **低於最低可快取長度時「不報錯、靜默不快取」。** Anthropic 文件明說要回頭看 usage 欄位才知道有沒有快取到。這是典型的靜默失敗——你以為在量 cache 效益，實際上兩組都沒進 cache。
- **只數看得見的輸出，漏掉 reasoning／thinking token。** OpenAI 官方逐字說 reasoning token 不可見、但佔 context 且以 output token 計費，數量可從幾百到數萬。一個「省了輸入 token」的做法若讓模型多想，總量可能不降反升。
- **temperature=0 不等於可重播。** 實測 1000 次同一 prompt 得到 80 種輸出、第 103 個 token 開始分岔。所以「跑一次 A、跑一次 B，比大小」在方法上無效，不管你把溫度設成多少。
- **把改善拿去和雜訊比大小之前先問雜訊多大。** 同設定僅換種子，7B 規模下 MMLU 標準差 0.57pp、ARC-C 0.80pp、HumanEval 1.11pp、COPA 2.15pp。宣稱的改善若小於這個量級，單次量測分不出來——這時候要做的是加題數（Miller 的 power analysis），不是加重跑次數：K 增加的降噪效益在 E[σ²]/K ≪ Var(x) 之後就飽和了。
- **壓縮率／裁切率是「你要求的」不是「它達成的」。** 實測顯示 LLMLingua 在 500-token prompt 上的 rate adherence MAE 已超過 0.05、8,000 token 以上超過 0.15。要記錄 achieved ratio 並回報其分佈，不能把 target ratio 寫進報告當結論。
- **只報 token 不報 latency／記憶體／呼叫次數。** The Efficiency Misnomer 的核心論點就是成本指標彼此會矛盾、只報幾個會導出片面結論；實測也顯示在已最佳化的 serving stack 上，壓縮的前處理時間會把加速吃光、變成純開銷。OpenAI 官方的比較清單（total tokens、latency、cost、calls、turns、retries）是同一件事的廠商版。
- **效益數字只在一個 operating window 內成立。** 那篇實測拿到的 up to 18% 端到端加速，綁死在 prompt 長度、壓縮率、硬體等級三者對上的條件；離開那個窗口效益歸零甚至為負。把別人論文的百分比當成你環境的預期值，就是在重蹈該論文批評的錯。
- **換提示寫法就會翻排名。** TACL 那篇以 6.5M 實例、20 個模型、39 個任務測出不同指令模板導致絕對與相對表現都明顯不同。若你比較的兩個對象本身就是「兩種提示組裝法」，單一提示的單次量測連方向都不保證。
- **用 LLM 當品質裁判卻不校準裁判。** 裁判的 sensitivity／specificity 不完美會產生**系統性偏誤**，不是隨機噪音——加重跑次數消不掉。沒有人工標註校準集，就沒有可信的品質下界，「品質不掉」是未證的。
- **「品質不掉」報成點值等於沒報。** 省 token 的宣稱必須綁品質差的**信賴區間下界**，而不是「平均分數差不多」。平均沒掉但下界跌穿門檻，代表你不知道最壞情況；這正是 OpenAI 官方那句『更少的呼叫與中間輸出只有在最終答案仍達到品質門檻時才算改善』在統計上的落地形式。
- **摘要裡的「up to」是最佳情況而非分佈。** 這是這個領域的預設報法（LLMLingua 摘要的 20x 與未量化的「little performance loss」即是），不是造假，但把它當成期望值來規劃就是誤用。要求對方報曲線（如 Dodge 的預算-效能曲線）而不是報一個峰值。

### 視覺回歸測試的「相似度度量 × threshold」地基：官方基準與權威層（感知度量的失效條件、flaky 實證研究對 threshold 的評價）

**裁決**：兩層都查到了，但**地基缺一塊**：官方層只定義了「參數叫什麼、預設多少、跑在哪算數」（threshold=0.2/YIQ、maxDiffPixels、maxDiffPixelRatio、baseline 受 OS 與硬體影響），完全不談「這個門檻在什麼條件下會漏掉真東西」；權威層補上了「為什麼」與「何時失效」（度量依觀看條件 PPD 才有意義、SSIM 有未定義值且不考慮觀看距離、LPIPS 對人眼看不見的位移與擾動會翻轉判斷、threshold 是被學界認可的緩解但沒有可移植最佳值、截圖抖動的主流根因是時序與環境而非度量）。缺的那一塊是**量化**：本次未查到任何同儕審查研究做過「把 threshold 從 X 調到 Y，漏掉多少比例真實視覺回歸」的掃描實驗——最接近的只有 Bajammal 等人「最佳門檻不可能有通解」的定性判決，以及 Romano 等人「修法分類裡根本沒有放寬容忍度這一項」的反面證據。因此 nova 不能宣稱「threshold 選得好就安全」有外部背書；能宣稱的只有：threshold 是合法緩解、但其數值不可攜、且必須連同度量實作、版本與觀看條件一起被釘住。

- [Microsoft（Playwright 官方 docs：Visual comparisons）] Playwright 視覺比對的實作與環境前提 — https://playwright.dev/docs/test-snapshots

- [ISO/IEC JTC 1/SC 29（JPEG 委員會）] ISO/IEC 29170-2:2015 —— 近無損編碼的評估程序（flicker paradigm） — https://www.iso.org/standard/66094.html

**權威層**：
- [Andersson, Nilsson, Akenine-Möller, Åström, Oskarsson, Fairchild（NVIDIA / Lund University），2020，Proc. ACM Comput. Graph. Interact. Tech.（HPG 2020）] **FLIP: A Difference Evaluator for Alternating Images** — DOI 10.1145/3406183；作者版 PDF https://developer-blogs.nvidia.com/wp-content/uploads/2020/07/flip-author-version-reduced-file-size.pdf（限制段落與 SSIM 案例已由本次直接抽取全文核對）
    補了：在官方「設一個門檻」之上補了度量本身的物理前提：FLIP 以對比敏感函數濾掉在**給定觀看條件**下看不到的細節，其管線明確依賴 PPD（pixels per degree，由螢幕尺寸、解析度、觀看距離算出；論文預設 67 PPD）。換句話說，任何感知度量的輸出值只有在標明觀看條件時才有意義——同一對圖在不同 DPI／縮放／觀看距離下，「該不該算差異」的答案本來就不同。論文另以 1,500 組圖對，將 FLIP 與 SSIM、LPIPS、PieAPP、HDR-VDP-2、Butteraugli、S-CIELAB 等逐一對照。
    失效：論文自列 Goals and Limitations：①「the algorithm is not designed to handle high-dynamic range input」；②主要限制是無法偵測 masking，「can lead to overestimation of differences when they are not perceived due to other image content masking them out」（即會把看不見的差異報成差異）；③為避免使用者輸入難以量測的觀看條件，刻意不用最精確的色度量。另對 SSIM 提出具體失效案例：SSIM「does not consider viewing distance and pixel size」，在只差 dither pattern 的圖對上產生大量觀察者根本看不到的誤差，且會產生一批「uninterpretable values」（負值）。
- [Jim Nilsson, Tomas Akenine-Möller（NVIDIA），2020] **Understanding SSIM** — arXiv:2006.13846
    補了：對被廣泛當成「感知相似度」預設答案的 SSIM 做數學拆解，指出其各項因子在合成與真實案例下都會給出非直覺結果。作者逐字說 SSIM 雖被大量採用，卻「little deep scrutiny of this index has been performed」。
    失效：明確列出：SSIM 會產生**未定義（undefined）**的結果、非直覺的結果；「assessing image quality based on SSIM can lead to incorrect conclusions」；當成 deep learning 的 loss 使用時「can guide neural network training in the wrong direction」。
- [Venkataramanan, Wu, Bovik（SSIM 原作者群之一）, Katsavounidis, Shahid，2021] **A Hitchhiker's Guide to Structural Similarity** — arXiv:2101.06354
    補了：指出「SSIM」不是一個數字而是一族實作：不同實作的預設參數／前處理不同，同一對圖片可得到不同分數，論文以「bendable ruler」形容，並說這使得用它評比編碼演算法的品質評估不可靠。對測試而言的意涵是：把 `ssim >= 0.99` 寫進判準而不釘住實作與參數，等於沒有釘住判準。
    失效：未指出（本次僅取得摘要層級說明，未取全文核對其失效條件清單）
- [Zhang, Isola, Efros, Shechtman, Wang，CVPR 2018] **The Unreasonable Effectiveness of Deep Features as a Perceptual Metric（LPIPS）** — arXiv:1801.03924；CVPR 2018 open access https://openaccess.thecvf.com/content_cvpr_2018/papers/Zhang_The_Unreasonable_Effectiveness_CVPR_2018_paper.pdf
    補了：以人類判斷資料集（BAPPS）實證：PSNR 與 SSIM 是「simple, shallow functions」，無法涵蓋人類感知的許多面向；改用深度特徵距離（LPIPS）在人類偏好一致性上大幅勝出。這是「像素級色差不等於人看得見的差異」這句話的同儕審查背書。
    失效：該論文本身以正面結果為主；失效條件由後續研究補（見下兩則）。
- [Abhijay Ghildyal, Feng Liu（Portland State University），ECCV 2022] **Shift-tolerant Perceptual Similarity Metric（ST-LPIPS）** — arXiv:2207.13686；DOI 10.1007/978-3-031-19797-0_6
    補了：點出既有感知度量（含 LPIPS）都假設兩張圖已對齊；對**人眼看不出來的微小位移**極為敏感。對視覺回歸測試的直接意涵：字型 hinting、次像素捨入、捲動位置差一像素這類位移，會讓度量值大幅跳動，而這正是實務上被誤解成「度量不準、把 threshold 調大就好」的主要來源。
    失效：逐字：既有度量「are often sensitive to a small alignment error that is imperceptible to the human eyes」——即在有微小 misalignment 時失效。作者以 anti-aliasing filtering、pooling、striding、padding、skip connection 的架構調整來緩解，代表這不是調門檻能解的問題。
- [Abhijay Ghildyal, Feng Liu，TMLR 2023（spotlight）] **Attacking Perceptual Similarity Metrics** — arXiv:2305.08840；OpenReview https://openreview.net/forum?id=r9vGSpbbRO
    補了：系統性檢驗傳統與學習式感知度量對**不可察覺擾動**的穩健性：以 FGSM、PGD、one-pixel attack、stAdv 等把失真圖往參考圖推，直到度量翻轉判斷。結論是所有受測度量都會被翻轉，且白箱對 LPIPS 生成的樣本可黑箱轉移到其他度量。意涵：度量值與「人看不看得見」之間不是單調關係，存在人看得見但度量說像、以及人看不見但度量說不像的雙向反例。
    失效：逐字：「All metrics ... are susceptible to perturbations generated via common adversarial attacks」。因此把單一度量值當成唯一驗收判準，理論上就存在可被構造出來的漏網區。
- [Bajammal, Stocco, Mazinanian, Mesbah（UBC），IEEE TSE 48(5):1722-1742, 2022] **A Survey on the Use of Computer Vision to Improve Software Engineering Tasks** — DOI 10.1109/TSE.2020.3032986；PDF https://tsigalko18.github.io/assets/pdf/2020-Bajammal-TSE.pdf（threshold 與 false positive 段落由本次直接抽取全文核對）
    補了：**這是對「用 threshold 容忍抖動」最直接的權威評價。** 該調查（66 篇論文）明說視覺方法對主題／周邊變化、光照與繪製差異敏感，而「A possible mitigation concerns using threshold parameters to limit their detrimental effect」——即 threshold 被學界認可為正當的緩解手段，不是壞味道。但同一篇隨即說：所收論文的視覺技術多是 ad-hoc 解，全部都討論到參數（如 optimal threshold selection）的需求，且「Authors recognize that this requirement is unlikely to be solved by a consolidated and broadly-accepted solution」。另指出 DOM 層差異不必然對應視覺差異，是早期跨瀏覽器檢測誤報多的根源。
    失效：失效條件即上述：threshold 沒有可移植的通用最佳值，必須逐情境校準；且該調查把「辨識兩圖間細小、難以察覺的差異」列為視覺方法的公開難題（以 VISOR 為例，重音字元繪製造成的極小差異即成誤報來源），並指出這類差異該不該算缺陷「is left to human's perception」。
- [Romano, Song, Grandhi, Yang, Wang（University at Buffalo / UT Dallas），ICSE 2021] **An Empirical Analysis of UI-based Flaky Tests** — arXiv:2103.02669（上述計數由本次直接抽取論文 Table I / IV / VI 全文核對）
    補了：**回答「視覺測試在 flaky 分類裡佔多少、成因是什麼」的實證資料。** 樣本 235 個 flaky UI 測試、62 個開源專案（web + Android）。根因四大類：AsyncWait 105 個（45.1%，web 52.0% vs mobile 32.5%）、Environment、Test Runner API Issue、Test Script Logic Issue。子類計數（Web/Mobile/Total）：Resource Rendering 47/14/61、Animation Timing Issue 17/9/26、Network Resource Loading 15/4/19、Platform Issue 16/18/34、Layout Difference 9/1/10。論文對 Resource Rendering 的定義逐字說明：測試在元件尚未完全繪製完成時就動作，「leads to visual differences detected by screenshot tests」。也就是說，截圖測試看到的抖動，主流成因是**時序與環境**（不同視窗尺寸、不同瀏覽器繪製策略），不是度量算錯。
    失效：對 threshold 這個做法的隱含裁決：該研究的修法分類是 Add/Increase Delay 21、Fix Await Mechanism 43、Fix API Access 12、Change Library Version 7、Refactor Logic Implementation 75（46.0%）、Disable Animations 4、Remove Test 73；**「放寬比對容忍度／調高 threshold」完全不在修法分類中**。把時序性 flakiness 用調大 threshold 壓下去，等於把 45% 的根因留在原地而只調暗警報。
- [Yu Pei, Jeongju Sohn, Mike Papadakis（University of Luxembourg / KNU），Journal of Systems and Software, 2026] **An Empirical Study of Web Visual Flakiness: Characterisation and Fix Strategies** — DOI 10.1016/j.jss.2026.112826；https://orbilu.uni.lu/handle/10993/68138
    補了：目前查到唯一專門針對「web 視覺抖動」的實證研究：262 個案例，來自 31 個開源專案（144）與 Chromium（118）；報告 visual commits 佔全部 commit 的 11.4%，且比 non-visual commits 更常引發 flakiness。同組另有 ICST 2025 的 web flaky test 研究（DOI 10.1109/ICST62969.2025.10989030）聚焦 DOM 與事件互動。
    失效：未指出（本次僅取得出版商／機構庫的摘要層級敘述，未取得全文核對其成因分佈與修法分類；上述 262／11.4% 兩個數字來自摘要頁敘述而非全文表格）

**nova_fit**：結論落到 nova：**被釘住的不是那個門檻數字，而是整份比對契約。** 一個只寫 `threshold: 0.2` 的 claim 在權威層看來是未定義的——同一個 0.2 在 pixelmatch v5（YIQ）與新版（OKLab/HyAB）不是同一件事，在不同 DPI 下也不是同一件事。

建議的資料結構（欄位名 ASCII，值可中文）：

```
claim
 └─ image_compare            # 比對契約，整包進判準、整包版本化
     ├─ metric               # pixelmatch | ssim | flip | lpips ...
     ├─ metric_version       # 缺這格 = 門檻語意浮動
     ├─ color_space          # yiq | oklab | ...（隨 metric_version 綁定）
     ├─ threshold            # 單一像素色差容忍
     ├─ max_diff_pixels      # 差異像素「數量」上限
     ├─ max_diff_pixel_ratio # 差異像素「比例」上限
     ├─ viewing_conditions   # { ppd, device_scale_factor }  ← FLIP 那條的落點
     ├─ env_fingerprint      # os / browser_build / headless / gpu / font_stack
     └─ baseline_provenance  # 誰在什麼環境產生、由誰核准
```

三條由上面的證據直接推出的機制：

1. **threshold 與 max_diff_* 是兩個方向不同的盲區，必須分開宣告、不可互相代償。** 前者放大會讓「面積大但每像素色差小」的變化整片消失；後者放大會讓「面積小但色差大」的變化消失。官方文件把它們列為三個獨立選項，nova 不該用單一「容忍度」欄位把它們糊成一格。

2. **調寬容忍度是規格變更，不是實作者的旋鈕。** 依 CLAUDE.md 的分權，`threshold`／`max_diff_*`／`viewing_conditions` 屬於 ClaimSpec，候選執行者不得修改；要動就走 RequirementChange，舊 claim 與證據不覆寫。這一條有權威背書：既然「最佳門檻不可能有通解」，那它就是每次都要重新裁定的規格決定，不是可就地最佳化的參數。

3. **驗收權不交給分數，交給事前命名的負控。** 呼應 CLAUDE.md 已有的 mutation 條款：raw diff score／raw kill rate 不進判準；判準是「事前命名的視覺 mutation，被指定 predicate 殺掉」。每次放寬容忍度，必須同時新增至少一格負控，證明**放寬後那些被指名的壞仍然會紅**——這正好補上權威層查不到的那塊量化：外部沒人替我們量過「調高多少漏掉多少」，那就由 nova 自己對**自己指名的那組壞**逐案量。

4. **能力不足回 typed 拒絕，不靜默降級。** 若某後端不支援所宣告的 metric 或無法提供 `viewing_conditions`，回 `UNSUPPORTED_METRIC` / `UNSUPPORTED_CAPABILITY`，不得改用近似度量後回報成功——這正是「未理解該擴充的舊元件必須 fail-closed」在這個題目上的具體落法。

**坑**：
- `threshold` 的預設值兩邊不同：pixelmatch 自己是 0.1，Playwright 設 0.2。抄別人部落格的數字時常錯把兩者混談。
- 同一個 `threshold` 數字的語意會隨實作版本改變：Playwright 文件寫的是 YIQ 色差，而 pixelmatch 上游目前的 README 已改為 OKLab + HyAB。門檻不釘版本 = 門檻沒被釘住。
- pixelmatch 另有獨立的 anti-aliasing 偵測機制（Vyšniauskas 2009），與 threshold 是兩回事。把「字型鋸齒造成的誤報」全部歸咎於 threshold 太小，會調錯旋鈕。
- 感知度量的輸出只有在標明觀看條件（PPD／DPI／device scale factor）時才有意義（FLIP 明文依賴 PPD，預設 67）。沒有記錄觀看條件的門檻數字不可重現、也不可跨裝置移植。
- SSIM 會產生未定義／負值與非直覺結果，且不考慮觀看距離與像素大小（FLIP 論文以 dither pattern 圖對展示：人看不到，SSIM 報大誤差）。把 SSIM 分數當成「人眼可見度」的代理是錯的。
- 「SSIM」不是單一數字而是一族實作（bendable ruler），參數不同分數就不同；`ssim >= 0.99` 這種判準沒釘實作與參數等於沒釘。
- LPIPS 這類學習式度量對人眼看不見的微小位移與微擾動會翻轉判斷（ST-LPIPS、Attacking Perceptual Similarity Metrics）。換成「更感知」的度量並不會消滅漏網區，只是換一組漏網區。
- 把 flaky 當成度量問題來治是治錯病：實證上 UI flaky 的最大根因是 AsyncWait（45.1%），其中 Resource Rendering（61/235）正是「還沒繪製完就截圖」，而該研究的修法分類裡**沒有**「放寬容忍度」這一項。
- 官方文件只保證「在產生 baseline 的同一環境重跑」；OS、瀏覽器版本、硬體、headless 與否、甚至電源狀態都會改變繪製結果。CI 換 runner image 造成的整批紅，是環境指紋問題，不是門檻問題。
- 本次未查到任何同儕審查研究量化過「調高 threshold 後漏掉多少真實回歸」。任何引用這類數字的說法（含各家工具廠商部落格）目前都沒有可驗證出處，不得當地基。
- 延伸 CLAUDE.md 既有裁決：diff 分數是連續值，一旦當成門檻型指標就會把不可殺／不可見的差異算進分母，重蹈 mutation score 當閘的錯。分數只能當觀測，不能當驗收權。

### 允許循環與共享狀態的執行圖，要滿足什麼條件才可重播；「node 可獨立重播」在研究上的名稱與代價

**裁決**：兩層都查到了，但**地基缺一塊、而且缺的正是關鍵那塊**。官方層（LangGraph、Temporal、W3C PROV、ProvONE、Workflow Run RO-Crate）給的是「怎麼做」：在 superstep 邊界存 checkpoint、非決定操作要包進 node／Activity、provenance 用什麼欄位描述、順序約束只用相對先後不用時鐘。官方層**沒有給任何「可重播」的充分條件**——LangGraph 官方甚至逐字承認它的 replay 就是重跑（「Replay re-executes nodes—it doesn't just read from cache」，且「may return different results」），也就是說 LangGraph 的 replay 是「重新執行」不是「重播錄音」；只有 Temporal 這一家把決定性寫成硬約束，而它的手段是把非決定整包踢出 replay 路徑（Activity）而不是讓它可重播。權威層才回答了關鍵問題，而且答案是三組互補的充分條件，缺一不可：①**結構條件**（Kahn／Lee & Parks）——每個 node 是 stream 上的 monotonic/continuous 函數、只做 blocking read、不得偵測「還沒收到」，如此**即使有循環也 determinate**；循環本身無罪，可觀察的時序才有罪。②**共享狀態條件**（LVars／CALM）——共享狀態只准單調 join、只准 threshold read，非單調寫入（覆寫、刪除、聚合）必須協調並把順序錄下來。③**切面與錄音條件**（Chandy-Lamport／Deterministic Replay Survey）——checkpoint 必須落在一致割上，且所有非決定來源都要被記錄並依相同順序回放。三者之外還有一條無法迴避的**負面結果**：KPN 的 boundedness 不可判定、workflow net 加擴充後 soundness 不可判定——所以不能承諾靜態判定循環圖會不會停。nova 想要的「node 可獨立重播」研究上叫 **interface-level / library-level record-and-replay**（R2 是代表作），在工作流社群的近親叫 **smart re-run / partial re-execution**（Kepler、VisTrails 的中間結果快取）；代價已經被量過：介面邊界要人工宣告資料流向且會宣告錯（R2），錄製有 probe effect（CSUR 綜述），全系統 provenance 收集的實測 overhead 從幾十趴到數十倍（ACM REP '24），而完整度最高的收集器就是最慢的那些。多出來的部分只有一個：官方層的 provenance 標準（PROV／ProvONE／RO-Crate）在 nova 目前階段可以只取其**語意分層**（prospective／retrospective／process 三分，以及「不假設同步時鐘、只用相對序」），不必整套序列化格式。

**權威層**：
- [Gilles Kahn（IFIP Congress 1974, pp. 471–475）；Edward A. Lee & Thomas M. Parks（Proceedings of the IEEE, 83(5):773–801, 1995）] **Kahn Process Networks 的決定性定理（以及 dataflow process networks 對它的整理）** — DOI 10.1109/5.381846（Lee & Parks）；Kahn 1974 收於 IFIP Congress proceedings，dblp key conf/ifip/Kahn74，無 DOI
    補了：這是「允許循環的圖為何仍能可重播」的**充分條件本體**，官方文件完全沒有的一層。KPN 由 process 與單向 FIFO channel 組成，determinate 的定義是：所有內部與輸出 channel 的 history 只取決於輸入 channel 的 history。充分條件是每個 process 都是 stream 上的 monotonic／continuous 映射（continuous 蘊含 monotonic：x ⊆ y ⇒ f(x) ⊆ f(y)），實作上落到「只做 blocking read」；整個網路的行為是最小不動點，**因此有回饋環（cycle）仍然 determinate**。也就是說：循環不是可重播的敵人，「能觀察到自己還沒收到東西」才是。
    失效：明確指出失效條件：(1) 引入 nondeterminate 構件（典型是 nondeterministic merge，或任何讓 process 去偵測 channel 是否為空／輪詢／逾時的能力）就破壞 determinacy——因為 process 的輸出開始依賴到達時序而不只依賴 history；(2) 可分析性有硬上限：判定一個 KPN 是否 strictly bounded（FIFO 不會溢位）是**不可判定**的，因此不能承諾「靜態檢查出這個循環圖會不會停、會不會爆」。
- [K. Mani Chandy & Leslie Lamport, ACM Transactions on Computer Systems 3(1):61–75, 1985] **Distributed Snapshots：一致割（consistent cut）** — DOI 10.1145/214451.214456
    補了：回答「有環、有在途訊息的圖，checkpoint 要在哪裡切才是可用的狀態」。第一個解決非同步分散式系統一致全域狀態的演算法：一致割的定義是割線之前收到的每個訊息，都必須在割線之前送出；演算法用 marker 訊息把在途訊息掃出 channel，process 在快照後對每條 outgoing channel 發 marker，並把快照到收到 marker 之間的 incoming 訊息一併記錄。這是「checkpoint 邊界必須是 superstep 邊界」這條工程直覺的形式化理由。
    失效：若各節點各自在任意時間點存檔而不做割的一致性處理，得到的全域狀態可能是**從未真實發生過**的狀態（有 orphan message：收到了卻沒人送過）。另一面向也要講清楚：即使演算法正確，快照記錄的是一個「可能發生過」的一致狀態，不保證是某個真實瞬間的照片。
- [Yunji Chen, Shijin Zhang, Qi Guo, Ling Li, Ruiyang Wu, Tianshi Chen；ACM Computing Surveys 48(2), Article 17, 2015] **Deterministic Replay: A Survey** — DOI 10.1145/2790077
    補了：把「可重播」的充分條件講成可操作的形式：把**所有非決定來源**記錄下來，重播時以相同順序餵回去。分類為 single-processor 與 multiprocessor 兩大類，並指出 MP 的難點在 memory race——「幾乎每一次記憶體參考都可能發生」。它同時建立了評估重播方案該量的維度：log size、record slowdown、replay slowdown、implementation cost、probe effect。這幾個維度就是「node 可獨立重播」的成本表欄位。
    失效：直接點名 probe effect：**錄製本身會改變被錄的執行行為**，所以「錄起來那次」不必然等於「沒錄那次」。另外指出高效能程式庫（如 MPI）的 out-of-order 執行會讓計算本身非決定，非決定來源不是只有 I/O。
- [Zhenyu Guo, Xi Wang, Jian Tang, Xuezheng Liu, Zhilei Xu, Ming Wu, M. Frans Kaashoek, Zheng Zhang；USENIX OSDI '08] **R2: An Application-Level Kernel for Record and Replay** — https://www.usenix.org/legacy/event/osdi08/tech/full_papers/guo/guo.pdf （OSDI '08，無 DOI）
    補了：這就是 nova 想要的「node 可獨立重播」在研究上的名字：**在自選的介面邊界上做 record-and-replay，把元件與其環境隔離後單獨重播**（interface-level / library-level record-and-replay，相對於 whole-system replay）。R2 在應用程式位址空間內定義 syscall-upcall 介面，把應用與 record&replay 程式庫嚴格隔離；關鍵設計是「**開發者自己決定哪一層介面是 replay space 與 system space 的分界**」，並替該介面上的呼叫產生 stub 來錄與播。
    失效：代價寫得很清楚：開發者**必須為介面加註記**，說明資料如何跨越被攔截的介面（哪些是輸入、哪些是輸出、指標指向多少資料），否則 replay 就不 faithful。也就是說「node 可獨立重播」不是免費的圖屬性，是一份**必須人工宣告且會宣告錯**的邊界契約；邊界選錯（切在錯誤的抽象層）會讓錄下來的東西既大又不可重播。
- [Lindsey Kuper & Ryan R. Newton；FHPC 2013（ICFP workshop）] **LVars：lattice-based data structures for deterministic parallelism** — DOI 10.1145/2502323.2502326
    補了：回答問題的另一半——**共享狀態**。它給出共享可變狀態仍保證決定性的充分條件：狀態住在使用者指定的 lattice 上，寫入只能是單調（inflationary）的 join，讀取只能是 threshold read（阻塞到狀態超過某個下界才回傳）。這把「決定性」從『不要共享狀態』放寬成『共享狀態但只准單調成長』，正好對應 reducer／channel 型的圖狀態。
    失效：條件是雙邊的、缺一即失效：只要出現**非單調寫入**（覆寫、刪除、遞減）或**精確讀取**（讀出當下完整值而非 threshold 查詢），determinism 保證立刻消失。代價是表達力：能塞進 lattice 且只單調成長的狀態才適用。
- [Joseph M. Hellerstein & Peter Alvaro；Communications of the ACM 63(9):72–81, 2020] **CALM 定理（Consistency As Logical Monotonicity）** — DOI 10.1145/3369736 ；arXiv:1901.01930
    補了：把上一條從語言層抬到系統層並給出**充要**刻畫：具有一致、免協調（coordination-free）分散式實作的程式，**恰好**是能用單調邏輯表達的程式。對一個允許平行 superstep 的圖來說，這條決定了哪些 node 可以自由重排／平行／重跑而結果不變（單調的），哪些一定要協調（因而重播時必須把順序也錄下來）。
    失效：非單調的問題（聚合、否定、覆寫式更新）**必須**協調才能保證一致；把它們當成單調來平行化，就會得到執行序相關、因而不可重播的結果。
- [W.M.P. van der Aalst 等；Formal Aspects of Computing, 2011] **Soundness of workflow nets: classification, decidability, and analysis** — DOI 10.1007/s00165-010-0161-4
    補了：Petri net 這一路對「允許循環的圖」的形式化結論：workflow net 是分析循環流程的標準抽象，soundness（無 deadlock、livelock 等，不需領域知識即可判定的異常）文獻上的**八種 soundness 定義對 workflow net 都是可判定的**。這是「循環圖可以被形式化檢查」的正面證據。
    失效：同一篇給了警告，而且方向與直覺相反：**大多數擴充會讓這八種定義全部變成不可判定**（例如加了 reset arc 之後 soundness 不可判定）。也就是說每增加一個看似方便的表達力（動態邊、任意清空狀態、取消整支子流程），付出的代價是靜態保證整片消失。
- [James Cheney, Laura Chiticariu, Wang-Chiew Tan；Foundations and Trends in Databases 1(4):379–474, 2009] **Provenance in Databases: Why, How, and Where** — DOI 10.1561/1900000006
    補了：把「要錄什麼才夠重算」拆成三個互不等價的概念：why-provenance（哪些輸入證成了這個輸出）、how-provenance（用什麼方式組合出來的）、where-provenance（值來自哪個位置），並整理三者之間的關係與在 view maintenance／update／除錯／annotation 傳播上的應用。這一層說明「lineage 有記」與「能重算」是兩件事。
    失效：未指出（該綜述給的是三種概念的關係與適用場景，本次查證未取得明確的『何時會失效』陳述）。
- [Jun Zhao, José Manuel Gómez-Pérez 等，IEEE e-Science 2012；以及 'Why Do Scientific Workflows Still Break?', SSDBM 2024] **Workflow decay 的兩次實證（2012 與 2024）** — DOI 10.1109/eScience.2012.6404482 ；DOI 10.1145/3676288.3676300
    補了：這是**時間軸上的失效證據**：可重播不是一次性性質，而是會隨時間衰減。2012 年那份分析 Taverna 工作流的 decay 成因；2024 年那份在現代工具（Snakemake、Nextflow，Snakemake 部分取自 workflow catalog 列出的 1602 個 GitHub repo）上重問同一個問題，結論是相當比例的工作流仍難以 rerun，遑論 repeat 或 reproduce，並追問「衰敗成因是否與上一代相同、或有新因素」。
    失效：失效機制是**外部世界變動**而非圖本身壞掉：第三方服務／資源消失或改版、執行環境與相依套件未被捕捉、隱含狀態與隱含相依沒有寫進規格。推論：只錄 provenance trace 不足以讓計算被重複——這正是 workflow decay 的定義。
- [Nicholas J. Pritchard & Andreas Wicenec；Future Generation Computer Systems（預印本 arXiv:2406.01146, 2024）] **Formal Definition and Implementation of Reproducibility Tenets for Computational Workflows** — arXiv:2406.01146 ；ScienceDirect pii S0167739X24006484
    補了：把「可重播」拆成七個**可測試的斷言**而不是一個模糊形容詞：rerun（邏輯工作流相同）、repeat（邏輯與實體皆大致相同）、recompute（實體 task 與相依精確相同）、reproduce（終端資料產物的科學資訊相同），再兩兩組合成 scientific／computational／total replication。實作面用 BlockDAG：對每個元件的 provenance 做 Merkle tree，巢狀簽章成整個工作流的 DAG 簽章，使兩次執行的比對成為常數時間。這給了 nova 一個現成的「用 digest 判定重播是否相同」的形式。
    失效：作者自己標出上限：precise recompute 需要相同的實體 task、硬體與執行軌跡，被形容為代價極大且 'likely impossible without total hardware control'；在他們自己的 lowpass filter 示範中**沒有任何一次試驗達到 computational replication**。分散式的非決定性使嚴格重現變複雜；方法只適用於傳統 task-based 工作流系統，推廣到其他系統未被證實。
- [Samuel Grayson, Faustino Aguilar, Reed Milewicz, Daniel S. Katz, Darko Marinov；ACM REP '24] **A benchmark suite and performance analysis of user-space provenance collectors** — DOI 10.1145/3641525.3663627
    補了：把「錄下來以便重播」的代價量成實測數字，而不是形容詞。Table 4 的 percent overhead（幾何平均，數值 3 代表耗時變 1.03 倍）：以 RR（決定性 record-replay）為例，BLAST 93、SPLASH-3 CPU 49、Compile w/Spack 562、HTTP srv/traffic 1261、Utils bash 426；ReproZip 在 postmark 是 1733、bash 是 2933；strace 在 postmark 650。對照組 fsatrace 幾乎都在個位數。
    失效：結論直接否定「永遠開著錄」這個預設：「provenance collectors exhibit an intolerably high overhead to be always used, with the exception of fsatrace」——而 fsatrace 之所以快是因為用 library interpositioning 而非 ptrace，代價是它「is one of the weakest collectors」，只收檔案讀寫／搬移／刪除／查詢，**連 process fork 與 exec 都不收**。也就是完整度與開銷在同一條曲線上，不能兩者兼得。

**nova_fit**：把「可重播」從形容詞降成**型別與欄位**，讓判準能由測試裁定而不是由執行者自報。

一、node 執行紀錄 `node_run`（每次執行一筆，append-only）：
`run_id`、`node_id`、`superstep_no`、`attempt`、`input_digest`（對該 node 實際讀到的 state 投影做 canonical 序列化後 hash，投影範圍必須明示宣告，不是「整個 state」）、`output_digest`、`code_version`、`env_digest`。判定「重播是否相同」＝比對 `output_digest`，這一步採 Pritchard & Wicenec 的 Merkle/BlockDAG 形式，常數時間可比。

二、`replay_class`（typed enum，**必填、無預設值**）：
`PURE`（純函數，可直接重算，不需錄音）／`RECORDED`（非決定但非決定來源已完整錄下，可回放）／`UNREPLAYABLE`（未錄，明示放棄）。未理解此欄位的舊元件遇到未知值必須 fail-closed 或回 `UNSUPPORTED_CAPABILITY`，**不得靜默當成 `PURE`**——把未知當純函數是這整套機制最貴的單點失效。`PURE` 是一個**宣稱**，必須有負控測試背書（同輸入兩次執行 digest 相同、且刻意注入一個非決定來源時該測試會紅），沒有負控的 `PURE` 等於謊。

三、非決定來源的錄音 `effect_receipt`：
`effect_id`、`node_run_id`、`seq`（node 內單調遞增序號）、`kind`（typed）、`request_digest`、`response_ref`。重播時依 `seq` 回放；`seq` 或 `request_digest` 對不上就是 typed failure `REPLAY_DIVERGENCE`（採 Temporal 的指令對帳語意，而不是 LangGraph 的「重跑看看」語意）。這條同時解決 R2 指出的邊界問題：`kind` 就是介面邊界的宣告，宣告不全就 replay 不 faithful。

四、state channel 的合併語意 `merge_kind`（每個 channel 必填）：
`MONOTONIC_JOIN`（lattice join，順序無關、可平行 superstep、重播不需錄順序）／`ORDERED_OVERWRITE`（非單調，必須把同一 superstep 內的寫入順序錄進 `write_order`，否則拒絕平行）。這是 LVars／CALM 的直接落點，也是「共享狀態＋循環仍可重播」的那半個充分條件。

五、checkpoint 的合法切面：
只允許在 superstep 邊界建立，欄位 `superstep_no` 與 `pending_writes`（同 superstep 內已完成 node 的寫入），**禁止 node 執行中途存檔**——理由是一致割，不是效能。

六、圖的靜態宣告 `read_discipline`：
node 只能 `BLOCKING_READ`；任何「偵測某輸入是否為空／逾時／輪詢」的能力必須是獨立宣告的擴充（具命名空間、具版本），且宣告了就把該 node 的 `replay_class` 上限鎖成 `RECORDED`。這把 Kahn 的 determinacy 條件變成結構承載而非文件叮嚀。

七、明確不做的事（寫進規格，避免日後被當漏畫）：
不承諾靜態判定循環會不會停或 channel 會不會爆（不可判定）；不把「重播成功率」做成分數型門檻（同 raw mutation kill rate 的理由——分母裡有本質上不可重播的項）；只准「事前命名的 `node_run` 被指定 predicate 判定 digest 相同」才有驗收權。

八、代價要進帳而不是進註解：
`replay_class` 逐 node 決定錄或不錄，`UNREPLAYABLE` 是合法且可見的選擇，但必須是明示的 typed 值。錄製開銷與 probe effect 要有量測欄位（`record_overhead_ratio`），因為權威層的實測告訴我們「永遠開著錄」在真實負載上不成立。

**坑**：
- 「replay」這個詞在兩家官方文件裡是兩個相反的意思：Temporal 的 replay 是拿既有 Event History 對帳、不重做外部工作；LangGraph 的 replay 官方逐字說是 re-execute nodes、不讀 cache、可能給出不同結果。把兩者混用會讓人以為「有 checkpointer 就等於可重播」——那是最容易發生的地基誤植。
- 循環不是可重播的敵人，**可觀察的時序**才是。Kahn 的結論是有回饋環的網路仍然 determinate，只要每個 node 是 stream 上的單調連續函數且只做 blocking read。反過來說，只要給 node 一個「看看現在有沒有東西進來」或「逾時就走另一條」的能力，determinacy 立刻消失——而這種能力通常被當成無害的工程便利加進去。
- node 中途存檔會拿到「從未真實發生過」的全域狀態（orphan message）。checkpoint 只能落在一致割上；這是 Chandy-Lamport 的結論，不是效能取捨。
- probe effect：錄製本身會改變被錄的執行。所以「錄起來那次跑綠」不能證明「沒錄那次也綠」——這正好是 CLAUDE.md 已有的「換個情境跑綠不能判定假紅」的一個具名實例。
- 不可判定性有兩處硬牆，別承諾靜態檢查：KPN 是否 strictly bounded 不可判定（Lee & Parks）；workflow net 的 soundness 本身可判定，但加上 reset arc 之類的擴充後八種 soundness 全部變不可判定（van der Aalst）。每加一個表達力，付的代價是整片靜態保證。
- `PURE` 是最貴的謊。宣稱某 node 是純函數而它其實讀了時鐘、環境變數、或迭代順序不定的容器，會讓整條重播鏈靜默失真而不是報錯。沒有負控測試背書的 `PURE` 必須被當成 `UNREPLAYABLE`。
- 未知的 `replay_class` 被靜默當成可重播＝典型的靜默降級。舊元件遇到不認得的擴充必須 fail-closed 或回 `UNSUPPORTED_CAPABILITY`。
- 「有記 provenance」不等於「能重算」。Cheney 等人把 why／how／where 分成三個互不等價的概念；只知道某輸出用到了哪些輸入（lineage），不足以重新產生它。
- 重播能力會**隨時間衰減**而不是壞在某一刻。workflow decay 的成因是外部服務改版消失、環境與相依未被捕捉、隱含狀態未進規格（2012 與 2024 兩次實證結論一致）。若 `env_digest` 與 `code_version` 沒錄，就無法區分「重播機制壞了」與「外面的世界變了」——這兩者的處置完全不同。
- 完整度與開銷在同一條曲線上。ACM REP '24 的實測：決定性 record-replay 在編譯類負載上 overhead 達數百趴到十幾倍；唯一夠快能 always-on 的 fsatrace 是「最弱的收集器之一」，連 process fork/exec 都不收。假設能同時拿到「全錄」與「零成本」是規劃層級的錯誤。
- 不要把「重播成功率」做成百分比門檻。理由與 CLAUDE.md 已寫死的 raw mutation kill rate 完全同構：分母裡混進了本質上不可重播的項（外部世界已變、硬體層非決定），分數會靜默退化且無法 actionable。要的是「事前命名的 node_run＋指定 predicate 判定 digest 相同」。
- 嚴格的 computational replication 在研究上尚未被示範成功——提出七個 tenet 的作者自己的實驗中沒有一次達成，並直言不完全控制硬體幾乎不可能。nova 若把驗收綁在最嚴格那一格上，等於把閘設在無人達成過的位置。
- 介面邊界不是圖自動給你的，是人工宣告的契約，而且會宣告錯（R2 明講必須為介面加註記說明資料如何跨界，否則 replay 不 faithful）。「node 可獨立重播」的成本主要落在這份宣告上，不在存 checkpoint 上。

### 程式終止性與「無進展偵測」的地基：官方的 timeout／bounded retries／backoff（safety 面）之上，補上 ranking function／well-founded relation／liveness／progress measure 的權威層（liveness 面），以及權威層對「用固定迭代上限代替終止證明」的評價

**裁決**：**缺一塊，而且缺的是同一件事的另一半。** 官方層（AWS Builders' Library、AWS Prescriptive Guidance、RFC 8961／BCP 233）給的全部是 **safety**：時限是「等待的上界」、重試次數有上限、backoff 要 cap、要加 jitter。它們保證「不會永遠等下去、不會把重試放大成雪崩」，但**沒有任何一份官方文件定義過「有沒有在前進」**——official 那一層裡「進展」是空的。權威層補的正是這一半：Lamport 1977 把它命名為 liveness、Alpern–Schneider 1985 給它形式定義並證明任何性質都是 safety ∩ liveness（所以只寫得出 safety 的規格是**留白**，不是「不需要」）。至於三個關鍵問題：①「無進展偵測」在形式方法裡對應的是 **liveness／progress property**，工具層的標準做法是 **non-progress cycle detection**（SPIN 的 progress label ＋ 預定義 LTL `<>[] np_`，Büchi acceptance）。②可檢查的 progress measure 有標準做法，而且不只一種形狀：Floyd 1967 的 ranking function（映到良基集合、嚴格下降）、Ben-Amram–Genaim 的 LRF／LLRF（ρ ≥ 0 且 Δρ ≥ 1）、Jurdziński 2000 的 lattice pre-fixed point 見證。③**「單調遞減且有下界」不是正解，只是正解的一個特例，而且少寫了條件**：真正的條件是「映到**良基**序且嚴格下降」；值域是有理／實數時「有下界＋遞減」不足，必須要求每步至少降固定量（≥1 或 δ>0）。更關鍵的是，現代自動化的正解形狀是 **disjunctively well-founded transition invariant**（Podelski–Rybalchenko 2004，Theorem 1 是充要條件，靠 Ramsey 定理）——不是一條全域單調遞減的量，而是「有限多個良基關係的聯集覆蓋**遞移閉包**」；而該文自己的 ACK-REQ 反例證明少了「遞移閉包」這個條件就會給出假通過。最後，「用固定迭代上限代替終止證明」權威層的評價是**有條件接受、但定位不同**：Holzmann Power of Ten Rule 2 與 JPL D-60411 Rule 3 都要求上限**靜態可證**（證不出來就算違規）、刻意不終止者要**反向證明不會終止**而非豁免，且外加上限的超限路徑是 assertion failure ＋ error return——那是**偵測**，不是證明；BMC（Biere et al. 1999）給的是同一個教訓的另一面：有界展開是找 bug 的正解，不是證明沒 bug 的正解。所以 nova 若把 cap 當成終止見證，那不是「缺一塊」而是**多了一個假保證**。

    補了：這是「單調遞減且有下界」是否為正解的直接答案。逐字：transition invariant 是「a binary relation over program states that contains the transitive closure of the transition relation」；Definition 2「A relation is disjunctively well-founded if it is a finite union of well-founded relations」；Theorem 1「The program is terminating if and only if there exists a disjunctively well-founded transition invariant」（證明用 Ramsey 定理）。也就是說：**正解不是一條全域單調遞減的量，而是「有限多個良基關係的聯集覆蓋遞移閉包」**；每段各自有自己的下降理由即可，不必排出一個全域序。論文自陳動機正是「especially when ranking functions and well-founded (lexicographic) orderings are involved」時建構輔助斷言難以自動化。

- [Amir M. Ben-Amram & Samir Genaim，2014，Journal of the ACM 61(4):1–55] **Ranking Functions for Linear-Constraint Loops（ranking function 與 lexicographic ranking function 的可檢查定義、以及合成的複雜度代價）** — DOI 10.1145/2629488；作者版全文 https://arxiv.org/pdf/1208.4041
    補了：把「單調遞減且有下界」寫死成可檢查的謂詞，並點出這個形狀的兩個必要條件。逐字（Def. 2.9）：ρ 是 LRF 若對每個 transition 都有 ρ(x) ≥ 0 且 Δρ(x″) ≥ 1；並註明「in the literature [Podelski and Rybalchenko 2004b] this 1 is sometimes replaced by δ > 0」，兩者對存在性等價。又逐字說明一般形狀是「maps a program state into an element of some well-founded ordered set, such that the value descends ... Since descent in a well-founded set cannot be infinite, this proves that the loop must terminate」，並明示這裡用的序是 a ⪰ b iff a ≥ b+1（which is well-founded）。Def. 2.11 給 lexicographic LRF：存在某個 i，前 i−1 個分量不上升、前 i 個非負、第 i 個至少降 1。
    失效：兩個明確的失效點。①**值域不良基時，「有下界＋嚴格遞減」不夠**：值域是有理／實數時必須要求每步至少降固定量（≥1 或 δ>0），論文的定義把這一條寫進去正是為此。②**成本會爆**：Theorem 3.1「The LinRF(Z) problem is strongly coNP-hard, even for SLC loops with affine-linear updates」，而且論文說明所建構的迴圈「either has a LRF, or fails to terminate」，因此換一種見證形式也逃不掉這個 coNP-hardness。合成 ranking function 不是便宜操作。

In those special cases, the reverse rule is applied: it should be statically provable that the iteration cannot terminate.」——注意是**反向證明**，不是豁免。②**外加上限只是偵測不是證明**：對迭代次數可變的迴圈（如走 linked list）加一個顯式上限時，「When the upper-bound is exceeded an assertion failure is triggered, and the function containing the failing iteration returns an error」——也就是超限時走的是錯誤路徑，這證明了「不會 runaway」，沒有證明「這趟有前進」。

**nova_fit**：**一、safety 與 liveness 在 schema 上必須是兩組欄位、兩組 failure code，不可互相頂替。**（Alpern–Schneider 的分解定理是這條的地基）

safety 側（官方層落點，直接沿用既有介面語意）：`deadline_ms`、`attempt_cap`、`backoff_policy{ base_ms, max_ms, jitter }`。耗盡時一律回 typed failure（`DEADLINE_EXCEEDED`、`ATTEMPT_CAP_EXCEEDED`），**永遠不得回「完成」**——這正是 CLAUDE.md「候選執行者不能自報完成」的同一條規則落在時間軸上。

liveness 側（權威層落點，新增擴充點）：一個具名的 `progress_measure` object。

**二、`progress_measure` 的欄位形狀，直接照權威層的三種見證形狀命名：**

- `measure_id`：跨程序 semantic id（ASCII）。
- `kind`：`well_founded_rank`（Floyd）／`lexicographic_rank`（LLRF）／`disjunctive_union`（transition invariant）。**未知值必須 fail-closed 回 `UNSUPPORTED_CAPABILITY`，不得靜默忽略**——這是 CLAUDE.md 語意單調那條的直接套用。
- `domain`：`nat` ／ `ordinal` ／ `rational_with_min_decrement`。選最後一種時 `min_decrement` **必填且必須 > 0**（Ben-Amram–Genaim Def. 2.9 的 Δρ ≥ 1 形狀）。不接受無 `min_decrement` 的浮點測度——這是「有下界≠良基」那個坑的機制化。
- `lower_bound`：必填，且型別必須與 `domain` 一致。
- `components[]`：僅 `kind=disjunctive_union` 時存在，每個元素自帶自己的良基見證；**同時必須有一個布林欄位明示這個聯集覆蓋的是遞移閉包**（例如 `covers_transitive_closure`），為 false 時該見證一律不具終止證明資格，只能降級成觀測。ACK-REQ 反例就是為這個欄位存在的。
- `observed[]`：每個 tick 一筆 `{ tick_id, value, decreased }`。**觀測值的來源必須是閘可獨立取得的一手資料，不接受執行者自報**（CLAUDE.md「監看器事件是二手資料」「不對自報照單全收」）。

**三、「上限」與「證明」是兩個欄位、兩種結論，禁止混用。**

`iteration_cap`（防 runaway 的守衛，來自 Holzmann／JPL 的定位）與 `termination_witness`（指向某個 `measure_id` 的終止見證）分開存放。cap 觸發 → `ITERATION_CAP_EXCEEDED`；有 tick 但 `decreased=false` 持續累積 → `NO_PROGRESS_DETECTED`。**只有 `termination_witness` 通過驗證才允許出現 `TERMINATION_PROVEN` 這個結論**，而且 cap 的存在**永遠不得**推導出它。另外照 JPL Rule 3 的形狀：`iteration_cap` 若不是靜態可判定的（例如由執行者自填的 magic number），該欄位應標記為 `unproven_bound`，並使任何依賴它的 claim 自動降級——與 CLAUDE.md 已有的「繞過留下痕跡並使 claim 自動降級」同一個機制。

**四、刻意長駐、不打算終止的迴圈：照 JPL 的反向規則，不是豁免。**

顯式宣告 `non_terminating: true` 後，要求的判準**從「會停」換成「無限次進展」**（SPIN `<>[] np_` 的形狀：每個週期都必須經過至少一個 progress 標記點），而不是把它從閘裡拿掉。豁免會變成 CLAUDE.md 上限 #5 的翻版——被跳過的檢查會被算成通過。

**五、claim 與負控落點。**

progress 閘最容易變成恆真格，所以負控至少要三格，缺一不可：① 一個「有界但不進展」的樣本（cap 內跑完、`decreased` 永遠 false）必須被殺掉；② 一個 `covers_transitive_closure=false` 的分段遞減假見證必須被拒絕為終止證明；③ 一個 `domain=rational_with_min_decrement` 但 `min_decrement` 缺失／為 0 的測度必須被拒收。再加一格防恆真：**合法的真見證不被誤殺**。

**坑**：
- 「有下界＋單調遞減」不等於良基。只有值域本身良基（自然數／序數）時兩者才等價；有理或浮點值域必須額外要求每步至少下降固定量（Ben-Amram–Genaim Def. 2.9 的 Δρ ≥ 1，等價於 Podelski–Rybalchenko 的 δ > 0）。schema 若允許沒有 min_decrement 的浮點 measure，就是允許一個滿足條件卻不終止的見證。
- 「有界」不等於「有進展」。固定迭代上限保證會停，不保證做了事——迴圈可以在上限內反覆做無用功後乾淨地「完成」。SPIN 之所以在 safety 檢查之外另外要 non-progress cycle detection，正是因為這是兩件不同的性質。
- disjunctively well-founded ≠ well-founded。Podelski–Rybalchenko 自己的 ACK-REQ 反例證明了這一點：把執行拆成幾段、每段各自遞減，**本身不是終止證明**；只有當那個有限聯集是含遞移閉包的 transition invariant 時，Theorem 1 才成立。少了遞移閉包這個條件的「分段遞減」會給出假通過。
- 固定迭代上限在權威層的合法性條件是「靜態可證」，不是「有填就好」。Holzmann Rule 2 逐字：證不出來就算違規（If the loop-bound cannot be proven statically, the rule is considered violated）。允許執行者自填一個大數字當 cap，等於把違規狀態記錄成合規狀態。
- 把「cap 內跑綠」當成「不會不終止」是 BMC 的老錯。有界展開能找到最短反例，不能證明反例不存在（除非另外論證 completeness threshold）。sound for finding ≠ sound for proving。
- 官方層完全沒有「進展」概念。只照 AWS／RFC 8961 做時限、有界重試、capped backoff、jitter，拿到的是完整的 safety 面與**空白的 liveness 面**；Alpern–Schneider 的分解定理說這個規格只寫了一半，不是「另一半不需要」。
- 刻意不終止的長駐迴圈不能當豁免處理。JPL D-60411 Rule 3 與 Power of Ten Rule 2 都是換成**反向要求**（證明它不會停／要求無限次進展），不是把檢查移除。做成豁免就會複製 CLAUDE.md 上限 #5：被跳過的檢查被算成通過，閘靜默變成永遠綠。
- 進展的觀測值若由被觀測者自報，等於沒有量測。progress measure 的每筆 observed 必須有閘可獨立取得的一手來源，否則整個 liveness 閘退化成「執行者說它有在前進」。
- 外加的迴圈上限走的是錯誤路徑，不是成功路徑。Holzmann 的做法是超限即 assertion failure 並回傳 error——nova 對應的是 typed failure code，絕不能讓超限落進「完成」分支。
- 合成 ranking function 不便宜。Ben-Amram–Genaim Theorem 3.1：LinRF(Z) 是 strongly coNP-hard，即使只是仿射線性更新的單路徑迴圈；而且他們證明換別種足夠表達力的見證也逃不掉。把「自動找出終止見證」當成隨手可得的能力會低估成本。
- 本次仍有兩處只到書目／摘要層級，尚未逐字查證，引用時不要當成逐字出處：Cook–Podelski–Rybalchenko 的 CACM 2011 綜述（全文 403／需權限）與 Floyd 1967 原文 PDF（OCR 抓取失敗，其形狀是靠 Ben-Amram–Genaim 的 JACM 論文逐字轉述確認的）。

### 量測結果必須帶不確定度：JCGM GUM／VIM 的定義、JCGM 106 的決策規則，與心理計量學的 construct validity／reliability——一個不帶不確定度的數字能不能拿去排序與做決定

**裁決**：**兩層都查到了，而且兩層的答案一致且比預期更硬——但地基缺的不是這一塊，是它與現有官方基準之間的接縫。**

先回答關鍵問題：**一個不帶不確定度的數字，依官方定義不是一個完整的量測結果。** GUM 3.1.2 逐字「complete only when accompanied by a statement of the uncertainty」，VIM 2.9 把 measurement result 定義成「set of quantity values ... together with any other available relevant information」而非一個值，且 NOTE 3 明說「一個值」是已被取代的舊定義。唯一的出口是 VIM 2.9 NOTE 2：不確定度「for some purpose 被判定為可忽略」時可只給單一值——**那是一個要被聲明、要被辯護、要被記錄的判斷，不是預設值**（NIST TN 1297 的例外條款把這一點寫死：偏離政策也「must document what was done and why」）。

拿去排序與做決定，權威層講得更重：GUM 0.1 逐字說沒有不確定度指標時「measurement results **cannot be compared**, either among themselves or with reference values」——排序與門檻判定兩件事都在這句的射程內。JCGM 106 把代價量化：直接拿點值跟門檻比（simple acceptance），在門檻附近的錯誤裁定機率**上界是 50%**。Goldstein & Spiegelhalter 與 Marshall & Spiegelhalter 把它推到排名上：即使底層差異真實存在，名次的 95% 區間可橫跨 20 名以上，52 個對象中只有 1 個能被有信心地定位。Bailey 與 dark uncertainty 再補最後一刀：**就算帶了不確定度也可能不夠**——已回報的不確定度形狀重尾、且系統性遺漏只有互相比對才看得見的分量。

**地基缺一塊，而且缺的位置很具體。** 既有的官方基準（W3C PROV 的 Entity/Activity/Agent、Vertex ML Metadata 的 lineage）回答的是「這個數**從哪裡來**」；JCGM 那一組回答的是「這個數**有多可信、能不能拿來比**」。兩者正交，PROV 的詞彙裡沒有任何一格承載 uncertainty——`prov:Entity` 上掛什麼精度是完全開放的。所以 nova 現在的地基是**有出處、無精度**：可以完整重播一個數字怎麼被產生，卻無法回答「這個數字和那個數字誰大」是不是一句有意義的話。

**沒有多出來的東西。** 這兩層都是既有的、可引用的國際規範與同儕審查文獻，不是 nova 的拆解決定。要注意的分寸只有一個：JCGM 全系列的正式適用範圍是**物理量的量測**，把它整套搬到非物理的構念上（可靠度、品質、能力這類）在字面上是超譯——補這個缺口的正是心理計量學那一層（Cronbach & Meehl 的 nomological net、Messick 的兩大威脅、Sijtsma 的信度），而 Jacobs & Wallach 2021 是把這一層正式接到計算系統上的同儕審查橋梁。**兩層拼起來才是完整地基，各自都缺一半。**

**nova_fit**：**落點一：`observations[].type` 現在只有標量型別，這是漏洞的入口。**

現況（`規格/執行/保證/外部時間上限.claim.json`）：`{"observation_id": "elapsed_ms", "source": "VERIFIER", "path": "elapsed_ms", "type": "DURATION_MS"}`。`DURATION_MS` 是一個裸數字。judge 那邊 `{"predicate_id": "elapsed_bound", "operator": "LESS_THAN", "left": {"observation": "elapsed_ms"}, "right": {"const": 1500}}` 就是 JCGM 106 講的 **simple acceptance**——門檻附近錯誤率上界 50%。這不是理論風險：`elapsed_bound_ms: 1500` 對 `wall_ms: 300 + grace_ms: 200` 留了 1000ms 餘裕，那個餘裕**就是一個沒有被命名的 guard band**，它的寬度是憑感覺挑的，不是從量測離散度算出來的，而且沒有任何欄位記錄它為什麼是 1000 而不是 100。

建議新增 observation 型別 `MEASURED_QUANTITY`，封閉物件（沿用「預設拒絕 unknown fields」）：
- `value`（數）
- `standard_uncertainty`（數，對應 GUM 的 uc）
- `coverage_factor`（整數，對應 k；報 U 時必須同時報 k，這是 NIST TN 1297 政策第 4 條）
- `unit`（ASCII semantic id）
- `uncertainty_kind`：enum `TYPE_A` ／ `TYPE_B` ／ `NEGLIGIBLE_DECLARED` ／ `UNEVALUATED`

`NEGLIGIBLE_DECLARED` 這一格就是 VIM 2.9 NOTE 2 那個出口的落地：可以宣告可忽略，但必須**顯性宣告**並附理由欄位，不能靠省略欄位偷渡。`UNEVALUATED` 必須是可表達的——不然實作者會被迫編一個數字，那比誠實地說「沒評估」更糟。

**落點二：judge 的比較 operator 遇到 `MEASURED_QUANTITY` 必須要求一條 decision rule。**

ClaimSpec 新增 `decision_rule` 區塊（對應 JCGM 106 §3.3.12「documented rule that describes how measurement uncertainty will be accounted for」）：
- `mode`：enum `SIMPLE_ACCEPTANCE` ／ `GUARDED_ACCEPTANCE` ／ `GUARDED_REJECTION`
- `guard_band_w`（數）或 `guard_band_multiplier_r`（數，w = r·U，JCGM 106 §8.3.2.3 的常用 r=1）
- `max_false_accept_probability`（數）

`SIMPLE_ACCEPTANCE` 不禁止——JCGM 106 §8.2 承認它在容差區間遠寬於覆蓋區間時是合理選擇——但**必須被明寫**，因為寫出來的那一刻，「上界 50%」這件事就從隱形變成有人簽了名。

**落點三：這是一個純粹的加蓋，走 CLAUDE.md §4 的第二條合法動作。**

`MEASURED_QUANTITY` 與 `decision_rule` 是**已宣告、具命名空間、具版本、可協商的擴充點**，不是對既有能力增加拒絕。關鍵是舊元件的行為：一個只認得 `DURATION_MS` 的舊 judge，讀到 `MEASURED_QUANTITY` 時**必須回 typed `UNSUPPORTED_OBSERVATION_TYPE`，不得退化成「取 value 欄位直接比」**——後者正是「靜默降級後誤判為成功」的教科書案例，而且是最誘人的那一種，因為它「看起來能跑」。同理，舊 judge 讀到帶 `decision_rule` 的 claim 必須回 `UNSUPPORTED_DECISION_RULE`。這一格值得一條負控：**舊 judge ＋ 新型別 observation ＝ 必須 fail，且 `must_fail_exactly` 指名那個 typed code**。

**落點四：`claimspec_version` 從 0.2.0 進 0.3.0，語意單調要能被測試背書。**

擴充後的接受集合擴大（原本 `UNSUPPORTED_*` 的請求變成可執行），這符合 §4 的第二條。但必須有一格負控證明**既有 claim 的裁定結果一個字都沒變**——現有 13 份 `.claim.json` 在 0.3.0 的執行器下必須逐份 digest 相同、terminal 相同。這條測試若不存在，「語意單調」就只是文件裡的一句話。

**落點五：比較兩個 subject 時，「無法區分」必須是一個 first-class 的終態。**

現在 `expected_terminal` 只有 `ACCEPT` ／ `CLAIM_REJECTED`。Goldstein & Spiegelhalter 的處置逐字是「there is a strong case for reporting just this: namely that the performance indicator conveys little useful discriminatory information」——**「分不出來」是結論，不是失敗**。建議加終態 `INDISTINGUISHABLE`：當兩個 `MEASURED_QUANTITY` 的差值區間涵蓋 0 時回它，而不是硬判一邊贏。這一格直接擋掉「拿雜訊當進步」這個最常見的自欺路徑。另外，Goldstein & Spiegelhalter 明講「用各自的區間跟平均值重不重疊來判定」是錯的——**要對差值建區間**，這是實作時最容易寫錯的一行。

**落點六：接 W3C PROV，把不確定度的產生過程本身變成 lineage。**

`uncertainty_kind: TYPE_A`（由重複量測的統計離散度得出）本身就是一個 `prov:Activity`：它有輸入（n 次重複觀測）、有 agent（做評估的 verifier）、有輸出（uc）。`TYPE_B`（由先驗資訊得出）的 `prov:Entity` 是那份先驗的出處。這讓「這個 uc 是怎麼來的」和「這個 value 是怎麼來的」走同一套既有詞彙，不必發明第二套溯源機制——**這是 nova 已有的地基剛好能承接新地基的地方，不要另起爐灶**。`evidence.retain` 應同時保留 value 與 uc；`record_kind` 可加 `MEASUREMENT_RESULT`。

**落點七：重跑不穩不是要重試到綠，是 Type A 不確定度的一手資料。**

nova 已有「先寫會紅的測試 → 實際跑到指定的失敗 → 最小實作 → 跑綠」的節奏，也已有 `probe_extra_ms` 這類承認量測有雜訊的參數。把 flakiness 記成 `standard_uncertainty` 而不是當成待消除的噪音，是 Sijtsma 那條信度論點的直接落地：**重複量測的離散度是資料，不是障礙**。而 dark uncertainty 那條給出對應的機制設計：單一 verifier 自己算的 uc 原則上偵測不到自己的系統性偏差，要看見它必須有**獨立的**第二個 verifier 量同一題並比對——這正好是 nova「驗收權不在執行者手上」那條原則在量測層的同構物，值得寫成一格。

**落點八：construct validity 對應到 nova 已有的東西，不需要新機制。**

Cronbach & Meehl 的「Unless the network makes contact with observations, and exhibits **explicit, public** steps of inference, construct validation cannot be claimed」——ClaimSpec 的 `statement`（構念的自然語言陳述）到 `observations`（操作化）到 `judge`（推論規則）這條鏈，**已經就是一個明示且公開的 nomological net**，這是 nova 現有設計無意間對上權威層的一處。缺的只有一件事：`controls.negative` ＋ `must_fail_exactly` 承載的正是「recurrent negative results 會否證構念本身」這條失效判定——所以**負控是空的那份 claim，在量測理論上等於從未被驗證過的構念**。這一點可以直接寫進 ClaimSpec 的條件檢查，不必新增欄位。Messick 的兩大威脅則對應到兩個可記錄的缺口：`statement` 涵蓋而 `observations` 沒量到的面向是 construct underrepresentation；`observations` 量到但與 `statement` 無關的變異是 construct-irrelevant variance。這兩個缺口值得在 claim 裡有欄位承認其存在，而不是假裝為零。

**坑**：
- **最大的陷阱：把「加一個 uncertainty 欄位」當成做完了。** Bailey 2017 用 41000 筆真實量測證明，已回報的不確定度形狀是重尾（近乎 Cauchy），5σ 不一致的實測率 0.12 對上常態預期的 6×10⁻⁷——差五個數量級。有欄位不等於那個數字對。真正的驗證手段只有一個：獨立來源量同一題然後比對（dark uncertainty，Thompson & Ellison 2011）。單一 verifier 自己算的 uc **原則上偵測不到自己的系統性偏差**，因為它不在任何被列舉的分量裡。
- **k=2 ≈ 95% 這個換算在真實資料上不成立。** NIST TN 1297 政策約定 k=2 是為了**可比性與可還原性**（所以政策第 4 條強制「Report U together with the coverage factor k」——報了 k，讀的人才能還原 uc 自己重算），不是因為常態假設在你的資料上成立。把 k=2 直接讀成「95% 信心」再拿去做風險計算，是把一個約定誤讀成一個機率保證。
- **judge 的 `LESS_THAN` 遇到帶不確定度的量會靜默降級成 simple acceptance。** 這是最容易發生、也最難發現的失敗：程式碼看起來完全正常，測試會綠，只是在門檻附近的錯誤裁定機率上界是 50%（JCGM 106 §8.3.1.2 逐字）。舊 judge 讀到新型別必須回 typed `UNSUPPORTED_OBSERVATION_TYPE`，**不得取 value 欄位直接比**——後者正是「靜默忽略後誤判為成功」，也正是 CLAUDE.md §4 明文禁止的那件事。
- **現有的餘裕已經是沒有名字的 guard band。** `外部時間上限.claim.json` 的 `elapsed_bound_ms: 1500` 對上 `wall_ms: 300 + grace_ms: 200`，那 1000ms 餘裕的功能就是 guard band，但它沒有名字、沒有記錄為什麼是這個寬度、也沒有對應到任何量到的離散度。**先命名再調整**——把既有的隱性 guard band 顯性化，是這件事最便宜的第一步，而且不改任何行為。
- **排名比原始量脆弱得多，不確定度不會等比傳遞。** Marshall & Spiegelhalter 1998 的實測：52 個對象中只有 1 個能被有信心地放進後四分之一；排第 25 的對象真實名次 95% 區間橫跨 15–36；名次變動 23 位而底層比率無統計顯著變化。**「底層量有真實差異」推不出「名次可信」**——這兩件事在該論文裡同時成立。
- **用「各自的區間跟平均值重不重疊」來判定是錯的做法。** Goldstein & Spiegelhalter 1996 逐字：「We can see little justification for this, since the mean has no special status」，並舉出反例——兩個對象的 95% 區間都與平均重疊，但**兩者差值的區間不含 0**。要比就對**差值**建區間。這是實作 `INDISTINGUISHABLE` 終態時最容易寫錯的一行。
- **JCGM 全系列的正式適用範圍是物理量的量測。** 把 GUM／VIM 整套搬到非物理的構念（可靠度、品質、能力這類）上，在字面上是超譯，會踩到 CLAUDE.md §4「引不出官方出處的東西不是地基」。補這個缺口的是心理計量學那一層，而不是把 JCGM 的話說得更大聲。標錯的代價是拿沙子當混凝土。
- **信度高完全不保證效度。** 一個穩定地量錯東西的工具，重複量測離散度可以極小、`standard_uncertainty` 可以極漂亮，而它量的根本不是你以為的那個東西（Messick 的 construct-irrelevant variance）。**不確定度小是「這個數很穩」，不是「這個數對」**——這兩件事在量測理論裡是正交的兩個軸，任一條單獨都不夠。
- **別把「不確定度可忽略」做成省略欄位。** VIM 2.9 NOTE 2 確實留了這個出口，但條件是「considered to be negligible **for some purpose**」——是一個有主體、有用途、要被辯護的判斷。做成 optional 欄位的話，「沒評估」和「評估後認為可忽略」在資料上長得一模一樣，而這兩者的意義天差地遠。必須有 `NEGLIGIBLE_DECLARED` 與 `UNEVALUATED` 兩個不同的 enum 值，且 `UNEVALUATED` 必須是可表達的——否則實作者會被迫編一個數字。
- **誤差棒只涵蓋它被設計來涵蓋的那一種變異。** 題目抽樣的標準誤涵蓋不了模型多重性（Goldstein & Spiegelhalter 逐字：多個同樣 fit 的模型會給出不同的估計集合）、涵蓋不了構念錯配、也涵蓋不了 dark uncertainty。**報了誤差棒之後產生的那種「已經嚴謹了」的安全感，本身就是新的風險。**
- **被排序者會反過來優化排序。** Goldstein & Spiegelhalter 記錄的實例：引入評比後，會拉高預期風險的通報因子從 1.7% 跳到 7.6%。任何進入驗收判準的量測都會改變被量者的行為——這和 CLAUDE.md 已經寫死的「raw mutation kill rate 永遠不進驗收判準」是同一條規律的兩個實例，不是新道理。
- **幾份引用未能一手逐字核對，落地時要補。** Thompson & Ellison 2011（Springer 需登入）、Possolo & Iyer 2017（AIP 回 403）、Messick 1995（未取得可靠全文）、ISO/IEC 17025:2017 §7.8.6.1（付費標準）——這四項的內容是由摘要層級轉述與多方交叉引用確認的，措辭未經原文核對。要拿它們當地基寫進 nova 之前，應先取得一手文本，否則就是 §4 講的「標錯的代價是拿沙子當混凝土」。GUM、VIM、JCGM 106、NIST TN 1297、Cronbach & Meehl、Goldstein & Spiegelhalter、Marshall & Spiegelhalter、Bailey 這八份是本次**逐字核對過原文**的。

### 適應性重複評估（adaptive holdout reuse）下，離散低頻寬回饋的累積資訊量上界：官方地基與權威地基的盤點

**裁決**：兩層合起來是「缺一塊」，而且缺的正是量化那一塊。官方層存在但不對題：NIST FRVT 與 NIST SRE Challenge 確實有成文的提交限流、progress/test 雙子集、best-so-far leaderboard，FDA／Health Canada／MHRA 的 GMLP 原則 4 與 8 確實要求訓練集與測試集獨立——但這些全部是定性要求，沒有任何一份官方文件說出「重複回饋累積了多少資訊」「這樣的限流能撐幾次」。GMLP 講的獨立性是一次性的資料切分性質，完全沒觸及「同一測試集被重複評估、每次都拿到回饋」這個時間維度的依賴。所有可計算的上界都住在權威層。針對你的三個關鍵問題：（1）有現成公式，而且有兩條：Dwork 等人 arXiv:1506.02629 Theorem 17 的 I∞^β ≤ log(|Y|/β)（|Y| 是整段 transcript 的取值總數，對任意資料分布成立），以及 Russo-Zou 的 |E[φ_T − μ_T]| ≤ σ√(2 I(T;φ)) 配 I(T;φ)=H(T) ≤ log(輸出數)。（2）前提分別是：前者要求輸出落在有限集合、且 |Y| 必須按整段 transcript 計（adaptive composition 下 bits 相加）；後者要求 sub-Gaussian，且只給期望偏差不給高機率。（3）差距具體是三件事——量級上，transcript 界的預算是總釋出位元數 B ≲ ε²n，回答數對 n 是**線性**，而 DP 在 i.i.d. 下拿到 ε²n 的 max-information 界、計算可行時可回答約 n² 個查詢、不計成本可回答指數多個，差約一個 n 的因子；前提上，transcript 界不要求 i.i.d.、不要求機制隨機化、不要求你有權改造回饋，DP 的強界要求 i.i.d.（Rogers 等人把 (ε,δ)-DP 接上時同樣要求 product distribution）；可轉換性上，兩者互不蘊含，Dwork 等人的 Theorem 32 明說不是逆命題、且轉換需要知道輸出邊際分布，所以拿不到 i.i.d. 下 DP 那條界的 description-length 版本。最後一個必須寫進地基的教訓：Blum-Hardt 的 Ladder 之所以對提交數 k 只有 log 依賴，靠的不是「回饋離散」而是「回饋很少改變」（單調 ＋ η margin）；同樣的離散化用在每次都回真分數的機制上，boosting attack 仍給出 Ω(√(k/n)) 的偏差。

**權威層**：
- [Dwork, Feldman, Hardt, Pitassi, Reingold, Roth（2015）] **The reusable holdout：以 differential privacy 保護重複使用的 holdout** — DOI 10.1126/science.aaa9375（Science 349(6248):636-638, 2015）；理論版 arXiv:1411.2664（STOC 2015）
    補了：把「重複評估同一個 holdout」從民間常識變成有保證的機制：分析者只能看到經過擾動的統計量，DP 的穩定性直接轉成泛化保證。配套的理論版（STOC 2015）證明 n 個樣本可以正確回答「指數多」個 adaptively chosen 的期望值查詢，相對於一般經驗估計只能撐線性多個，是指數級的改善。這是整條線的起點，也是官方層完全沒有的東西：官方只說「要獨立」，這裡才說「重複用還能撐多久」。
    失效：指數多那條結果依賴計算上不可行的機制（private multiplicative weights）；計算可行的版本只到約 n² 個查詢。強保證要求 i.i.d. 樣本。且它要求你有權改造回饋機制（加噪音）——只能被動觀察 transcript 的場景套不上。
- [Dwork, Feldman, Hardt, Pitassi, Reingold, Roth（NIPS 2015）] **approximate max-information：把 description length 與 differential privacy 統一起來** — arXiv:1506.02629（NIPS 2015, Generalization in Adaptive Data Analysis and Holdout Reuse）
    補了：這一篇直接回答了「離散低頻寬回饋有沒有現成上界公式」。Theorem 17：輸出落在有限集合 Y 的演算法，對任意 β>0 有 I∞^β(A,n) ≤ log(|Y|/β)——注意 |Y| 是**整段 transcript 的取值總數**，不是單次回答。Theorem 9 更原始：P[S∈R(A(S))] ≤ |Y|·β，純 union bound。Theorem 13 把 max-information 轉成壞事件機率：P[(S,A(S))∈O] ≤ 2^k·P[S×A(S)∈O] + β。Theorem 15：description length 在 adaptive composition 下相加（bits 相加、|Y| 相乘）。對照組 Theorem 19：ε-DP 給 I∞ ≤ log e·εn（任意分布）；Theorem 20：i.i.d. 下 I∞^β ≤ log e(ε²n/2 + ε√(n ln(2/β))/2)——是 ε²n 不是 εn。
    失效：作者自己明講兩件事。① description length 與 pure DP 互不蘊含：低 description length 不保證 DP（DP 連單一個體的少數 bit 都不准洩），DP 也不限制輸出長度。② Theorem 32 不是 Theorem 30 的逆命題：把有界 max-information 轉回 randomized description length 的建構會產生一個**新的**演算法、且需要知道輸出的邊際分布，因此**無法**由此推出 i.i.d. 情形下 Theorem 20 那條 ε²n 界的 description-length 版本。另外 Theorem 20 的強界要求 i.i.d.，非 i.i.d. 只剩 εn 那條弱界。
- [Avrim Blum, Moritz Hardt（ICML 2015）] **The Ladder：把 leaderboard 的整段 transcript 壓縮成有限位元數** — arXiv:1502.04585（ICML 2015, Proceedings of the 32nd ICML, Vol. 37）
    補了：這是「有限 transcript 上限」最乾淨的實作範例，而且它的證明核心（Claim 3.2）就是一個明擺著的編碼／數 transcript 論證。機制本身極簡：只有當新提交的經驗損失比目前最佳低過 η 才釋出、且釋出值四捨五入到 η 的整數倍，否則原封不動重播舊值。因為分數單調下降且刻度是 η，整段互動最多只會改變 ⌈1/η⌉ 次，於是整棵 adaptive tree 可用 B = (1/η + 2)·log(4t/η) 個 bit 唯一編碼，對這 2^B 個節點做 union bound ＋ Hoeffding 得 Theorem 3.1：Pr{|min_i R_D(f_i) − R_t| > ε+η} ≤ exp(−2ε²n + B + 1)。取 η = O(n^{−1/3}log^{1/3}(kn)) 得 leaderboard error O(log^{1/3}(kn)/n^{1/3})，對提交數 k 只有 log 依賴。**關鍵教訓**：省 bit 的不是「回饋離散」，是「回饋很少改變」；把同樣的 rounding 用在每次都回真分數的 Kaggle-style 機制上，Theorem 5.1 的 boosting attack 只要 k 次隨機提交就能造出 1/2 − Ω(√(k/n)) 的假優勢。摘要中作者對現行做法的評語是幾個字：poorly understood heuristics。
    失效：① 它保證的是被**弱化過**的 leaderboard accuracy（只保證「目前為止最佳」那個數字準），不是每個提交的估計都準——後者在 k 大時被計算硬度結果排除，作者明說是為了繞開硬度才改判準。② 誤差 n^{−1/3} 比非適應的 n^{−1/2} 差；且 Theorem 3.3 給出 Ω(√(log k / n)) 的資訊論下界，即使函數非適應選定也逃不掉。③ 假設 i.i.d. 樣本、有界 loss。④ 每隊一個 Ladder 實例的變體需要假設參賽者不用多帳號；作者提供的保守變體才不需要這個假設。
- [Daniel Russo, James Zou（AISTATS 2016；期刊版 IEEE Trans. Inf. Theory 66(1):302-323, 2020）] **Information usage：以互資訊界定探索造成的偏差** — arXiv:1511.05219；期刊版 IEEE Transactions on Information Theory 66(1):302-323 (2020)
    補了：Proposition 1：若每個 φ_i − μ_i 是 σ-sub-Gaussian，則 |E[φ_T − μ_T]| ≤ σ√(2 I(T;φ))。關鍵推論直接對上「封閉 enum」的問題：當 T 完全由 φ 決定時 I(T;φ) = H(T) ≤ log(可能輸出數)——所以離散回饋的資訊量上界就是 transcript 空間的對數，不需要任何 DP 機制、不需要 i.i.d.、也不要求你能改造機制，只要能數 transcript。若 φ_i 是 n 筆 i.i.d. 樣本的平均，界變成 σ√(2I/n)。Proposition 7 另給適應性的代價尺度：加噪音時 k^{1/4}/√n，不加噪音時可惡化到 Ω(σ√k/n)——與 Blum-Hardt 觀察到的 Kaggle 機制隨 √k 退化是同一件事。作者也明說這框架適用於非獨立、結構化的資料。
    失效：① 只界**期望偏差**，不是高機率尾界。Dwork 等人在 arXiv:1506.02629 明確反駁：互資訊為 k 時，壞事件機率仍可高達 k/(2 log(1/δ))，所以互資訊界撐不起高機率保證。② 需要 sub-Gaussian；重尾要換成 sub-exponential 版本（Prop 9）或不同 σ_i 的版本（Prop 8）。③ 它是**描述性**工具而非機制：對 worst-case adversarial analyst 不提供設計保證，作者自述與 DP 是互補而非替代。④ 附錄 I 指出 max-information 在 rank-selection 情境下有反直覺行為——訊號越強、真實偏差越小，max-information 反而趨於無窮——所以 max-information 不能拿來評價某個具體選擇規則的實際偏差。
- [Ryan Rogers, Aaron Roth, Adam Smith, Om Thakurta（FOCS 2016）] **(ε,δ)-DP 與 approximate max-information 的橋，以及它的前提** — arXiv:1604.03924（FOCS 2016）
    補了：把「DP → 有界 max-information」從 pure (ε,0)-DP 擴到 approximate (ε,δ)-DP，使得帶 δ 的機制也能接上 post-selection 的有效性保證與 p-value 校正。這是把 DP 那條路用在實務機制上的必要一塊。
    失效：作者明確標出前提：這條擴充只在**輸入來自 product distribution** 時成立。一旦資料不是獨立抽樣（時序、網路、同一受試者多筆），這條橋就斷，只能退回 pure DP 對任意分布的弱界 I∞ ≤ log e·εn。
- [Moritz Hardt, Jonathan Ullman（FOCS 2014）；Thomas Steinke, Jonathan Ullman（COLT 2015）] **適應性查詢數量的計算硬度上限** — arXiv:1408.1655（FOCS 2014）；arXiv:1410.1228（COLT 2015）
    補了：給整個框架畫出天花板：在標準硬度假設下，沒有計算可行的演算法能對 n 個樣本正確回答 n^{3+o(1)}（Hardt-Ullman）個適應性統計查詢；Steinke-Ullman 用 interactive fingerprinting codes 把界收緊到約 n²，與 DP 機制達到的 n² 對上，因此 n² 基本上就是可行演算法的極限。這解釋了 Blum-Hardt 為什麼必須改用較弱的 leaderboard accuracy 判準。
    失效：是**條件性**結果，建立在標準密碼學硬度假設（one-way functions／fingerprinting codes）之上，不是無條件下界；而且只約束計算可行的機制，不約束計算不可行的機制（後者仍可回答指數多個查詢）。
- [Roelofs, Shankar, Recht, Fridovich-Keil, Hardt, Miller, Schmidt（NeurIPS 2019）] **120 場 Kaggle 競賽的 overfitting 實測（meta-analysis）** — NeurIPS 2019, https://proceedings.neurips.cc/paper_files/paper/2019/file/ee39e503b6bedf0c98c388b7e8589aca-Paper.pdf
    補了：這是「離散低頻寬回饋在真實世界會不會爆」的唯一大規模實證。取 MetaKaggle 中提交數 ≥1000、且該評分指標至少有 10 場競賽的分類競賽，共 120 場，比對 public 與 private 分數。結論是幾乎沒有實質 overfitting 跡象，public 與 private 對應良好；即使聚焦在前 10% 的提交，效應量通常也小於 1% 分類正確率。這把最壞情況理論與實務拉開的距離量化了。
    失效：作者自己標出例外：出事的離群競賽通常有病理——non-i.i.d. 的資料切分，或（有效）測試集太小。所以這個「沒事」的結論不能外推到小 holdout 或非獨立切分的情境，也不能被拿來取消預算——它只說明最壞情況的界在典型情境下是鬆的。
- [Jacob Whitehill（2017）] **高精度數值回饋通道的完全崩潰：log-loss oracle 攻擊** — arXiv:1707.01825
    補了：實測示範回饋頻寬一旦不受限會發生什麼：對成批樣本反覆查詢 log-loss 分數，可逐步反推出全部 ground-truth 測試標籤。作者在真實 Kaggle 競賽第一階段取得 log-loss 0.00000、848 名參賽者中排名第 4，完全沒有訓練任何真正解題的分類器。這是「封閉 enum vs 連續高精度分數」兩者差別的具體代價。
    失效：攻擊要求回饋是高精度連續數值、且攻擊者能自由控制提交批次的組成。回饋若被離散化、加噪、或提交次數受限，攻擊效率大幅下降——這正是為什麼離散化是必要條件（但由 Blum-Hardt 的 boosting attack 可知，它不是充分條件）。

**nova_fit**：回饋預算必須是一級的、可被外部裁定的資料結構，不能是散在文件裡的告誡。具體形狀：① 新增 `feedback_budget` object，欄位 `transcript_space_log2`（整段 transcript 的位元上限 B）、`spent_bits`、`round_count`、`holdout_size_n`、`target_error_eps`、`iid_assumed`（bool）、`enum_cardinality`。B 的合法性判準直接落在 Blum-Hardt 的 exp(−2ε²n + B) 形式上：`spent_bits` 必須維持在 ε²·n 之下，否則沒有任何界。② 回饋通道本身必須是**已宣告、封閉的列舉型別**：`verdict_enum` 的取值集合固定、schema 對該 object `additionalProperties: false`（呼應「每個 object 預設拒絕 unknown fields」）；任何不在列舉內的取值一律 typed `UNSUPPORTED_*`，不得靜默降級成「大概是這個意思」。③ 記帳要記 transcript 不記單次：每輪 append 一筆 `feedback_event{round_index, enum_value, bits_charged}`，且必須實作 Ladder 式的計費規則——維護 `last_released_value` 與 `improvement_margin`（η），只有當釋出值**改變**時才計整筆，未改變時重播舊值並計零；這是把「省 bit 靠答案很少變、不是靠答案很粗」寫進程式而不是寫進文件。④ 閘：`spent_bits > transcript_space_log2` 時回饋通道 fail-closed，回 typed refusal 而非繼續給答案。這條要有會 fail 的測試背書，負控至少三格——(a) 把 `verdict_enum` 換成連續數值後，同一支 boosting 式腳本能把估計值推偏（證明離散化的閘真的在擋東西）；(b) 拿掉 `improvement_margin` 讓每輪都釋出真值後，偏差隨輪數以 √k 成長（證明計費規則不是裝飾）；(c) 防恆真格：預算充足時正常回饋不被誤擋。⑤ claim 必須把**前提**一起記錄成欄位而非散文：`iid_assumed`、`enum_cardinality`、`holdout_size_n`、以及 `side_channels_declared`（列出除了 enum 之外還有哪些通道會外洩訊息——錯誤訊息、耗時、排名位置、重試次數都算通道；Whitehill 的結果說明只要漏一條高精度通道，enum 的保護整個作廢）。前提不成立或未宣告時，只能宣稱 description-length 那條弱界（它不需要 i.i.d.），不得宣稱 DP 等級的保證。⑥ 對應 CLAUDE.md 既有的不可違反條款：`feedback_budget`、`verdict_enum` 定義、`improvement_margin` 全部必須放在候選執行者寫不到的地方——候選者若能改 budget 或改 enum，整個界形同虛設，這與「不能改 budget、不能改 criterion」是同一條規則的延伸。⑦ 誠實標註降級：目前業界對「可行演算法最多約 n² 次適應性查詢」有條件性硬度背書，所以 nova 不得在任何 claim 裡宣稱能安全支撐超過該量級的互動輪數。

**坑**：
- 把「回饋是封閉 enum」直接當成「資訊量很小」。上界是整段 transcript 的位元數：每輪 m 選一、共 k 輪，naive 上界是 k·log₂m，對 k 是線性成長。不記錄 k、不設 k 上限，等於沒有任何界。
- 把 rounding 當成保護。Kaggle-style 機制就是每次回四捨五入後的真分數，Blum-Hardt 的 boosting attack（Theorem 5.1）證明只要精度到 1/√n，k 次隨機提交就能造出 1/2 − Ω(√(k/n)) 的假優勢。真正省 bit 的是「答案很少改變」（單調 ＋ η margin），不是「答案很粗」。
- 逐次計費而不是按 transcript 計費。description length 在 adaptive composition 下是相加的（arXiv:1506.02629 Theorem 15），每輪獨立算一次會系統性低估總量。
- 拿互資訊界去做高機率保證。Russo-Zou 的 Proposition 1 只界期望偏差；Dwork 等人明確指出互資訊為 k 時壞事件機率仍可高達 k/(2 log(1/δ))。要高機率保證必須用 max-information。
- 反過來拿 max-information 去評價某個具體選擇規則的實際偏差。Russo-Zou 附錄 I 給出反直覺案例：訊號越強、真實偏差越小，max-information 反而趨於無窮。max-information 是 worst-case 設計工具，不是診斷工具。
- 忽略 i.i.d. 前提。DP 那條 ε²n 的強界要求 i.i.d.；Rogers 等人把 (ε,δ)-DP 接上 approximate max-information 時同樣要求 product distribution。資料若有時序、結構或同一來源的多筆重複，只剩 εn 那條弱界。GMLP 原則 4 講的「所有依賴來源」正是這件事。
- 以為可以把 DP 的保證「翻譯」成 transcript 上限。Dwork 等人 Theorem 32 明說那不是逆命題：轉換會產生新的演算法、且需要知道輸出的邊際分布，因此拿不到 i.i.d. 情形下 DP 那條界的 description-length 版本。兩者由 approximate max-information 統一，但互不蘊含。
- 承諾超過計算硬度上限的互動輪數。Hardt-Ullman 與 Steinke-Ullman 在標準硬度假設下把可行演算法的適應性查詢數壓在約 n²；超出這個量級的保證在計算可行的前提下不成立。
- 漏算側通道。Whitehill 用 log-loss 這一條高精度數值通道就在真實競賽裡把標籤全部還原。封閉 enum 必須是**唯一**的回饋通道；錯誤訊息、執行耗時、排名位置、重試次數、甚至「被拒絕」本身都是通道，沒宣告就沒計費。
- 拿實測結果取消預算。Roelofs 等人在 120 場 Kaggle 競賽發現幾乎沒有 overfitting、效應量小於 1% 正確率——但出事的離群競賽全是 non-i.i.d. 切分或有效測試集太小。「典型情況沒事」不等於「界可以拿掉」，它只說明最壞情況的界在典型情境下是鬆的。
- 把官方的限流條文當成量化保證。NIST FRVT 的「每四個月一次」與 NIST SRE 的「每天三次」都沒有附帶任何誤差保證或推導；Blum-Hardt 對這類做法的評語是 poorly understood heuristics。引用它們可以證明「業界確實用限流」，不能證明「限這麼多就夠」。

### 證明「不低於門檻」的統計方法：非劣性檢定（non-inferiority）與等效性檢定（equivalence／TOST）——雙邊範圍值 claim 的地基盤點

**裁決**：兩層都查到了，而且都很厚——但地基「缺一塊」，缺的不是統計而是領域轉移的正當性。官方層（ICH E9／E10、FDA NI 2016、FDA BE、FDA Adaptive 2019、EMA CPMP/EWP/482/99 與 2158/99）把非劣性／等效／TOST／CI-檢定對偶／事前 margin／期中偷看這六件事全部規定得毫無模糊空間，可以直接當混凝土；權威層（Schuirmann 1987、Berger & Hsu 1996、Lakens 等 2018、Johari 等 2022、Howard 等 2021、Ramdas 等 2023、Rothman & Greenland 2018、Deng 等 2013、Andrews 2000）補齊了官方沒寫的兩件事——為什麼對偶關係成立以及它在什麼形狀下不成立（Berger & Hsu：1−2α 那條捷徑只對 TOST 成立，一般情況會算錯覆蓋率）、邊跑邊看要怎麼合法（anytime-valid 換寬度買停止自由）、bootstrap 為何恰好在門檻附近最不可信（Andrews：參數在邊界時不一致）。缺的那一塊是：這整套地基全部出自臨床試驗法規，沒有任何一份官方文件講軟體工程或 LLM 評測；因此「把 margin、TOST、CI 對偶搬到 nova 的驗收閘」這個動作本身是 nova 的組合契約，不是可引出處的地基，必須照 CLAUDE.md 第四條登記進 `交接.md` §十九 的已知降級清單，而不是宣稱有官方背書。反過來說也有一塊「多了」：FDA 的 M1／M2 兩層 margin 依賴「對照組相對安慰劑的歷史效果」與 assay sensitivity，這兩個前提在 nova 場景中沒有對應物（沒有安慰劑、沒有歷史試驗），硬搬會變成拿沙子當混凝土——可移植的是「margin 事前釘死＋CI 上界比對＋雙邊拆成 IUT」這個骨架，不是 M1／M2 的具體推導。

**權威層**：
- [Donald J. Schuirmann（FDA），J. Pharmacokinet. Biopharm. 15(6):657–680，1987] **TOST（two one-sided tests）程序的原始論文：A comparison of the Two One-Sided Tests Procedure and the Power Approach for assessing the equivalence of average bioavailability** — DOI 10.1007/BF01068419（https://link.springer.com/article/10.1007/BF01068419）
    補了：官方文件只寫「用 TOST／用 CI」，這篇寫為什麼不能用另一種看起來很自然的做法。它拿 TOST 對比當時流行的 power approach（先做「無差異」檢定不顯著，再檢查估計 power ≥ 0.80 就宣告等效），證明後者是錯的方法論；並證明 TOST 的結論與 Westlake 基於 1−2α 信賴區間的做法完全一致——這就是「區間落在 margin 之內 ⇔ 通過」這條對偶關係的來源，也是為什麼 BE 用 90% CI 搭配 α=0.05 的兩個單邊檢定。ICH E9 §3.3.2 那句「以無差異檢定不顯著來宣告等效是 inappropriate」，權威層的推導就在這裡。
    失效：論文自己給了條件式結論而非無條件勝出：在 α=0.05 作為單邊檢定名目水準的特定選擇下，TOST「has uniformly superior properties to the power approach in most cases」——是 in most cases，不是全部。另一個實務失效點是 TOST 本質上是保守的交集聯集檢定，當變異很大而 margin 很窄時它的檢定力會塌到接近 0，此時「沒通過」完全不代表「有差異」，只代表資料量不足以做任何決定；把這種結果讀成「品質退步了」是誤讀。
- [Roger L. Berger（North Carolina State Univ.）與 Jason C. Hsu（Ohio State Univ.），Statistical Science 11(4):283–302，1996] **Bioequivalence trials, intersection-union tests and equivalence confidence sets** — DOI 10.1214/ss/1032280304（https://projecteuclid.org/journals/statistical-science/volume-11/issue-4/Bioequivalence-trials-intersection-union-tests-and-equivalence-confidence-sets/10.1214/ss/1032280304.full）
    補了：這是「區間落在 margin 之內就等於通過」這條對偶關係唯一一份把邊界條件講清楚的權威文獻，而且它的結論與大眾直覺相反。兩個貢獻：①把等效／非劣性統一成 intersection-union test（IUT）——多個單邊子假設全部要拒絕才算通過，而 IUT 的 size 不會超過各子檢定的 α，所以「同時要求 token 上界降低『且』品質下界不低於門檻」這種雙邊複合 claim，不需要對 α 做多重比較校正。這一點對本題的雙邊 claim 是直接可用的地基。②戳破一個廣泛誤解：認為 size-α 的等效檢定「一般而言」對應到 100(1−2α)% 信賴集合，是錯的，而且這個誤解「will be shown to lead to incorrect statistical analysis」；正確對應的信賴集合提供的是 100(1−α)% 覆蓋。他們並導出一個比當時 FDA／EC 指引所規定的檢定更有檢定力的檢定。
    失效：明確指出失效條件：1−2α 那條對偶捷徑只在 TOST 這個特定形狀成立，不能推廣。一旦你不是用標準 TOST（例如改用更有檢定力的檢定、或 margin 的形狀不是對稱區間、或參數是比值而非差值），「先算個 90% CI 再看它有沒有落進 margin」就不再等價於一個 size-α 的檢定，覆蓋率會錯。換句話說：對偶關係是一條要驗證的性質，不是一條可以到處套用的定律。
- [Daniël Lakens、Anne M. Scheel、Peder M. Isager（Eindhoven University of Technology），Advances in Methods and Practices in Psychological Science 1(2):259–269，2018] **Equivalence Testing for Psychological Research: A Tutorial（以及同作者 2017 的 practical primer）** — DOI 10.1177/2515245918770963（https://journals.sagepub.com/doi/10.1177/2515245918770963）；同作者 primer 為 DOI 10.1177/1948550617697177

**nova_fit**：落到 nova，這件事的形狀是「把一個雙邊範圍值 claim 的所有自由度在資料產生之前凍結成一份可雜湊、可比對的規格」，而 ClaimSpec 閘本來就是唯一有接受權的地方，所以它應該長成 ClaimSpec 的一個 typed 變體而不是另建一套。

建議的資料結構（欄位名 ASCII，值域用 failure code 風格的大寫常數）：

```
ClaimSpec.threshold_claim
├─ claim_kind          : NON_INFERIORITY | EQUIVALENCE | SUPERIORITY
│                        （未知值 → UNSUPPORTED_CAPABILITY，不得靜默當 SUPERIORITY）
├─ subclaims[]         : 雙邊 claim 拆成 N 個單邊子 claim，全過才算過
│   ├─ metric_id       : 語意 id（跨程序）
│   ├─ direction       : UPPER_BOUND | LOWER_BOUND
│   ├─ margin          : { value, unit, basis }   ← basis 是「為什麼是這個數」的外部依據
│   └─ estimand        : PAIRED_DIFF | INDEP_DIFF | RATIO_LOG
├─ alpha               : 每個單邊子檢定的水準（Berger & Hsu：IUT 不需多重校正）
├─ ci_method           : STUDENT_T | TOST_90 | BOOTSTRAP_BCA | CONFIDENCE_SEQUENCE
├─ coverage            : 明寫 0.90 / 0.95，禁止由 alpha 隱式推導
├─ design              : { pairing: PAIRED|INDEPENDENT, pair_key, order_randomized: bool }
├─ looks_policy        : FIXED_N | GROUP_SEQUENTIAL | ANYTIME_VALID
├─ planned_n           : precision-based（目標區間半寬 → 反推 n），非 power-based
└─ frozen_at           : { commit_sha, timestamp }   ← 必須早於任何一筆量測的 timestamp
```

四個把「規矩由結構承載」落實的機制點：

一、**凍結點要由結構強制，不由人記得。** `frozen_at.commit_sha` 與量測結果的產生時間之間的先後，是可以寫成會 fail 的測試的：任何一筆 `subclaims[].margin` 的變更若其 commit 時間晚於該 claim 第一筆 evidence，閘必須拒絕。這正好是 CLAUDE.md「候選執行者不能改 criterion」那條的量化版本，而且它有外部權威背書（EMA CPMP/EWP/482/99：事後選 ∆ 一定能選到通過的那個值）。

二、**方向不對稱要寫進狀態機。** NON_INFERIORITY → SUPERIORITY 的升級是合法的（封閉檢定，α 不變）；SUPERIORITY → NON_INFERIORITY 的降級不合法，除非 margin 早已在 `frozen_at` 之前存在。這是一條 typed transition，不是一段文件。

三、**`ci_method` 與 `coverage` 的組合要有負控。** 最容易出的錯是 TOST 用了 95% CI（應為 90%，因為兩個單邊各 α），以及在 `claim_kind = NON_INFERIORITY` 且真實效果貼近 margin 時使用 BOOTSTRAP_BCA（Andrews 2000：邊界參數上 bootstrap 不一致）。這兩格都能寫成事前命名的 mutation ＋ 指定 predicate 來殺——符合 CLAUDE.md 對 mutation testing 的既有立場（不用分數，用點名）。

四、**`looks_policy` 決定誰有權中途看結果。** FIXED_N 的 claim 一旦被中途讀取過就必須自動降級（呼應 SLSA Source Track 的「記錄連續性、讓繞過留下痕跡」思路）；要保留邊跑邊看的自由，就得在 `frozen_at` 之前宣告 ANYTIME_VALID 並改用 confidence sequence，代價是同樣資料下的區間更寬。把這個代價寫進結構，執行者就沒有「先偷看再決定用哪種區間」的空間。

五、**`planned_n` 用精度而非檢定力反推**（Rothman & Greenland 2018；ICH E9 §3.5 對等效試驗本來就是這樣定義的）。因為這類 claim 的用途是決策，判準應該是「區間窄到足以做決定」而不是「有機會抓到差異」；相對地，`subclaims` 全數未通過時，正確的 typed 回覆是 `INCONCLUSIVE_INSUFFICIENT_PRECISION` 而不是 `FAILED`——把「沒證明不低於門檻」誤報成「低於門檻」是這整套方法最常見的誤讀，值得一格獨立的負控。

- 【關鍵問題 1 的直接答案：margin 必須事前決定嗎？必須，而且官方對事後改 margin 的判決是「不足以支持該宣稱」而非「需要校正」。】ICH E10 §1.5.1.1 逐字「Prior to the trial, an equivalence or non-inferiority margin, sometimes called delta, is selected」；ICH E9 §3.3.2 要求 margin 寫進 protocol，§5.1 補上「Only results from analyses envisaged in the protocol (including amendments) can be regarded as confirmatory」。FDA 2016 對事後定 margin 逐字：「An unplanned determination of non-inferiority following failure to show superiority, when the margin was not determined until results of the trial were known, would not be sufficient for demonstrating non-inferiority of the test drug」，並另有一句封住事後調整分析：「Applying post-hoc adjustments developed at the time of analyzing the NI trial would not be appropriate」。理由由 EMA CPMP/EWP/482/99 講得最白：「It is always possible to choose a value of ∆ which leads to a conclusion of equivalence or non-inferiority if it is chosen after the data have been inspected」，而且該文特別點出這個病不是型一誤差膨脹——「there does not appear to be a statistical multiplicity issue per se related to this switch of objective, that does not diminish the difficulties associated with the post hoc definition of ∆」。意思是：你無法用任何 alpha 校正把事後選 margin 救回來，因為壞掉的是選擇程序而不是誤差率。連 coverage（90%/95%）也必須同時事前釘死。唯一的例外方向是官方明講可接受的：資料出來後區間比要求還窄，直接用實際區間沒問題（「There is no question here of a data-derived selection process」）——變窄可以，放寬不行。
- 【關鍵問題 2 的直接答案：有，正式名稱是 precision-based sample size（以精度而非檢定力規劃規模），而且對等效／非劣性而言這是官方預設而不是替代方案。】ICH E9 §3.5 逐字：等效或非劣性試驗的樣本數「should normally be based on the objective of obtaining a confidence interval for the treatment difference that shows that the treatments differ at most by a clinically acceptable difference」——官方已經直接把樣本數定義成區間寬度問題。權威層的通則化是 Rothman & Greenland, Epidemiology 29(5):599–603, 2018（DOI 10.1097/EDE.0000000000000876），主張以目標精度反推研究規模並給出公式。同一節還有一個常被忽略的官方警告：以「真實差為 0」來評估等效試驗的檢定力，會低估所需樣本數；非劣性亦然（若新品效果實際低於對照組）。實務推論：規劃時不要假設兩者一樣好。
- 【關鍵問題 3 的直接答案：最少要在資料產生之前釘住七樣。】① claim 的類型與方向（非劣性／等效／優越性，以及哪一邊是上界哪一邊是下界）——ICH E9 §3.3.2 要求 protocol 明寫「explicit intention」；② 每個方向的 margin 數值與其外部依據（依據必須獨立於本次資料）；③ 信賴區間的 coverage 與單邊/雙邊（EMA 482/99 明講 coverage 也要同時事前選）；④ 區間的計算方法（t／TOST／bootstrap 變體／confidence sequence），因為方法換了對偶關係就可能不成立（Berger & Hsu 1996）；⑤ 設計是配對還是獨立、配對鍵是什麼、順序是否隨機化；⑥ 看結果的政策（固定 n／group sequential 的看幾次何時看／anytime-valid），FDA Adaptive 2019 逐字「details of the design should be completely prespecified」；⑦ 分析母體與缺失值處理規則——這一條在非劣性框架下特別要命，因為偏誤方向是反的（見下一格）。少釘任何一樣，都留下一個事後可以被說成「本來就是這樣打算的」的自由度。
- **偏誤方向在非劣性框架下是反的，這是與一般直覺最衝突的一格。** ICH E9 §3.3.2 逐字：「The equivalence (or non-inferiority) trial is not conservative in nature, so that many flaws in the design or conduct of the trial will tend to bias the results towards a conclusion of equivalence」；FDA 2016 講得更具體：不遵從、端點誤判、樣本流失都會「bias the results toward no treatment difference (success)」。在優越性框架下，草率的執行讓你證不出東西（安全的失敗）；在非劣性框架下，草率的執行讓你「證出」不低於門檻（不安全的成功）。對 nova 的直接後果：量測雜訊、環境不穩、任務抽樣不當，全部都會讓「品質下界不低於門檻」這半邊的 claim 更容易通過。所以這類 claim 需要的品質控管比一般驗收更嚴，而不是更鬆。
- **「沒有顯著差異」不等於「等效」，這條官方寫成禁令。** ICH E9 §3.3.2 逐字：「Concluding equivalence or non-inferiority based on observing a non-significant test result of the null hypothesis that there is no difference between the investigational product and the active comparator is inappropriate.」Schuirmann 1987 的整篇論文就是在拆解這個錯誤（power approach）。對應到工程現場：跑了一批任務、兩種技術的品質分數 p 值不顯著，這什麼都沒證明——很可能只是樣本太少。正確的 typed 結果是「精度不足、無法裁決」，不是「通過」。
- **TOST 的 CI 對偶用的是 1−2α 而不是 1−α，而且這條捷徑只對 TOST 成立。** FDA BE 指引用 90% CI 搭配兩個各 5% 的單邊檢定（不是 95%）；Berger & Hsu 1996（DOI 10.1214/ss/1032280304）明講「size-α 等效檢定一般對應 100(1−2α)% 信賴集合」這個信念是錯的、而且「will be shown to lead to incorrect statistical analysis」，正確對應的信賴集合覆蓋是 100(1−α)%。實務規則：一旦不用標準 TOST（改用更有力的檢定、margin 不對稱、參數是比值而非差值），就不能再假設「算個區間看它落不落進 margin」等價於一個 size-α 的檢定——對偶關係是要逐案驗證的性質，不是定律。
- **雙邊複合 claim（用量上界降低『且』品質下界不低於門檻）不需要多重比較校正——因為它是 intersection-union test 而不是聯集。** Berger & Hsu 1996 把等效性統一成 IUT：所有子假設都要被拒絕才算通過，而 IUT 的 size 不超過各子檢定的 α。這與「同時檢查多個指標、任一顯著就宣稱」的情境正好相反，後者才需要 Bonferroni 之類的校正。搞反方向會導致兩種錯誤：不該校正時校正（白白損失檢定力），或該校正時不校正（型一誤差失控）。
- **「同一組任務跑兩種技術」屬於配對／交叉設計（受試單位自己當自己的對照），它省樣本，但代價是 carry-over。** ICH E9 §3.1.2 給了官方的省樣本論證（「acts as his own control ... reduces the number of subjects ... sometimes to a marked extent」），也給了失效條件（「Crossover designs have a number of problems that can invalidate their results. The chief difficulty concerns carryover」）。在軟體場景中 washout 幾乎不可能做乾淨：快取、暖機、狀態殘留、共用隨機種子、任務順序帶來的學習效應都會殘留。Shi & Ye（arXiv:2302.01246）證明當 carry-over 滿足特定符號條件時只損失檢定力而不膨脹型一誤差，但符號反過來就不成立——而符號反過來的方向（先跑的技術讓後跑的看起來更好）正好會偏向宣告非劣性，與上面第四格的偏誤方向疊加。最低限度的防護是順序隨機化，並把順序當共變量檢查。
- **配對省下的樣本量不是常數，完全取決於同一單位在兩次量測間的相關性。** 相關性高時配對威力很大，相關性接近 0 時配對等於白做（Deng 等 2013 CUPED，DOI 10.1145/2433396.2433413，同一原理）。所以「用配對所以省一半樣本」是沒有根據的口號；正確做法是先實測相關性再決定規模。另有一個反噬情境：若用來配對／調整的前期資料本身已被處理污染，調整會引入偏誤而不是降低變異。
- **bootstrap 恰恰在最需要它的那一格失效：真實效果貼著 margin 的時候。** 非劣性／等效的虛無假設就坐在參數空間邊界上，而 Andrews, Econometrica 68(2):399–405, 2000（DOI 10.1111/1468-0262.00114）證明參數在邊界時 bootstrap 不一致——覆蓋率不會隨樣本數收斂到名目水準。同時 percentile bootstrap 只有一階正確，偏態指標（任何右尾很長的用量型指標都是）會系統性偏一邊；要二階正確得用 BCa 或 bootstrap-t（DiCiccio & Efron 1996，DOI 10.1214/ss/1032280214），而二階正確性又建立在光滑性與漸近常態上。結論：bootstrap 不是萬用逃生門，把它當預設會在決策最難的那一格靜默出錯。
- **邊跑邊看確實會讓固定樣本的區間失效，而且壞掉的不只是 p 值，點估計與覆蓋率一起壞。** FDA Adaptive 2019 逐字：期中與最終各用 0.025 則「the overall chance of the trial yielding a Type I error would exceed 2.5 percent」；更關鍵的一句是「a conventional end-of-trial treatment effect estimate such as a sample mean that does not take the adaptations into account would tend to overestimate the true population treatment effect ... confidence intervals ... may not have correct coverage probabilities」。Johari 等（arXiv:1512.04922 / DOI 10.1287/opre.2021.2135）對業界 A/B 情境的判詞是傳統推論在連續監看下「wholly unreliable」。業界的處理方式不是禁止偷看，是換一套在所有停止時間都有效的推論：confidence sequence（Howard 等 2021，DOI 10.1214/20-AOS1991）與 e-process／SAVI（Ramdas 等 2023，DOI 10.1214/23-STS894），代價是同樣資料下的區間更寬。注意這個選擇必須事前做——已經偷看過之後再改用 anytime-valid 救不回來，因為保證是對程序的不是對資料的。
- **FDA 的 M1／M2 兩層 margin 不要照搬。** M1 是「對照組相對安慰劑的整個歷史效果」，M2 是「必須保留的比例」，兩者都依賴安慰劑對照的歷史證據與 assay sensitivity——ICH E10 §1.5.1 明講沒有 historical evidence of sensitivity 時「demonstration of efficacy from a showing of non-inferiority is not possible and should not be attempted」。這兩個前提在非醫藥場景沒有對應物。可移植的是骨架（margin 事前釘死、CI 上界比對、雙邊拆 IUT、方向不對稱的切換規則），不是 M1/M2 的具體推導。硬搬會製造一個「看起來有官方背書」的假地基。
- **margin 沒有通用公式，這是官方自己說的，不是本次查不到。** EMA 2158/99 逐字：「It always needs to be tailored specifically to the particular clinical context and no rule can be provided that covers all clinical situations」，且「must always be justified on both clinical and statistical grounds」。因此任何形式的「margin 用某個固定百分比自動算出」都是加蓋，必須在 claim 的 basis 欄位留下獨立於本次資料的外部依據。權威層能提供的是決定程序而非數值（Lakens 等 2018 的 SESOI 方法集，DOI 10.1177/2515245918770963）。
- **近期有一份正式的反方立場，收錄但不要當地基。** Koobs & Koning, arXiv:2603.16213（2026-03）承認「margin must be specified but can rarely be objectively justified in practice」，並提出以 e-values 為基礎、在事後選擇 margin 下仍一致有效的資料相依 margin 曲線 α ↦ Δ̂_α。它與本題「要範圍值不是精準值、用途是決策」的需求高度吻合，但它是 2026 年的預印本、限於 STP3 模型族、未被任何法規或標準採納。正確用法是與事前 margin 並列報告，不是取代——把它當成免除事前釘死義務的藉口，就是拿沙子當混凝土。
- **本次盤點的最大降級風險（要登記進 `交接.md` §十九）：這整套地基百分之百出自臨床試驗法規，沒有任何一份官方文件涉及軟體工程或 LLM 評測。** 因此「把 margin／TOST／CI 對偶搬進 nova 的驗收閘」這個動作本身引不出官方出處，它是 nova 的拆解決定與組合契約，不是地基。可以引官方出處的只有這些方法在其原領域的語意與相容性規則；跨領域的適用性主張必須標記為 nova 自己的決定並附上判斷理由。
- **工具層的取證教訓（本次實際踩到）：WebFetch 對 ICH E9、EMA 482/99、EMA 2158/99 三份 PDF 全部回報「內容經壓縮／損毀無法解析」，其中 EMA 2158/99 那次摘要模型仍然產出了帶引號的「逐字」內容——與自行抽文比對後確認那段引文並不可靠。** FDA 78504 則直接回 HTTP 404。可靠路徑是 curl 下載 PDF 後用 pypdf 自行抽文再逐字 grep。凡是本報告中打引號的官方原文，都經過這條路徑核對；WebFetch 摘要一律未採信。這正是 CLAUDE.md「監看器事件是二手資料，關鍵判斷回頭看一手來源」在文獻查證上的同一條規則。

### 職責分離（separation of duty）與最小權限：「實作者不得改自己的驗收條件」的地基出處與必要條件

**裁決**：兩層都查到了，地基「缺一塊」，且缺的那塊剛好是 nova 現行條文的鏡像盲點。分三點講清楚。

第一，關鍵問題的答案：well-formed transaction 與 separation of duty **不是同一件事**，「實作者不得改自己的驗收條件」也不等於這兩條之一，而是 Clark-Wilson **ER4 前半的鏡像**。三者的關係是：CR2/ER1（well-formed transaction）管「驗收條件只能經由已認證的那條路被改」，不含任何人的分離；CR3（separation of duty）管「誰被允許執行哪個程序」，不含變換的正確性；兩條正交，只有前者則同一個人可以合法地走正規流程把條件改鬆，只有後者則兩個不同的人各自用不受控手段亂改。而 ER4 逐字是雙向的——①只有 certifier 能改該 TP 的關聯清單；②certifier **永遠不得**擁有該對象的 execute 權。nova 的 CLAUDE.md 寫了①的鏡像（「實作者只改該 task 列出的 subject，不能改已准入的 ClaimSpec」），**沒有寫②**。現行條文限制 verifier 與規格作者的是「不能宣告接受」，那限制的是**宣告**；ER4 要求的是限制**執行權**。這是缺的那一塊。

第二，官方層與權威層的分工在本題異常清楚，而且官方自己承認了這個分工。NIST SP 800-53 的 SA-8(15) 逐字寫「[SALTZER75] originally named predicate permission the separation of privilege. It is also equivalent to separation of duty」——官方標準明文把自己的出處指回 1975 年那篇論文。官方層能給的到此為止：AC-5 全文是 [Assignment: organization-defined]、GitHub 的「非最後推送者核准」是可選設定、SLSA 把兩人審查放在最高的 Source Level 4。**照抄官方預設值不會得到職責分離**，官方給的是機制不是保證。權威層補上的正是官方不寫的兩件事：為什麼這樣才對（Saltzer & Schroeder 的三重理由——accident、deception、breach of trust，因此**不必預設執行者有惡意**就能證明它不該持有驗收權），以及什麼時候失效（Bishop 逐字的 root 不可與 certifier 分離、CERT 十五案全部倒在「工具不強制」或「日誌沒人看」、HRU 與 Li et al. 的不可判定與 coNP-complete）。

第三，CLAUDE.md 上限 #4（「CI 跑的是候選者自己那一份 checker」）在 Clark-Wilson 的語言裡不是漏洞清單上的一條備註，而是**模型前提崩塌**：checker 是 TP，TP 必須本身也是 CDI 才談得上「已認證」；checker 落在被評者可寫範圍內時它是 UDI，CR2 的認證從第一步就不成立，後面 CR3、ER4 全部無所附麗。同理，CLAUDE.md 已寫「還是不准寫不可能繞過」，這個判斷有硬背書：Bishop 逐字「No way to overcome this without changing nature of root」。所以正確方向不是消滅繞過通道，而是照 SLSA Source Level 2 的做法——**發 attestation 記錄連續性，讓繞過留痕並使 claim 自動降級**。

沒有「多了」的部分。要補的是 ER4 後半、checker 的 CDI 化，以及把「不可能性證明」換成「違反偵測＋降級」。

- [Jerome H. Saltzer、Michael D. Schroeder，Proceedings of the IEEE 63(9), 1278-1308，1975] **保護機制設計八原則：least privilege 與 separation of privilege** — DOI 10.1109/PROC.1975.9939（Crossref 查證：Saltzer, J.H.; Schroeder, M.D., Proceedings of the IEEE, 63(9), 1278-1308, 1975）；條文原文比對自 https://www.cs.virginia.edu/~evans/cs551/saltzer/

**一、把 Clark-Wilson 的四類實體對映成既有物件，先把邊界釘死**
- `ClaimSpec`、`must_fail_exactly`、固定負控 → **CDI**（受完整性控制，只能經閘變更）。
- 閘的程式（checker、判準執行器）→ **TP**，且**這個 TP 本身必須同時是 CDI**。這是本次調查最要緊的一條：TP 若可被被評者任意改寫，它就是 UDI，CR2 的「已認證」不成立。
- `subject`（該 task 允許實作者改的檔案集合）→ **UDI**。
- 恆真格檢查、覆蓋檢查 → **IVP**。

**二、補 ER4 的後半（目前缺的那一塊）**
在 claim 上加一組互斥見證欄位，並讓閘去比對，而不是靠文件宣告：
- `certified_by`：認證這組判準對這組 CDI 有效的主體 id。
- `executed_by`：實際執行實作的主體 id。
- 恆真檢查 `certified_by != executed_by`，配一格負控（兩者相同時閘必須紅）。
- 再加 `certifier_execute_denied`（布林或主體集合），對映 ER4 後半：認證方對該 subject 不得持有執行權。這一格若沒有負控證明它抓得到「認證方同時動了 subject」，等於沒有。

**三、把 subject 與判準來源做成集合層級的不相交，並由閘裁定**
- `subject_paths` 與 `criterion_paths` 兩個明確列舉的集合（依 CLAUDE.md「全集宣稱一律直接列舉目標型別」的規矩，用 `iterdir()`／`ClassDef`／`ast` 這類直接列舉，不從別的型別推導）。
- 閘檢查 `subject_paths ∩ criterion_paths == ∅`；交集非空即紅。

**四、checker 的來源要進 claim，且不合格時降級而非靜默通過**
- `checker_ref`：閘的程式來自哪個 ref／哪個來源。
- 當 `checker_ref` 落在被評者可寫範圍內時，claim 自動標成 `SELF_CERTIFIED` 等級，而不是直接失敗——這符合 SLSA 的降級思路，也符合 CLAUDE.md 的語意單調：新增欄位、新增拒絕，未理解此擴充的舊元件回 `UNSUPPORTED_CAPABILITY` 並 fail-closed，不得靜默忽略。

**五、繞過留痕，取代「不可能繞過」的宣稱**
- `bypass_used`、`bypass_actor`、`bypass_reason` 三欄；任一非空則 claim 等級自動降一級並在報告中顯示。
- 對映 Bishop 的「root 不可與 certifier 分離」與 CLAUDE.md 既有的五個上限，尤其第 3 條的人為出口。

**六、身分是前提不是配套（ER3 先於 ER4）**
- `actor_identity_source`：`certified_by` 與 `executed_by` 這兩個 id 的認定來源。CERT 案例中有人用他人帳號 check-in，SoD 掛在身分之上，身分一破則 SoD 靜默失效**而日誌顯示為合規**。這一格需要一則負控：兩個欄位由同一個可偽造來源填寫時，閘必須降級或紅。

**七、閘的形狀：做違反偵測，不做不可能性證明**
依 HRU 的不可判定與 Li et al. 的 coNP-complete，閘只實作「這次改動是否踩到已列舉的禁區」（便宜、可判定），不實作「證明不存在任何路徑可繞」。這不是嚴格度讓步，是把不可能的工作換成可交付的工作。

**八、日誌要有人（或機制）真的看**
CERT 十五案的第二種失敗模式是日誌存在而無人稽核。所以 `bypass_*` 與降級事件必須進入**會 fail 的檢查**，不能只寫進報告等人讀——依 CLAUDE.md「只以文件形式存在的規範等於不存在」。

**坑**：
- ER4 是雙向的，只做前半等於沒做職責分離。「實作者不得改驗收條件」只是 ER4 前半；後半「認證方永遠不得擁有該對象的執行權」目前 nova 沒有對應機制。限制「不能宣告接受」限制的是宣告，不是執行權。
- 把 well-formed transaction 與 separation of duty 當成同一條會漏掉一半。兩者正交：只有前者，同一人可以合法走正規流程把條件改鬆；只有後者，兩個不同的人各自用不受控手段亂改。
- 「有工具」不等於「有閘」——這句有量化背書。CERT 十五案**全部**倒在兩種模式之一：工具沒有強制第二人核准，或日誌沒人稽核。組態管理工具存在不構成任何保證。
- 身分是職責分離的前提而不是配套（ER3 先於 ER4）。CERT 案例中有人用主管的電腦與帳號 check-in 惡意程式碼——身分一破，SoD 靜默失效**而且日誌會顯示為合規**，這比沒有日誌更糟。
- checker 若在被評者的寫入範圍內，這不是漏洞清單上的一條備註，是 Clark-Wilson 的前提崩塌：TP 必須本身是 CDI，否則 CR2 的「已認證」從第一步就不成立，CR3 與 ER4 全部無所附麗。
- 不要試圖證明「不存在任何繞法」。一般模型下 safety 不可判定（HRU 1976），以互斥角色強制 SSoD 是 coNP-complete（Li et al. 2007）。閘的正確形狀是違反偵測＋降級，不是不可能性證明。
- 不要寫「不可能繞過」，這有硬背書而非只是謹慎：Bishop 逐字「root can assume identity of users owning TPs, and so cannot be separated from certifiers. No way to overcome this without changing nature of root.」正確做法是照 SLSA 記錄連續性，讓繞過留痕並使 claim 自動降級。
- 照抄官方預設值不會得到職責分離。官方全部是 organization-defined 或 opt-in：AC-5 整條是 [Assignment]、GitHub 的「非最後推送者核准」是可選設定、SLSA 把兩人審查放在最高的 Level 4。官方給機制，不給保證。
- 職責分離只擋單人，官方自己標了上限：AC-5 的 Discussion 逐字寫「without collusion」。當兩個角色實際上由同一個不可靠執行者扮演時，SoD 名義成立、實質為零——這一點對「執行者泛指任何不可靠執行者」的設定特別要緊。
- NISTIR 7316 的第三角色漏洞：兩個互斥角色成立 SoD 之後，若稍後新增的第三個角色同時握有兩邊權限，SoD 已被破壞而**原本的互斥宣告看起來還是綠的**。任何「已宣告互斥」的檢查都不足以證明目標達成（Li et al. 正是證明這兩者不等價）。
- 不要把 Saltzer & Schroeder 當成「地基已完備」的背書：作者自陳「these principles do not represent absolute rules--they serve best as warnings」。它們是警示啟發式，違反時觸發審查，不是可以直接編譯成閘的規則。
- 不必預設執行者有惡意才能主張它不該持有驗收權。Saltzer & Schroeder 的理由涵蓋 accident、deception、breach of trust 三者，CERT PRACTICE 8 也明講獨立測試可偵測「both intentional and unintentional」的問題引入。把論證建立在「防作弊」上反而讓這條規則顯得可以協商。
- MERIT 與內部威脅文獻建模的是**有動機的人類**（不滿、報復）的升級路徑，對無動機但不可靠的執行者是否適用，該文獻未處理。引用時要標明範圍，不要讓它承擔它沒說過的結論。
- ACM Computing Surveys 2025 那份 SoD 綜述本次只取得書目與摘要（ACM DL 回 403），可信度僅到「此文獻確實存在且書目正確」，不可拿來背書任何具體主張。
