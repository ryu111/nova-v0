# 地基與加蓋：每一條提案都要過的篩子

控制端 2026-08-27 裁定：
1. **官方與權威論點是地基，nova 想要的是加蓋。** 地基不能為了加蓋而改形狀。
2. **`nova[llm]` 的方括號是 extras。** nova 本體 = 用軟體工程的方式把五門 engineering
   做**拆解／組合／擴充**；`[llm]` 是裝上去的 extra，所以 claude／codex／gemini 平級。
3. 官方與權威論點的優先級**高於 CLAUDE.md**。衝突時改 CLAUDE.md。

## 可檢查的判準（2026-08-27 第一版被 sol 駁回，這是修訂版）

**第一版寫的是「加蓋只能增加拒絕，不能改變介面」。sol 用 `nova[llm]` 自己當反例駁回：**
安裝 extra 之後，原先回 `UNSUPPORTED_BACKEND` 的請求變成可執行——接受集合**擴大**了。
那不是破壞地基，是標準的可選能力擴充。PyPA 的 extras 規格就是為此存在；
MCP 也允許經 capability negotiation 啟用不改核心協定的 extension。

修訂版：

> **加蓋不得改變既有介面的語意與既有保證。可以做兩件事：**
> 1. **對既有能力增加拒絕**；
> 2. **透過已宣告、具命名空間、具版本、可協商的擴充點增加新能力。**
>
> **未理解該擴充的舊元件必須 fail-closed 或回 `UNSUPPORTED_CAPABILITY`，
> 不得把擴充靜默忽略後誤判為成功。**

這叫**語意單調**，不是「接受集合只能縮小」。
MCP 官方的擴充規則正是這個形狀：extension 不得移除或改名欄位、不得改型別、
不得改既有行為語意、不得增加新的必填欄位；支援與否經 capabilities 協商。

**地基也不是「永遠凍結某家廠商今天的 JSON」。** 真正不可破壞的是**已採用介面的語意與相容性規則**，
否則業界正式推出新版本時 nova 反而不能跟進。不變式是：
既有版本語意不改；新能力走新版本或協商式擴充；
**nova 的政策只能拒絕既有請求，不能把既有拒絕偷偷翻成接受**；
安裝明示 extra 或協商成功則可以增加能力。

## 每一條提案要填的五格

| 格 | 問題 |
|---|---|
| 地基 | 業界官方的那一份是什麼？出處？（沒有出處就不是地基，是我們自己的意見） |
| 拆解 | 單元邊界在哪：誰擁有什麼、誰不准知道什麼 |
| 組合 | 單元之間的契約是什麼：介面／封套／manifest 的形狀 |
| 擴充點 | 新東西怎麼進來而不動既有保證 |
| 加蓋 | nova 多出來的那一條**拒絕**是什麼？它有沒有改到地基的介面？ |

最後一格若答「有改到介面」，這條提案要退回重想，或明講它是分叉並說明為什麼值得。

## 五門 engineering 的初步填法（待官方研究回來後校正）

### harness engineering
- **地基**：十一部件（協調迴圈／工具／記憶／上下文管理／提示構造／輸出解析／
  狀態管理／錯誤處理／防護與安全／驗證迴圈／子代理協調）。
- **拆解**：十一格各自一個 port，互不知道對方的實作。
- **組合**：`InvocationEnvelope` ＋ immutable `ContextManifest` 是組裝契約。
- **擴充點**：backend adapter port——claude／codex／gemini／local 平級接同一個契約。
- **加蓋（多出來的拒絕）**：驗收權不在執行者手上。judge 只進 evidence 不產生 terminal；
  能力不足只回 typed `UNSUPPORTED_*` 不得靜默降級。**介面沒動。**

### loop engineering
- **地基**：必要終止條件——硬迭代上限、成本預算、**無進展偵測**、目標檢查、逾時。
- **拆解**：`FlowSpec`／`MachineSpec` 是宣告資料，不是程式碼。
- **組合**：guard compiler 把宣告編成可判定的轉移。
- **擴充點**：新的終止 predicate 以資料加入，不改 runtime。
- **加蓋**：候選執行者不能延長 deadline、改 budget、改 criterion。**介面沒動。**

### graph engineering
- **地基**：DAG 排程、依賴、可並行性、關鍵路徑。
- **拆解**：node 是可獨立重播的單位。
- **組合**：邊只承載依賴，不承載狀態。
- **擴充點**：新 node 型別以 schema 加入。
- **加蓋**：每個 node 有可重播 identity；執行者不得把自己的執行路徑升格成新的 edge。

### agentic engineering
- **地基**：Anthropic 的五種模式（prompt chaining／routing／parallelization／
  orchestrator-workers／evaluator-optimizer）＋ 工具授權。
  官方分界：workflow 是**你**掌握控制流；agent 是你掌握目標與護欄、不掌握每個分支。
- **拆解**：agent 是 Execution 內受限、可替換的求解器，不是控制平面。
- **組合**：`ToolAuthorizationPolicy` ＋ `ExecutionRequest`（不含判準內容）。
- **擴充點**：新工具進封閉授權清單。
- **加蓋**：agent 不能自行擴張 scope、宣告 Work 完成、改 effect receipt、寫 state DB。

### multi-agent engineering
- **地基**：delegation policy、子代理 context isolation、fan-out、usage scope 歸屬。
- **拆解**：子代理在乾淨 context 探索，只回吐濃縮摘要。
- **組合**：`DelegationPolicy`（子代理數／深度／模型／每支上限）＋ usage scope
  `ROOT_ONLY|DELEGATION_TREE_TOTAL|UNKNOWN`。
- **擴充點**：新的 delegation profile 以資料加入。
- **加蓋**：子代理回吐的摘要是**觀測**，不取得權威地位；
  「不同廠商」不等於「技術獨立」，獨立性要量對外部錨點的誤差相關係數。

## 用法

官方研究與 sol 回覆進來後，逐條套這五格。填不滿的：
- 「地基」欄空的 → 那是我們的意見不是地基，降級成加蓋，並且要能寫成會 fail 的測試。
- 「加蓋」欄答「有改到介面」→ 退回重想。
- 五格都填得滿、且加蓋只增加拒絕 → 才進計畫。

## 2026-08-27：sol 判定「引不出官方出處、必須降級」的十二項

以下這些**目前引不出能支撐其完整語意的官方出處**，不得再稱為地基。
它們不必刪，但正確標籤是「nova 的拆解決定／組合契約／額外拒絕／待驗證的擴充政策」：

1. harness 恰好由那十一個部件構成
2. loop 恰好有五個「必要」終止條件
3. `MachineSpec` 必須是純宣告資料
4. graph 必須是 DAG
5. graph node 必須可獨立重播
6. edge 只承載依賴、不承載狀態
7. `InvocationEnvelope`、`ContextManifest`、guard compiler 是業界既有介面
8. `DelegationPolicy` 的具體欄位與 usage-scope 核銷規則
9. 子代理摘要只能是 observation
10. 「不同廠商」不等於「技術獨立」
11. `PrimitiveCatalog` 與 `ProtectedClaimClosure` 的具體 manifest 形狀
12. `disclosure_units` 能提供 reusable-holdout 的統計保證

### 三處具體事實更正（不是標籤問題，是內容錯了）

- **harness 十一部件**：sol 查到的 HarnessArch 是私人 taxonomy，而且它列的是
  Instructions／Context Delivery／Context Management／Tool Interfaces／Execution Environment／
  Durable State／Orchestration／Sub-agents／Skills／Verification & Observability／Evolution
  ——**與我先前寫的那十一項不是同一份**。Anthropic 官方只說 augmented LLM 通常由
  retrieval、tools、memory 增強，沒有頒布唯一部件表。
- **graph 必須是 DAG**：LangGraph 官方**允許循環**、conditional edge、dynamic edge、
  shared state 與 parallel supersteps；基本分解是 State／Nodes／Edges。DAG 只是子類。
- **邊只承載依賴不承載狀態**：**不正確**。LangGraph 明說 message／state 沿 edge 傳遞，
  conditional edge 也依 state 路由。應改為「邊擁有合法路由語意；state payload 經明確
  schema／channel 傳遞，不把隱藏 mutable state 塞進 edge implementation」。

### 引得出官方出處的（可當地基用）

- prompt 是版本化 artifact —— AWS Bedrock Prompt Management、OpenAI Agents SDK `Prompt(id, version, variables)`
- provenance 的 Entity／Activity／Agent 三分 —— W3C PROV
- judge 要拿 human ratings 當 ground truth 算 balanced accuracy／F1／confusion matrix —— Vertex「Evaluate a judge model」
- 適應性查詢會破壞 holdout 的一般化保證 —— Reusable Holdout（arXiv 1506.02629）
- 視覺 baseline 受 OS／版本／硬體／headless／字型影響，**threshold 是測試定義的一部分** —— Playwright 官方
- allowlist ／最小權限 —— OWASP Excessive Agency；可信 builder 與可驗 provenance —— SLSA
- required status check 未綠不得合併、可鎖定 check 來源 —— GitHub protected branches；artifact integrity —— NIST SSDF SP 800-218
- 五種 **workflow pattern**（不是 agentic 的完整分類）—— Anthropic Building Effective Agents
- 多代理適合 breadth-first、可獨立探索的工作，**不適合需要高度共享 context 的 coding 類工作**，且 token 成本高 —— Anthropic Multi-Agent Research System
- extras 用來增加 optional dependencies —— PyPA dependency specifiers；擴充不得改既有語意 —— MCP Extensions
- timeout／bounded retries／backoff —— AWS Builders' Library
