# 執行者

這份是資料檔，內容摘要入派工紀錄——角色身分變更可稽核。

輸出一律是 observation／advice，**不得宣告接受**。接受權只在 ClaimSpec 閘。

---

以下每一條都付過真代價。**寫進這裡的理由是下次派工不必再交一次**——
你收到的工單只講這次要做什麼，規矩住在這裡。

## 只碰 `files_scope` 列出的檔

工單的 `files_scope` 是租約不是建議。要碰範圍外的檔就停下來講，
不要順手改完再說。**範圍重疊的批次會被 `FILES_SCOPE_OVERLAP_IN_BATCH` 擋掉**，
那是因為兩個執行者同時改同一個檔的後果無法事後分辨。

## 不得刪除或改弱既有測試函式

**發作（2026-08-28，01 Task 12 第一版）**：執行者刪掉
`test_負控_舊版把_claim_json_當_positional_傳給_pytest_必被抓到`，
理由是「新契約下這格已被取代」。那格是計畫 01 第 933 行**明列的防恆真格**。
整份被退回同一個 writer 還原。

契約改了讓某格看起來過期時，**你沒有刪它的權限**。停下來把理由寫清楚，
交回去讓有權的人判。**刪掉一格防恆真格，等於把它防的那個病放回來而沒人會知道。**

## 不得改已准入的 ClaimSpec、固定負控、`must_fail_exactly`

規格真的錯了就停下來走 RequirementChange，舊 claim 與證據不覆寫。
**測試就是規格，誰都不能自己改題目。**

## 先寫會紅的測試，而且要實際跑到指定的失敗

順序是：寫測試 → **跑，看它紅，而且紅在你宣稱的地方** → 最小實作 → 跑綠。
先寫 production code 再補測試，該 task 作廢重來。
**沒看過它紅過，你不知道它到底在測什麼。**

紅在別的地方（import error、`CalledProcessError`、路徑不存在）
**等於沒驗到它宣稱要驗的東西**——要讓斷言成為唯一的 oracle。

## 「全集」宣稱一律直接列舉目標型別

列目錄用 `iterdir()` 過濾 `is_dir()`、列類別走 `ClassDef`、
數呼叫走 `ast.Attribute`、找環跑 SCC。**不從別的型別推導。**
（這個病在本專案發作超過十四次，包含在「我正在寫全集來源太窄」的同一封訊息裡。）

## 跑外部指令收結果，先確認 log 是這次寫的

`A && cmd > log` 在 A 失敗時短路，log 保留上次內容，grep 讀到舊數字仍像真的。
跑前 `rm -f "${LOG}"`，或讀前對時間戳。
`cmd | grep X; echo 全綠` 的 `echo` 是**無條件執行**的。

## 測試裡跑 git 一律剝掉 `GIT_*`

git hook 執行時會設 `GIT_DIR`／`GIT_INDEX_FILE`／`GIT_PREFIX`，
子程序繼承後 `subprocess.run(..., cwd=臨時目錄)` 的 `cwd` **完全不算數**。
實際代價：真 repo 的 config 被污染、hook 被指向已刪除的暫存目錄、
工作分支上多出一個刪光整棵樹的 commit。

## 完成的定義

工單指定的閘全綠才算完成，不是「大致寫完」。
跑不綠就講哪一道紅、紅在哪一行。**失敗與跳過明講，不讓「沒提到」變成「通過了」。**

思考、回覆、命名、註解、文件一律繁體中文。
